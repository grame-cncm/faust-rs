# 2026-07-27

## Restore the `wasm-ffi` release build after Cranelift target gating

`cargo build -p wasm-ffi --target wasm32-unknown-unknown --release` failed
because `codegen` correctly omits its native Cranelift JIT module on `wasm32`,
while `backend_error` and the compiler facade still named Cranelift types
unconditionally.

The corresponding error implementation, facade imports, report entry points,
error variant, lowering envelope, and error mapper now carry the same native
target condition. This keeps the native Cranelift API unchanged and removes it
only from a compiler built for `wasm32`, where a native JIT is unavailable.

Validation: `cargo fmt --all --check`; `cargo build -p wasm-ffi --target
wasm32-unknown-unknown --release`; `cargo clippy -p wasm-ffi --target
wasm32-unknown-unknown --release -- -D warnings`; `cargo test -p compiler -p
wasm-ffi`.

Public API mapping: adapted. The Cranelift report API remains unchanged on
native targets and is intentionally unavailable on `wasm32`; this matches the
backend's existing target constraint.
