# 2026-07-27

## Analyze and clarify the FFI crate organization

Commit date: 2026-07-27

Source commit: `f51d5000`

Added
`porting/ffi-crate-organization-analysis-2026-07-27-en.md` in response to the
review concern that the workspace contains many `*-ffi` crates while the
non-FFI-named `utils` crate contains foreign-interface code.

The analysis distinguishes useful API/backend boundaries from naming debt.
`tree-ffi`, Box, Signal, Interpreter, Cranelift, WASM, and the final
`faust-ffi` aggregation crate have separate handle, compatibility, runtime,
target, or packaging responsibilities and should not be merged merely to
reduce the Cargo member count. The actual inconsistency is `crates/utils`: all
of its consumers are FFI adapters, and its implemented surface consists of ABI
callback tables, C string and pointer ownership, argument decoding, compile
options, and a raw-pointer factory cache.

The proposed migration renames that crate to `ffi-common`, splits it into
`abi`, `strings`, `memory`, `args`, and `factory_cache` modules, documents a
one-way `compiler core <- FFI adapters <- distribution` dependency rule, and
makes the `faust-ffi` packaging facade inherit the workspace unsafe-code
prohibition. Follow-up phases separately replace unconstrained borrowed C
string lifetimes with owned values, add ABI layout checks, and harden the
factory cache only after its parity-sensitive ownership and concurrency
contract is explicitly decided.

No compiler behavior, Rust crate layout, generated code, or external C ABI
changes in this documentation commit. Public API mapping is deferred to the
implementation phases; the proposed `utils` rename is an internal adapted Rust
API with no intended C ABI impact. Validation: relative-path review and
`git diff --check`.

## Analyze BRA tape safety, adjoint liveness, and seed-aware routing

Commit date: 2026-07-27

Source commit: `de7667be`

Documented the post-`Attach` C++ analysis in
`porting/rad-bra-tape-safety-liveness-analysis-2026-07-27-en.md`.
The analysis confirms that the `i0 & 8191` tape mask removes out-of-bounds
access but silently aliases gradients for `count > 8192`, and that structural
tape collection can leave write-only tape arrays and hot-loop stores.

It also corrects the claim that public `rad` always uses `BlockReverseAD`:
the symbolic sweep is attempted first, but currently descends into
seed-independent temporal subgraphs. For `w * no.noise`, this reaches the
noise recursion and triggers a conservative BRA fallback even though the
useful adjoint slice for seed `w` is feed-forward.

The proposed remediation is split into explicit gates:

1. choose and expose a safe BRA window contract (fixed chunked TBPTT is
   recommended; dynamic host-sized scratch remains the exact whole-block
   alternative);
2. compute seed-dependency masks, including a recursion-slot fixpoint, before
   symbolic/BRA dispatch;
3. produce a live `BraAdjointPlan` whose tape requirements are checked by an
   independent structural checker before FIR emission.

No compiler behavior or public API changes in this documentation commit.
Public API mapping is deferred until the fixed-window versus dynamic-scratch
decision is made. Validation: relative-link inspection and `git diff --check`.

## Preserve `Attach` semantics in the BlockReverseAD backward sweep

`SigBlockReverseAD` FIR lowering now treats `Attach(value, effect)` as an
identity in the adjoint graph: the full cotangent flows to `value`, while the
attached branch remains a forward-only effect. The BRA postorder follows only
the value child, so metering is neither differentiated nor replayed during the
reverse sweep. This closes the `FRS-SFIR-0004` failure reproduced by
`rad_attach_repro2.dsp`.

Added a structural BRA regression and an interpreter test whose attached
bargraph branch depends on the differentiated seed; the expected TBPTT gradient
proves that no spurious adjoint flows through that branch. Also aligned the
WASM JSON scaffold test with the canonical JSON contract that emits an empty
top-level `"meta": []` array.

Validation: `cargo run -q -p compiler --bin faust-rs -- -double
rad_attach_repro2.dsp`; `cargo fmt --all --check`; `cargo clippy --workspace
--all-targets -- -D warnings`; `cargo test --workspace --all-targets`; `cargo
run -p xtask -- golden-check`.

Public API mapping: 1:1. `Attach` still returns its value operand and forces the
attached operand in the forward pass; reverse-mode differentiation now applies
the matching identity adjoint without changing the generated DSP interface.

## Restore the `wasm-ffi` release build after Cranelift target gating

`cargo build -p wasm-ffi --target wasm32-unknown-unknown --release` failed
because `codegen` correctly omits its native Cranelift JIT module on `wasm32`,
while `backend_error` and the compiler facade still named Cranelift types
unconditionally.

The corresponding error implementation, facade imports, report entry points,
error variant, lowering envelope, and error mapper now carry the same native
target condition. This keeps the native Cranelift API unchanged and removes it
only from a compiler built for `wasm32`, where a native JIT is unavailable.

Validation: `cargo fmt --all --check`; `cargo build -p wasm-ffi --target
wasm32-unknown-unknown --release`; `cargo clippy -p wasm-ffi --target
wasm32-unknown-unknown --release -- -D warnings`; `cargo test -p compiler -p
wasm-ffi`.

Public API mapping: adapted. The Cranelift report API remains unchanged on
native targets and is intentionally unavailable on `wasm32`; this matches the
backend's existing target constraint.
