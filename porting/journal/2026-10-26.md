## C and C++: helper functions guarded as in C++ (`FAUST_INT_WRAP`, `FAUSTMAXI`)

Commit date: 2026-10-26

Source commit: this commit

The wrapping integer helpers of the C and C++ backends, and the C backend's
`faustmaxi` / `faustmini`, were printed without a guard, so two faust-rs C++
classes, or two C DSPs, in one translation unit failed with
`redefinition of 'faust_wrap_add'` (and of `faustmaxi`). C++ master-dev
(`88b5c93ae`) prints the first under `#ifndef FAUST_INT_WRAP`; the pinned
`8eebea429` and master-dev print the second under `#ifndef FAUSTMAXI`.

- Both backends now print `FAUST_INT_WRAP`, so DSPs from either compiler can
  share one translation unit.
- C++ (`crates/codegen/src/backends/cpp/mod.rs`): `inline`, with the body
  changed from `uint32_t` to the reference's `(unsigned int)` casts, token for
  token. The functions have external linkage, and identical definitions keep a
  program that mixes the two compilers across translation units within the
  one-definition rule.
- C (`crates/codegen/src/backends/c/mod.rs`): the wrapping helpers keep
  `static inline FAUST_UNUSED` and `uint32_t` (internal linkage, nothing
  shared); `faustmaxi` / `faustmini` go under `FAUSTMAXI`, in the reference's
  order (`faustmaxi` first), still `static inline FAUST_UNUSED`.
- C++ side: the pinned reference prints `faustmaxi` / `faustmini` as plain
  `inline` in C, a C99 inline definition with no external one, so a C file
  calling `faustmini` fails to link at `-O0`. Master-dev fixed it in
  `220e37386` (`static inline`); that commit is cherry-picked onto a new local
  branch of the C++ repository, `fix-faustmaxi-static-inline-FIR19` (from
  `8eebea429`, worktree `../faust-faustmaxi-static`), built, and checked on
  that link case. The pin and the checked-out reference branch are unchanged.
  C++ master-dev itself (`/Users/letz/faust` at `04b121feb`, 2.90.15) needs
  nothing: two DSPs from it share one translation unit in C (`-std=c99 -O0`)
  and C++, scalar and `-vec`.
- Registry: DIFF-BEH-028 (the wrapping helpers were not registered against
  the pinned `8eebea429`, which has none).
- Tests: `crates/compiler/tests/int_wrap_guard.rs`: the exact text in both
  backends; two C++ classes plus a C++ Faust copy of the helpers, and two C
  DSPs, built at `-O0` and run in one translation unit (each fails with its
  guard removed).
- Seen while validating: `cpp_signal_differential` fails when
  `/usr/local/bin/faust` is not the C++ compiler (it is now a link to
  `faust-rs`); it passes with `FAUST_CPP_BIN` set to the pinned 2.84.3.

## One bargraph per bargraph signal (`vumeter.dsp`)

Commit date: 2026-10-26

Source commit: this commit

Found while comparing the `-uim` macros with faust 2.90.15 over the corpus:
`tests/impulse-tests/dsp/vumeter.dsp` (`process = hmeter, hmeter;`, one
`hbargraph` box applied to each channel) has `FAUST_PASSIVES 2` in C++ and 1
in faust-rs. The difference was older than `-uim`: faust-rs declared one
`fHbargraph0` and wrote both channels' levels to it, so in every backend the
second meter overwrote the first. faust 2.84.3 and 2.90.15 both show two
meters, each written by its own channel.

- Cause: the UI is collected from the box before propagation, and a control is
  keyed by its widget box and group context. A bargraph box is a function of
  its input; C++ makes one widget per bargraph *signal*
  (`sigHBargraph(path, min, max, x)` carries `x`, and `generateHBargraph`
  calls `addUIWidget` once per compiled signal).
- Fix (`propagate`): `BargraphSplits` (`crates/propagate/src/ui_build.rs`).
  The first input a bargraph control is propagated with keeps the control;
  each other input gets a copy of it, allocated after the collected controls,
  whose leaf is inserted with the original's group path and order key, after
  it. The UI collector is now finished after propagation
  (`collect_ui_program` / `UiDraft::finish`); `build_ui_program` (used by
  `control_widgets`, hence `coutputs`) finishes it with no split, so
  `coutputs(e)` still lists bargraph boxes. A constant fold keeps its
  placeholder ids.
- Checked against C++ on `vumeter.dsp`, a shared input (`_ <: m, m`: one
  meter), chained meters (`m : m`: two), a meter in and around a recursion
  (three, each leaf displaying the same signal as C++'s leaf at its position)
  and two channels in two groups (four).
- Residual, recorded as DIFF-BEH-027: inputs are compared as propagated, C++
  compares them after simplification, so `x + x` and `2 * x` are two meters
  here and one in C++ (same value shown twice; nothing lost).
- Tests: `crates/compiler/tests/bargraph_per_signal.rs` (four tests; the two
  splitting ones fail with the split disabled) and
  `a_bargraph_box_gets_one_control_per_input_signal` in
  `crates/propagate/tests/core_api.rs`.
- Validation: workspace fmt, clippy and tests; `golden-check` and the five
  structure gates. A base-vs-new compile of every `.dsp` under `tests/` and
  `examples/` (632, scalar and `-vec`, with `-I libraries`) changes only
  `vumeter.dsp`. Its impulse test passes on the cpp, c, cpp-vec1, interp,
  cranelift, wasm and rust lanes (samples only; the meters are not in the
  oracle). `compile-budget-check` refuses to run on this machine (karplus
  calibration 3 ms, under its 4 ms floor); a hand A/B over the impulse corpus
  and the `ddsp_*` programs, three alternating rounds, is flat (5.71–5.87 s
  base, 5.80–5.91 s new).

## Control characters of string literals become spaces, as in C++

Commit date: 2026-10-26

Source commit: this commit

A newline inside a label, a tooltip or a `declare` value reached
`buildUserInterface`, `metadata()` and the JSON as `\n` in faust-rs and as
a space in Faust 2.84.3 and 2.90.15. Found while porting `-uim` (entry
below): this closes the eight `tests/` and `examples/` programs it lists as
differing only by it.

- **Where C++ does it.** Not only in the `uqstring` rule of
  `faustparser.y` (`unquote`/`replaceCR`, `\n` only): `Symbol::get`
  (`tlib/symbol.cpp`) replaces every character below 32 with a space when a
  string becomes a symbol. That covers the raw `string` rule of `declare`
  and the `fstring` strings of `ffunction`/`fconstant`/`fvariable` too,
  and tabs and carriage returns as well as newlines. The lexer has no
  escapes: a backslash followed by `n` stays two characters.
- **Where faust-rs does it.** `blank_control_chars` in `crates/parser`,
  applied to the two token builders that produce string literals:
  `uqstring_from_token` (labels, `declare`, `import`, `library`,
  `component`, `soundfile`) and `raw_symbol_from_token` (foreign-function
  strings). Identifiers cannot hold control characters, so nothing else
  changes.
- **Tests.** `parser/tests/api_bridge.rs`
  `string_literal_control_characters_become_spaces_like_cpp` (newline, tab,
  CR in metadata, labels and foreign strings, a kept `\n` escape);
  `compiler/tests/string_literal_control_chars.rs` (C++ output and JSON of
  the reproduction, strings as the reference prints them).
- **Parity.** On the 133 impulse-tests programs, the unordered set of JSON
  labels, addresses and metadata strings now equals the reference's for
  `cubic_distortion`, `parametric_eq`, `phaser_flanger`, `reverb_designer`
  and `virtual_analog_oscillators` (123/133 equal, from 118). The ten left
  differ by bargraph numbering, `library_path` entries and MIDI
  addresses, none by a control character.
- **Codegen identity.** Base vs new C++ output over the 632 `.dsp` of
  `tests/` and `examples/`: 509 identical, 116 failing on both, 7 changed
  (the five programs above and `tests/corpus/modulation_21`/`22`, a
  tooltip), all by a `\n` turned into a space. No golden snapshot holds an
  embedded newline: `golden-check` is green with no refresh.
- **Compilation cost.** Hand A/B of the compile-budget basket (release,
  best of five, interleaved): every case within ±4 %. Two outliers of a
  first pass were retimed: `cubic_distortion -vec` 525 → 528 ms,
  `spectral_level` scalar 302 → 303 ms (best of 20, load average 18).

## `-uim`: user-interface macros for the C and C++ backends

Commit date: 2026-10-26

Source commit: this commit

Port of the C++ `-uim` / `--user-interface-macros` option
(`global::gUIMacroSwitch`, `CodeContainer::printMacros`,
`InstructionsCompiler::generateMacroInterfaceTree`), used by the `faust2*`
scripts and the architectures that reach DSP fields by name
(`minimal-static.cpp`, `teensy.cpp`, `juce-plugin.cpp`, `clap-arch.cpp`,
`unity`, `max-msp64.cpp`, `DspFaust.cpp`, ...).

- **`ui`: raw group labels.** The C++ macro paths print the raw label of each
  enclosing group, metadata included (`"[1]Main [style:knob]/gain"`), which
  the UI tree no longer had after metadata extraction. `UIGROUP` nodes carry
  it as a fifth child (`UiBuilder::group_with_raw_label`,
  `UiMatch::Group::raw_label`, `UiGroupSpec::raw_label`); group merging is
  unchanged (`UiGroupSpec::same_group` ignores the raw spelling). The
  synthesized root and `hgroup("", ...)` have an empty raw label and add no
  path segment, as the reference's unnamed root folder.
- **`transform`: the table.** `signal_fir::ui_macro_widgets` walks the pruned
  UI the module shows, so dead widgets are left out and every macro names an
  emitted zone (`SignalFirOutput::ui_macros`).
- **`codegen`: the block.** `backends::ui_macros` renders the
  `#ifdef FAUST_UIMACROS` block for `c` and `cpp` (options `ui_macros` and
  `ui_macro_widgets`); under `-uim` the C++ class and its table
  sub-containers are `struct`s without access specifiers.
- **`compiler`:** `-uim` / `--user-interface-macros`, echoed in the
  compilation options and `FAUST_COMPILATION_OPIONS`.
- **Differences:** DIFF-CLI-014 — zone numbering, number spelling, C-string
  escaping and indentation follow the rest of the faust-rs output.
- **Validation:** `crates/compiler/tests/ui_macros.rs` (entries and order
  checked against the reference 2.84.3 on the same source), unit tests in
  `ui_macros.rs` of `codegen` and `transform`; `minimal-static.cpp` built and
  run against the output in `-single`, `-double` and `-vec`; a C harness
  reading the macros' `offsetof`s; `-mem -uim` C++ compiled.
- **Unchanged without `-uim`:** C and C++ output byte-identical to the base
  (HEAD plus the uncommitted `sigtype` change) on the 632 `.dsp` of `tests/`
  and `examples/`; golden check green.
- **Compile cost:** the budget gate cannot run on this Mac, so a pre/post
  A/B of the basket, best of five: every case between 0.95 and 1.03 of the
  base, i.e. noise.
- **Against faust 2.90.15** (installed), normalizing zone numbers and number
  spelling: 297 of the 315 `.dsp` of `tests/` and `examples/` that both
  compile give the same block. The 18 others: the soundfile zone name
  (`fSound` vs `fSoundfile`, 5 files); newlines kept in labels where the C++
  parser's `unquote` turns them into spaces (8, also visible in
  `buildUserInterface`, `metadata()` and the JSON); the Rust-only relative
  group navigation (2, DIFF-BEH-008); a widget order that changed in C++
  after 2.89 (2, same in `buildUserInterface`); in `vumeter.dsp`, two
  same-label bargraphs that faust-rs shows as one (also in
  `buildUserInterface`); `comb_bug_exp.dsp`, whose `FAUST_FILE_NAME` follows
  the `filename` that faust-rs's `metadata()` already reports. The C++ Rust
  backend ignores `-uim` apart from the option echo, and so does faust-rs's.
