## eval: report the other undefined symbols of a program

Commit date: 2026-11-01

Source commit: this commit

`process = ax + bx + c;` gave one error, and two more compilations to find the rest.
Each undefined symbol the evaluator reaches now gets its diagnostic.

The plan was to record a failed lookup and go on in the same run. Reading the evaluator
ruled that out: it tries things and drops their error (`a2sb(...).ok()` on arguments, a
constant tried in `iteration.rs`), so a symbol met there does not fail a program today, and
recording it would refuse programs that compile. Instead the ordinary run stands. When it
fails on an undefined symbol, a further run with its own `LoopDetector` reads each one as `_`
and records it. Which programs are accepted and their first error cannot change, since the
code that decides them is unchanged. What the further run fails on is dropped, since the `_`
may have caused it, and a symbol found this way may lie in code the repaired program does not
reach, which a note says.

The cost is on the error path: at most twice the first run, at least 1 s, polled with the
cancel flag, and at most 8 errors. `a_run_past_its_budget_stops` fails with the check removed.
The Faust scope rules are not restated anywhere.

On the 2991 mutants, the previous binary and this one agree on every verdict and every first
error. Simulated compiles go from 3.30 to 3.27, little because two wrong names rarely meet
in that mix. On the 20 programs of the blind repairs, which hold two typos each, a prototype
found both at once in 17 of 19. The first estimate, a sixth of the attempts, was wrong: it is
about 7 % there, and the blind repairs were not run again. Analysis and plan in
`porting/multi-error-semantic-diagnostics-analysis-and-plan-2026-11-01-en.md`.

`compile-budget-check` cannot run on this Mac. The success path gains a `match` on the result
of evaluation and an `Instant::now`.

## diagnostics: keep to the facts of the failure at the standard level

Commit date: 2026-11-01

Source commit: this commit

What remained of the text the evaluation in `faustprobe-diagnostics-eval` measured
restated the header or held for every failure of a kind. On an undefined symbol,
`cause`, `rule` and `computed` said in three lines that the symbol is undefined, and
three help lines said to define it.

`cause:` and `rule:` notes, and `general:` and `template:` help, move to `debug`.
`Standard` keeps what depends on this failure: `computed` notes with values,
`suggested target`, `did you mean`, specific help and fixes. `Concise` shows the
first specific help, so each level stays a superset of the one below, and an
undefined symbol has none there. The JSON report keeps all of it.

The filter is on these prefixes, in `diagnostics_human.rs`, next to the one for
`node_id=`. A typed tier would have meant changing a hundred producers for a
distinction `normalize_note_order` already reads from the same prefixes. Generic help took the
prefix `general:`. Three `computed:` notes that repeated their header became `cause:`
(the scope of a symbol, `2 == 3 -> false`, the tuple of a `case`), and so did
`provided=2, expected_max=1`, the reason of a modulation circuit, and `first bound to
node N`, the last place a node number was shown.

`iteration count is not an int node: 309` printed a node number too, and now says
`iteration count is not an integer constant`.

Reading all 37 forms of error the corpus produces at this level, none becomes
unclear: each keeps a header that says what failed, and the location. That is a
reading, not a measure, and the blind repairs of the evaluation have not been run
again on this text.

Median text on the 2754 mutants goes from 491 to 454 characters, 71 for C++. The
median hides the two families: syntax errors, the majority, do not change, and
semantic ones fall by a third or more, arity from 1119 to 780 and a misspelt name
from 1000 to 604. Lines reported are unchanged, so simulated compiles and lines read
do not move.
