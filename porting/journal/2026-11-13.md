## Clippy 1.100 lints: needless_range_loop and needless_bool

Commit date: 2026-11-13

Source commit: this commit

The CI "Lint and test" jobs of run 43312340812 (push of `460f02cc` to `main`)
failed at the Clippy step: rustc/clippy 1.100.0 (2026-11-09) flags code that was
already on `main`. Three sites:

- `transform/src/signal_fir/vector/assemble/check.rs` and `materialize.rs`:
  `needless_range_loop` on the iteration-major transposition of a lockstep
  bundle's member loops (`exec[index]` of every member, in member order, for
  each `index`). Clippy's suggested `exec.iter().take(width)` would read a
  single loop's list and is wrong here; both sites are rewritten as
  `(0..width).flat_map(...)`, which builds the same vector in the same order.
- `compiler/src/enrobage.rs::word_boundaries`: `needless_bool`, the trailing
  `if ... { return false } true` becomes a negated expression.

Validation: `cargo clippy --workspace --all-targets -- -D warnings` clean,
`cargo test -p transform -p compiler --lib` and `xtask golden-check` pass. No
whole-corpus codegen-identity differential was run; the rewrite preserves
element order by construction.

Lesson: the clippy gate before commit is workspace-wide; running it on the
touched crate alone (as for `460f02cc`) misses lints a new toolchain adds
elsewhere.
