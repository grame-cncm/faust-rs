# 2026-08-18

## P6: extend the structural floor, and fix a phantom documentation gate

Commit date: 2026-08-18

Source commit: this commit

P6, the phase that records P1-P5's result as a permanent floor rather than a
one-time cleanup.

**Line-size scope widened from two crates to four, threshold lowered from
2400 to 2000.** `structure-check` now scans `transform`, `compiler`, `fir`,
and `codegen` — the crates this campaign actually restructured — instead of
just `transform`/`compiler`. `MAX_PRODUCTION_LINES` drops to 2000: P3 and P5
removed every file that had been driving the old 2400 (`fir/checker.rs`,
`interp/compiler.rs`, `interp/fbc_to_cpp.rs` are all under 1000 lines now).

**Not literally "the whole workspace".** Measured before committing to it:
mechanically scanning all 31 crates at any reasonable threshold produces
roughly a dozen fresh findings on files this campaign never analyzed —
`parser/lib.rs` (3151), `sigtype/rules.rs` (2610), the FFI crates. Doing that
would convert a passing gate into "known-broken with a permanent exception
list", which is exactly the failure mode the old threshold's own doc comment
warned about. The brief's intent is followed — real widening, backed by real
work — without pretending to have analyzed crates nobody looked at today.

**Twelve files stay over the new threshold, each named in
`KNOWN_OVERSIZED_FILES` with a specific reason** rather than folded into a
raised number: `signal_fir/vector/lower/signal.rs` (numerically sensitive,
plan §7), `compiler/src/lib.rs` (dense facade, not one collapsible block —
checked by inspection: its largest `impl` is ~970 lines, nothing like
`checker.rs`'s 2649-line block), `fir/inliner.rs` and
`cranelift/lowering.rs` (untouched by this campaign, backlog), the seven
textual-backend `mod.rs` files (plan §2.9: legitimate machine size, not
duplication), and `interp/executor.rs` (P3's deliberate deferral). The list
is cross-checked both ways — a path absent from the scan, or one that has
since shrunk under the threshold, is itself a finding, so a future split
that resolves an exception gets flagged for cleanup instead of leaving a
dead entry.

**The `missing_docs` floor for `transform` did not exist, despite being
documented as existing since plan R9.2.** `cargo rustdoc -p transform --lib
-- -D missing-docs` had no CI step and no xtask command running it — a
phantom gate, caught only because P6 tried to wire it up properly. Worse: an
xtask command shelling out to `cargo rustdoc -- -D missing-docs` was written
first, and a rejecting-mutation test on it revealed the command had *no
effect at all* — an undocumented `pub struct` compiled clean. The cause:
both `transform/lib.rs` and `compiler/lib.rs` declared
`#![warn(missing_docs)]`, and an inner attribute overrides a command-line
lint level for that same lint, so `-D missing-docs` (and the workspace's own
`-D warnings` from clippy/CI) had never once touched it.
`compiler/src/lib.rs`'s own comment claimed "[t]he workspace CI gate ... turns
this into a hard failure" — a documented guarantee that a rejecting mutation
showed was false.

Fixed by changing both attributes to `#![deny(missing_docs)]`, which fails
`build`/`check`/`clippy`/`test` directly with no separate command needed —
simpler and stronger than the shelled-out command, which was deleted.
`structure-check` gained a cheap, filesystem-only rule verifying the literal
`#![deny(missing_docs)]` string is present for each crate in
`DOCUMENTED_CRATES`, so a future edit back to `warn` is caught mechanically.
`fir`, `codegen`, `parser`, `eval`, and `propagate` measured 288/509/46/66/56
missing-doc errors respectively — real, pre-existing debt this phase records
and does not attempt to close.

**A methodology note on testing the new checks.** The first attempt to
verify the stale-exception cross-check mutated a real backend file
(`cmajor/mod.rs`) to simulate it shrinking below threshold — but `xtask`
depends on `codegen` and `compiler` as real Rust crates, so `cargo run -p
xtask` rebuilds them, and the mutated file broke `codegen`'s compilation
outright. The cross-check logic was extracted into two pure functions,
`stale_oversized_exceptions` and `missing_deny_attribute`, taking already-read
strings rather than touching the filesystem, and six unit tests in
`crates/xtask/src/tests.rs` verify both mechanisms without needing the
workspace to build — the same lesson `render_baseline_section` and
`parse_impl_header` already taught in earlier phases: pure functions over
in-memory data are what make a check's own logic testable at all.

**Also fixed: two stale intra-doc links in `transform/src/signal_fir/mod.rs`**,
left over from P1's rename of `compile_signals_to_fir_fastlane_with_ui` to
`compile_signals_to_fir_fastlane` — a direct regression of this campaign's
own earlier commit, caught by finally running the doc-coverage check that
should have caught it in P1.

Both plan documents (`porting/faust-rs-structure-readability-plan-2026-08-18-
{en,fr}.md`) are updated with P6's actual outcome and a status line for the
whole campaign: P1, P2, P4, P5, P6 done; P3 two-thirds done; P7 open.

Gates: `cargo fmt --all`; clippy `-D warnings` exit 0; `cargo test --workspace
--all-targets` exit 0 with 103 suites and 2541 tests (2535 plus 6 new); FIR
over the 133-DSP corpus unchanged, SHA-1
`2223e5b6ed5e4baf231ecdbfb7a14d7b2ce3a642` (doc/attribute-only edit); all five
structure gates OK, including the two new rules; the public-API baseline does
not move. `compile-budget-check` measured 959.750 units on `reverb_designer`
vector codegen against the 953.982 ceiling — inside the 945-976 band observed
since `fb229047`, same pre-existing cause.

Source commit: this commit

`fir/checker.rs` was 3336 lines holding a single 2674-line `impl VerifyCtx` with
67 methods. As with `compiler.rs`, the methods themselves were fine — the
longest, `check_compute_body_io_access`, is 153 lines, and nothing approached
the 400-line criterion. What made the file hostile is that it is the FIR
*validity authority*: everything downstream trusts it, and a reviewer had no
boundary at which to stop reading.

Seven rule modules under `checker/`:

| module | methods | lines |
|---|---|---|
| `context` | 8 | 157 |
| `types` | 12 | 198 |
| `phases` | 4 | 253 |
| `table_fill` | 6 | 325 |
| `statements` | 11 | 519 |
| `values` | 18 | 563 |
| `module_shape` | 8 | 665 |

`checker.rs` goes from 3336 to 669 lines, keeping the diagnostic model, the
symbol tables, the scope stack, and the public entry points. Bodies move
verbatim; the only edit is visibility, private to `pub(super)`.

**Neutrality proof.** The checker emits diagnostics rather than code, so the
proof is that it says the same things: `--dump-fir-verify` over the 133-DSP
corpus is byte-identical, SHA-1
`de6cfb6431c77c84b9459fce5790e6430efd9abf` on both sides.

**A generator bug caught by insisting on fixing the generator, not the output.**
The first extraction computed each method's end as "the line before the next
method starts", which swept trailing section banners into the previous method
and left `context.rs` with an unbalanced brace. The fix was not to patch the
emitted file: a method now ends at the last `    }` before the next one begins,
and the generator asserts every extracted chunk balances before writing
anything. All 67 chunks then balanced on the first try. Patching the single file
that failed to compile would have left the same latent defect in any module
whose imbalance happened to be syntactically legal — the same trap recorded for
`compiler.rs`, met again because the first fix there addressed the symptom.

## P4: one error carrier for the seven textual backends

Commit date: 2026-08-18

Source commit: this commit

The plan predicted "the `CodegenError` type with its `new`/`Display`/`Error`
impls duplicated verbatim across all seven textual backends". Measurement
corrected that: **the error-code enums genuinely differ** — `asc`, `julia` and
`rust` have three codes, `c` and `cpp` add `MemoryLayout`, `cmajor` and
`codebox` have their own sets entirely. Only the *carrier* was duplicated, and
even then in three shapes: four backends byte-identical, `cpp` with an extra
`fir_node` provenance field, `cmajor`/`codebox` exposing `code`/`message` as
public fields instead of accessors.

That accident was already visible from outside. `crates/codegen/src/backend_error.rs`
had to carry **two** macros, `impl_backend_error_via_methods!` and
`impl_backend_error_via_fields!`, for no reason other than that nobody had
unified the carrier.

`crates/codegen/src/backends/codegen_error.rs` is now that carrier:
`BackendError<C>`, generic over the backend's own code enum, with `new`,
`code()`, `message()`, `at_node()`, `fir_node()`, `Display` and `Error`. Each
backend keeps its enum, implements `CodegenErrorCode` on it, and aliases
`pub type CodegenError = BackendError<CodegenErrorCode>;`.

Net: 246 lines removed, 67 added across the seven backends, plus 85 lines of
shared carrier — and `cmajor`/`codebox` moved from the fields macro to the
methods one, so that split now only serves `interp` and `cranelift`, which were
left alone.

**Neutrality proved backend by backend, before the abstraction landed**, as the
plan requires. Emitted output over the 133-DSP corpus, byte-identical on both
sides:

| backend | emitted | SHA-1 |
|---|---|---|
| asc | 133 | `fe737bdb1572` |
| c | 133 | `3d34b6cbbac4` |
| cpp | 133 | `c90fe20889aa` |
| julia | 133 | `9cea6eccc085` |
| rust | 133 | `0625d7e870a8` |
| cmajor | 131 | `d9874539f989` |
| codebox | 91 | `df556358f258` |

**A methodological error worth recording, because it silently invalidates a
proof.** The `julia` and `rust` baselines were first captured by a background
job that was still running when the foreground rebuilt `faust-rs` with the
change applied. Files emitted after that rebuild came from the *modified*
binary, so the "before" set was part before and part after — and comparing it
against the modified build would have proved identity by assuming it. The
baselines were discarded and recaptured with the change stashed. A long capture
and a rebuild must not share a working tree.

Gates: `cargo fmt --all`; clippy `-D warnings` exit 0; `cargo test --workspace
--all-targets` exit 0 with 103 suites and 2535 tests, unchanged totals;
`golden-check` OK; all five structure gates OK. The public-API baseline records
the move: `CodegenError::{new,code,message,at_node}` out, `BackendError::*` plus
`trait CodegenErrorCode` and `type CodegenError` in. `compile-budget-check`
stays red on `reverb_designer` vector codegen for the cause established in
`73f38bb7`.

## P3 (partial): split the FBC-to-C++ instruction dispatch by family

Commit date: 2026-08-18

Source commit: this commit

First half of P3. `fbc_to_cpp.rs` held `compile_instr`, 1449 lines and 283 match
arms — the second-longest function in the workspace. It is now a dispatcher plus
six family modules under `fbc_to_cpp/`:

| module | lines | parameters |
|---|---|---|
| `casts` | 69 | `out, t, instr` |
| `control` | 228 | all, including the arena |
| `memory_io` | 255 | `+ block_id, pc` |
| `math_std_value` | 330 | `out, t, instr` |
| `math_std_stack` | 347 | `out, t, instr` |
| `math_ext` | 386 | `out, t, instr` |

`fbc_to_cpp.rs` goes from 2255 to 913 lines. No function above 400 remains, and
no family file reaches 400. The arms are moved verbatim; only the enclosing
function changed.

**The partition is checked by the compiler, not by review.** An opcode missing
from every family leaves the dispatcher's match non-exhaustive; an opcode
claimed by two families makes an arm unreachable, which clippy rejects under
`-D warnings`. Nobody has to re-read 283 arms to believe the split is complete.

Each family takes only the parameters it uses, so a signature states what a
family cannot reach: the math families see neither the block arena nor the
block position, and therefore cannot raise position-dependent errors.

**Neutrality proof.** Emitted C++ is byte-identical across the corpus: 132 of
the 133 impulse DSPs produce FBC that the generator accepts, 4 663 528 bytes,
SHA-1 `d3987abc6017ae8cac40cca5a8452ff5387686d3` on both sides, rebuilt from the
stashed original rather than compared against a stored artefact. The public-API
baseline does not move, since every new item is private.

Gates: `cargo fmt --all`; clippy `-D warnings` exit 0; `golden-check` OK; all
five structure gates OK. `compile-budget-check` stays red on `reverb_designer`
vector codegen for the cause established in `73f38bb7` — the P2 state measured
964.500 units against the 953.982 ceiling, inside the 945-976 band seen since
`fb229047`.

**A trap worth recording.** The first attempt to compare emitted C++ produced
*zero* emissions and the SHA-1 of the empty string, which reads exactly like a
clean result. `--dump-cpp-from-fbc` takes a `.fbc` file, not a `.dsp`: the corpus
has to go through `--dump-interp` first. A comparison that emits nothing on both
sides matches perfectly and proves nothing.

**Deferred, with reasons: `executor.rs` is not split.** Its 1640-line
`try_execute_block_io_inner` is the interpreter dispatch loop — `loop { match
instr.opcode { … } }` over local real/int/address stacks and a program counter.
Splitting it by family the way `fbc_to_cpp` was split would insert a second
match per executed instruction in the hottest loop of the product. The plan
forbids performance regressions, and no gate in this repository measures
interpreter throughput, so the cost could be neither proven absent nor
detected. Three options were put to the maintainer: extract arm bodies as
`#[inline(always)]` helpers keeping one match; defer and move to `compiler.rs`;
or build an interpreter throughput benchmark first and split against it. The
maintainer chose to move to `compiler.rs`, which is compile-time code and
carries no such risk.

## P2 (eval, propagate): collapse the remaining pipeline entry-point families

Commit date: 2026-08-18

Source commit: this commit

Second and third crates of P2, after `parser` in `73f38bb7`.

**`eval`: nine entry points become two.** The crate crossed two names —
`eval_process` for the default `process` entry, `eval_entrypoint` for a custom
one — with three optional concerns spelled out in the names: statistics, a
source context, cancellation. `EvalRequest` now carries `entrypoint`
(default `"process"`), `source_context` (default `EvalSourceContext::memory()`)
and `cancel`, and the single `eval` always returns the statistics; discarding
them is the caller's `?.0`, which is exactly what the non-instrumented wrappers
did. `eval_process` stays as the shorthand for the dominant case, its 45 call
sites untouched. **Three of the nine variants had no caller anywhere**:
`eval_entrypoint`, `eval_entrypoint_with_source_context`, and
`eval_process_with_stats_and_source_context`.

**`propagate`: three entry points become two.** Only
`propagate_typed_with_ui` / `_with_ui_options` was a telescoping pair, and it is
folded — `ui_options` is now an explicit parameter, 19 call sites passing
`&PropagateUiOptions::default()`. `propagate_typed` is deliberately kept
separate: it is not a variant but a different operation. It disables provenance
recording — a documented performance choice, since `eval` reaches it for every
constant fold and would otherwise pay a full provenance forest walk each time —
and it returns `Vec<SigId>` rather than `PropagateOutput`. Merging it would be
exactly the "two things that resemble each other" fusion the plan forbids.

**Neutrality proof.** FIR for all 133 impulse-test DSPs identical after each
step, SHA-1 `2223e5b6ed5e4baf231ecdbfb7a14d7b2ce3a642` — unchanged since before
P1, so the whole campaign has emitted the same FIR throughout.

Gates: `cargo fmt --all`; clippy `-D warnings` exit 0; `cargo test --workspace
--all-targets` exit 0 with 103 suites and 2535 tests, unchanged totals;
`golden-check` OK; all five structure gates OK.

**`compile-budget-check` remains red for a cause that predates this campaign**,
as established in `73f38bb7`: `reverb_designer` vector codegen brushes and

## P2 (parser): collapse fourteen parser entry points into five operations

Commit date: 2026-08-18

Source commit: this commit

First crate of P2. `parser` exposed fourteen public entry points across the
`parse_program` / `parse_file` / `parse_url` families, whose names spelled out
which optional arguments they carried: `_with_metadata`,
`_with_precision_and_metadata`, `_with_imports_and_precision_and_metadata`,
`_with_remote_imports_and_precision_and_metadata`, and so on. Each name was one
point in a combinatorial space and a caller had to find the point matching the
arguments it happened to hold.

**The plan said "identical shape to P1"; it is not, and the phase was adapted.**
The parser variants differ by *return type* — the in-memory no-import parse is
infallible, anything resolving imports returns `SourceReaderError` — and by
*source* (memory / file / URL). Collapsing all fourteen into one entry would
have forced a `Result` onto 43 call sites that cannot fail, which is a
regression, and would have merged operations that do not share a role. So the
fold is per operation, with the optional knobs in one `ParseOptions`:

- `parse_program(input, source_file)` — the infallible shorthand, unchanged, all
  43 call sites untouched;
- `parse_program_with_options` — same, with precision or a shared metadata store;
- `parse_program_with_imports` — in-memory root, import expansion, fallible;
- `parse_file` — file entry;
- `parse_url` — HTTP(S) entry.

Fourteen become five. `ParseOptions` carries `metadata_store`, `float_size`
(default 1), `search_paths`, `virtual_sources` and `remote`, with `Default` and
chainable setters.

**One semantic trap.** The old remote variant decided whether the root was a
remote source by attempting `Url::parse(source_file)`. Merged naively, that
probe would start running for local callers whose source identity happens to
parse as a URL, changing which expander path they take. The branch is therefore
gated on `options.remote.is_some()`, reproducing both old paths exactly; the
reason is a comment at the test itself.

Two variants were already dead: `parse_file_with_imports_and_metadata` had no
caller, and the URL enabled/disabled pair now differs only by whether
`options.remote` is present.

**Neutrality proof.** FIR dumps for all 133 impulse-test DSPs rebuilt from the
stashed original code: identical, SHA-1
`2223e5b6ed5e4baf231ecdbfb7a14d7b2ce3a642`, `diff -rq` clean.

Gates: `cargo fmt --all`; clippy `-D warnings` exit 0; `cargo test --workspace
--all-targets` exit 0 with 103 suites and 2535 tests, unchanged totals;
`golden-check` OK; all five structure gates OK.

**`compile-budget-check` fails, and it failed before this work started.**
`reverb_designer` vector codegen exceeds its ceiling of 953.982 units. Measured
on an idle machine across four states with byte-identical FIR, hence identical
codegen input:

| code | units |
|---|---|
| `fb229047` (before P1) | 967.250 |
| HEAD (P1 + baseline fix) | 965.500 |
| this commit | 976.250 |
| during P1 | 945.250 (passed) |

A 3.3 % spread straddling the ceiling: **the gate is non-deterministic at this
margin on this machine**, and the case has been brushing its ceiling since
before the readability campaign began. This also corrects the P1 journal entry:
its `compile-budget-check exit 0` was accurate but lucky — the same code
measures above the ceiling on other runs. The baseline is deliberately *not*
updated, since raising it would mask the condition rather than diagnose it. This
needs its own investigation: either the vector codegen path for this DSP is
genuinely near a cost cliff, or the calibration is too coarse for a case sitting
at 130 % of its recorded baseline.

**Migration method note.** The first rewrite script crashed mid-run on an
unexpected arity and left files half-modified; everything was reverted with
`git checkout` and redone with an explicit arity assertion and a dry run. The
assertion immediately isolated the one trap: a `parse_file_with_imports(...)`
mention inside a doc comment, which the first version would have turned into
broken code.

## Qualify baseline methods by their implementing type

Commit date: 2026-08-18

Source commit: this commit

P1 exposed a blind spot in the public-API baseline added earlier today:
`SignalFirRequest::new` did not appear in its diff, although it is a new public
item. The scanner recorded items as `(kind, name)` with no knowledge of the
enclosing `impl`, so every method sharing a name collapsed onto one entry.
**18 of the 31 crates already carried a bare `fn new`**, which means adding a
constructor to a brand-new type produced no diff at all and `--check` stayed
silent — the gate was blind to exactly the kind of boundary growth it exists to
catch.

`public_items_for_package` now tracks the enclosing `impl` with a brace counter
that ignores string literals and trailing line comments, and records methods as
`Type::method`. `impl Trait for Type` is indexed under `Type`, since that is the
item a reader looks up. `parse_impl_header` only matches an `impl` at the start
of a line, keeping nested and indented blocks out.

Validated with a discriminating mutation rather than a green run: a public
`MutationProbe` type with a `new` constructor added to `transform`, regenerated,
and diffed against the clean post-fix baseline yields exactly

```
> fn MutationProbe::new
> struct MutationProbe
```

The old scanner would have emitted `fn new`, already present in `transform`'s
section, hence deduplicated, hence invisible. With the mutation removed the
baseline is byte-identical to the clean one again.

Effect: 2598 -> 2719 baseline items, 1208 methods now distinguished by their
type. The 1209/1088-line diff is entirely mechanical — the same surface, named
precisely.

Two unit tests lock the pieces: `parse_impl_header` across the four `impl`
shapes this workspace uses, and `brace_balance` against the failure that would
be silent and total — a format string such as `"[{}] {}"` desynchronising the
counter for every `impl` after it in the file.

Gates: `cargo fmt --all`; `cargo clippy --workspace --all-targets -- -D warnings`
exit 0; `cargo test --workspace --all-targets` exit 0, 103 suites, 2535 tests
(2533 plus the two new ones); all five structure gates OK.
`compile-budget-check` was not run: `xtask` is not in the compilation pipeline
`AGENTS.md` §5 lists, and this change emits no FIR, so the test suite is its
only neutrality evidence — as the readability plan §7 requires such phases to
state.

`Option`s passed as `None` by the short variants. Callers had to know which of
five near-identical names carried the argument they needed.

Replaced by one entry point, `compile_signals_to_fir_fastlane(&SignalFirRequest)`.
The request struct takes the six always-required inputs through `new()` and
attaches each optional input by name: `with_clock_domains`, `with_timing_sink`,
`with_signal_origins`, `with_forced_shadow_report`. 15 files touched, 14 call
sites migrated, +256/-251 lines.

The shadow-report flag needed care to stay behaviour-identical: every old
variant read `FAUST_RS_SHADOW_REPORT` from the environment except
`_with_ui_and_shadow`, which forced it on. The single entry point ORs the
request field with the environment probe, reproducing both behaviours without
a second function.

One variant was already dead before this phase:
`compile_signals_to_fir_fastlane_clocked_with_timing` had no caller outside its
own file.

**Neutrality proof.** FIR dumps for all 133 impulse-test DSPs were produced with
the new code, the change was then stashed, the same dumps rebuilt from the
original code, and the change restored: 13 296 059 bytes, SHA-1

Gates: `cargo fmt --all`; `cargo clippy --workspace --all-targets -- -D warnings`

The `code-graphs --check` gate added earlier today fired as designed and its

**Two things recorded rather than fixed here**, to keep the commit single-subject:

- `compile_fastlane_inner` still takes 11 positional parameters. It is private,
  so it is not the boundary; folding it is a separate change.
- The public-API baseline has a blind spot this diff exposed:
  `SignalFirRequest::new` does not appear, because deduplicating on

## Audit the workspace structure and plan the readability restructuring (Phase 0)

Commit date: 2026-08-18

Source commit: this commit

Phase 0 of the structure/readability campaign: audit and plan only, no code
touched. Deliverable is the twin pair
`porting/faust-rs-structure-readability-plan-2026-08-18-{en,fr}.md` (EN
canonical), backed by `porting/scripts/structure-metrics.py` so every figure in
them can be replayed rather than trusted.

The metrics script is a brace scanner that blanks comments and string literals
before counting. It is deliberately syntactic and undercounts rather than
guessing: 272 411 lines of Rust, 212 571 production, 31 production files over
1500 lines, 116 functions over 150 lines, 24 `impl` blocks over 500.

The dominant finding was not among the suspects the brief listed. **240
production functions take more than 6 parameters** (up to 22 in
`interp/factory.rs`), and the same pressure has produced six families of
telescoping entry points at stage boundaries — `parse_program` has 6 variants,
`eval_entrypoint` 5, `compile_signals_to_fir_fastlane_*` 5, all delegating to
one inner function whose optional arguments are spelled out in the variant
names. `compile_fastlane_inner` takes 11 positional parameters, three of them
`Option` passed as `None` by the short variants. This is the defect with the
widest blast radius because it sits exactly where a reader orients, and the
cheapest to fix because the remedy is pure delegation.

Three suspects from the brief were measured and dismissed, so no phase spends
effort on them: module tree depth (max 3), modules without a `//!` header (7 of
~700), and anonymous tuple returns with 3+ fields (13, ten of them test
fixtures). Crate-level dependency direction is clean with no cycles.

Two premises of the brief are contradicted by measurement, and the recommended
order changes accordingly:

- `transform` is not a bulk target. Its `signal_fir/vector/**` is already
  restructured into 13 coherent sub-modules of 2000-3500 lines each by the R3
  work; attacking it wholesale would redo finished work. What remains is one
  oversized file (`lower/signal.rs`, 2339) and its entry points.
- `codegen` is not "the only place restructuring reduces volume". Pairwise
  similarity of the seven textual emitters' `mod.rs` is 21-57 % (c/cpp highest),
  not near-duplication, and 7-34 % of each file is inline test code. The volume
  is in `interp` (12 848) and `cranelift` (4 620), large because they are
  machines. Extractable duplication is the per-backend `CodegenError` plus
  `decode_module` — hundreds of lines, not thousands.

Two `AGENTS.md` §2 discrepancies recorded. The `extended` math-node integration
into `signals` is true in substance but stale in vocabulary: the constructors are
in `signals`, while the word survives only in `boxes/src/print.rs` and the
interpreter opcode tables, so grepping for it lands in the wrong crate. Also,
three workspace members are declared placeholders (`graph` 21 lines, `doc` 22,
`algebra` 29), so every crate-level view overstates the structure by three.

Recorded without making it a phase: `compiler` carries 21 449 lines of test code
against 16 011 of production, and 652 of the workspace's ~2500 `#[test]`
functions — a quarter of the suite sits at the top of the pipeline, where a
failure identifies the whole compiler rather than a stage.

Plan is P1 through P7, each severable. Recommended first phase is P1: collapse
the five `compile_signals_to_fir_fastlane_*` entry points
(`signal_fir/mod.rs:508-663`) into one taking a documented `SignalFirRequest`.
Smallest provable instance of the most general defect, one commit, and it
exercises every gate including the public-API baseline added earlier today —
where the boundary change will show up as a reviewable diff. No implementation
starts before the plan is explicitly approved.

## Gate the checked-in code graphs and add a public-API baseline

Commit date: 2026-08-18

Source commit: this commit

`cargo run -p xtask -- code-graphs` had no verification mode and was in no CI
job, so its output drifted silently: the last regeneration was 2026-07-28, as a
side effect of an unrelated docs commit, and `libfaust-ffi` was already missing
from both crate graphs. A generated artifact nobody regenerates is worse than
no artifact, because readers still trust it.

`code-graphs` now renders its artifacts into a `Vec<(PathBuf, String)>` before
touching the disk, then either writes them (plus the Graphviz SVGs) or, under
the new `--check`, compares them against what is committed and reports every
difference at once. Regeneration is the bless path — there is deliberately no
self-healing mode, since the point is to read the diff.

The gated artifact for public surfaces is the new
`docs/code-graphs/public-api-baseline.txt`: one `<kind> <name>` line per public
item, sorted and deduplicated, with **no source locations**. The failure mode it
exists to catch is the `pub` leak — relocating a function out of a crowded
module usually means widening a `pub(crate)` helper to `pub` so the move
compiles, which no existing gate observes, and which grows the very crate
boundary a restructuring set out to clarify.

Two artifacts are exempt from `--check`, both for reasons that were measured
rather than assumed:

- `public-api-index.md` keeps `file:line` locations, so any code motion makes it
  differ. Regenerating after a mutation that only shifted line numbers produced
  a 2202-line diff with no public item changed; gating it would fire on exactly
  the commits a restructuring produces, and a gate that cries wolf gets turned
  off.
- The three `.svg` renderings shell out to Graphviz `dot`, which the CI runners
  do not install — this is why `code-graphs` could never be wired to CI as it
  stood. They derive from the `.dot` files, which *are* checked.

Validated with rejecting mutations, not just a green run: adding a
`pub fn leaked_helper()` to `algebra` makes `--check` exit 1 naming the
baseline, while inserting three lines at the top of the same file (shifting
every line number) leaves it green at "8 artifacts identical". Four unit tests
in `crates/xtask/src/tests.rs` lock both properties plus deduplication and flag
parsing; `render_baseline_section` was extracted so they run without invoking
`cargo metadata`.

Wired into the Ubuntu-only "Structure check" CI step, which goes from four
static gates to five. It stays mono-OS for the same reason as the others: the
compared artifacts hold crate and item names only, never paths, so they are
byte-identical on every platform. `AGENTS.md` §3/§4 document the new command and
what to do when the baseline differs. The first regeneration also settles the
accumulated drift, putting `libfaust-ffi` back into both crate graphs.

Also removed `tests/impulse-tests/FOO.dsp`: 9789 lines of *generated* output
(`name: "reverb_designer"`, "Code generated with Faust 2.87.2"), committed by
accident in `295d23e8` during asc backend work and referenced by no Makefile,
test, or document.

Gates: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo test --workspace --all-targets`, and all five structure gates including
the new one.
