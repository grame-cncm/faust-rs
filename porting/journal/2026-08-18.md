# 2026-08-18

## Sync `user-cli-guide-en.md` with the actual CLI, and fix drift found while auditing docs/

Commit date: 2026-08-18

Source commit: this commit

The user pointed at `docs/user-cli-guide-en.md` and said it was stale. Diffing
it against `crates/compiler/src/cli/{args,runner,validate,source_mode}.rs`
showed it was missing roughly two-thirds of the actual flag surface: `--check`,
`--dump-interp`, `--dump-sig-dag`, `--svg` and its six layout flags, `-v`/
`--version`, the `--libdir`/`--includedir`/`--archdir`/`--dspdir`/`--pathslist`
info flags, `-cn`/`-scn`/`--cpp-class-name`/`-pn`, architecture wrapping
(`-a`/`-A`/`-i`), `--diagnostic-paths`, `--warn`, `--memory-manager`,
`--table-init`(`-sample-rate`), `--vec`/`--vs`/`--lv`, `--scheduling-strategy`,
four more `-lang` backends (`rust`, `asc`, `cmajor`, `codebox`/
`codebox-test`), and most of the legacy (`-pn`, `-cn`, `-mcd`, `-vec`, …) flag
mappings. It also had a stale claim that `-ec`/`-os` were rejected outside
`c`/`cpp`/`rust`/`fir`, when the execution-capability table
(`crates/compiler/src/execution.rs`) accepts `asc` explicitly too and treats
`codebox`/`cmajor` as intrinsic no-ops rather than rejections. The
`--signal-fir-lane` valid/invalid mode list was rebuilt against the actual
checks in `validate.rs`.

Every documented flag name, default, and `-lang` value was cross-checked
against `faust-rs --help`, and roughly a dozen of the documented example
commands (`--check`, `--dump-sig-dag`, `--dump-interp`, `--lang asc`, `-v`,
`--libdir`, …) were run against the built binary rather than assumed correct
from reading source. A follow-up request asked for the `-lang` example lists
to be alphabetized, which turned up three more unsorted enumerations in the
same file (the flag heading, the "reachable only through `-lang`" sentence,
and the legacy-compatibility bullet) — all four are now consistently
`asc, c, cmajor, codebox, codebox-test, cpp, cranelift, fir, interp, julia,
rust, wasm, wast`.

Asked to check the rest of `docs/` for similar drift, the same staleness
turned up in `docs/developer-workflows-en.md` §5 ("CLI language model"): it
listed only 7 of the 13 `-lang` backends. Fixed and cross-referenced the full
guide, and added `--check` to its "useful extras" list since it is now the
recommended no-codegen validity-check mode for CI/tooling. Running the
project's own consistency tool, `cargo run -p xtask -- diagnostics-quality-check`,
across the rest of `docs/` caught a real bug unrelated to the CLI guide:
`docs/faust-error-model-en.md` §7.1's `FRS-SRC-*` code table was missing rows
for `FRS-SRC-0004`/`0005`/`0006` (`InvalidUrl`/`NetworkDisabled`/
`RemoteFetch`, the remote-import error codes) that `docs/diagnostics-codes-reference-en.md`
already had. Added the three missing rows so the checker's cross-reference
passes again.

`docs/user-diagnostics-guide-en.md`, `docs/user-mem0-guide-en.md`, and
`docs/faustprobe-user-guide-en.md` were also spot-checked against the live
`compiler`/`faustprobe` binaries (including a poly-voice `--note`/`--nvoices`
render, since the `faustprobe` binary's own `--help` text for `--nvoices`
claims note/chord scheduling isn't wired up yet — it is; that stale doc
comment lives in the source, not `docs/`, and was left for a separate pass).
All three matched actual behavior with no changes needed.

**Check.** `cargo run -p xtask -- diagnostics-quality-check` (was failing with
3 findings, now `OK`). `cargo run -p compiler -- --help` diffed by hand against
every flag documented in `user-cli-guide-en.md`. `cargo run -p compiler --
--check|--dump-sig-dag|--dump-interp|--lang asc|-v|--libdir` and
`-lang cpp -mem0 -json` run against `tests/corpus/rep_01_passthrough.dsp` to
confirm documented behavior. `cargo run -p xtask -- structure-check`,
`error-model-check`, and `cli-parser-check` all `OK`.

**Not done.** The many point-in-time research/design notes under `docs/`
(De Bruijn recursion, fad/rad, vector-scheduling, …) were left untouched:
they are dated technical notes rather than living references tracked against
the CLI, and none of the automated consistency checks flagged them.
