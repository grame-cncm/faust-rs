## Crate-wide legibility analysis of `crates/transform`

Commit date: 2026-08-25

Source commit: this commit

New twin analysis documents
`porting/transform-legibility-analysis-2026-08-25-{en,fr}.md` (EN canonical):
why `crates/transform` is still costly for a human to read after the June 2026
decompositions and the July R0–R9 cleanup, and three independent,
FIR-neutral restructuring experiments to fix it.

Measured state (all commands recorded in the doc so the tables can be
re-derived): `transform` is now the largest crate of the workspace (34,628
effective + 15,681 test LOC via `scripts/loc_report.py`; 62,399 raw lines over
150 files, 48% of them under `signal_fir/vector/`). A brace-balance scan
counts 1,589 functions of which 69 exceed 100 lines and 21 exceed 200 —
`build_module` alone is 767 lines. Both production lowerers dispatch on the
typed `SigMatch` view but duplicate every stateless leaf-emission arm
(only `map_binop` is shared); ≈200 comment lines explain present-tense code
through historical plan codenames; and one measured truth-drift instance:
`loop_graph.rs` still claims "nothing here is wired into scalar codegen yet"
while `module/build.rs:991` routes every scalar per-sample slice through it,
and its file-level `#![allow(dead_code)]` hides an 11-warning dead cluster
(probed by removing the allow under `cargo check`, then restoring it).

The diagnosis names five costs (L1 function-level scale, L2 twin-lowerer
duplication, L3 codename indirection, L4 truth drift, L5
production/diagnostic mixing) and maps them to three experiments: E1
present-tense documentation + truth fixes + `diagnostics/` quarantine for
`pv_slice`/`shadow` (zero FIR risk), E2 recipe decomposition of the 21
oversized functions behind a ratcheting max-length gate, E3 a shared
stateless `leaf_emit` module for the two lowerers — the same pattern that
closed the C-family emitter drifts at backend level. The doc also freezes
what must not be simplified (producer/checker duplication, deterministic
ordering, fail-closed fallback taxonomy) and the shared migration protocol
(clean rebuild, golden-FIR byte diff across the mode matrix, impulse oracle,
rejecting-mutation validation for every new gate).
