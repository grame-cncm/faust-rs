## E1: present-tense doc comments, a codename gate, and a crate reading order

Commit date: 2026-08-25

Source commit: this commit

Third E1 landing, the large one: ~260 comment lines across ~60 files of
`crates/transform` explained present-tense behavior through historical plan
codenames ("P4.3b", "the P5 verifier", "roadmap P3 slice 4", "§4.8", "R1's
bullet", "S7"). Every such line now names the behavior itself — decoration
certificate, vector plan, routing evidence, state plan, clock/AD plan,
event-order certificate, assembly gate, schedule certificate, guarded-block
lowering, fire-time maintenance — and provenance survives only in
`Plan provenance:` mentions, `Development history:` lines naming their
`porting/` document, and the stage-map glossary of `vector/mod.rs`.

The sweep surfaced four more stale claims, all truth-fixed in passing:
`schedule/mod.rs` still said "nothing in the production compile path calls
`schedule` yet; hgraph keeps its own hand-rolled walk" (contradicted by
`hgraph`'s own header — the generic scheduler is production-authoritative
on both paths); `core_lowering.rs` and `error.rs`/`coverage.rs`/
`contract.rs` said clocked lowering "has not landed" where the rejection
actually fires when no clocked-lowering state is active for the run; and
`region.rs` said guarded child regions "arrive with P3" while documenting
them two paragraphs later.

The gate: `xtask structure-check` gains check 6 — a bare plan codename
(`P4.3b`, `R1`, `V5b`, `S7`, `§4.8`) in a transform comment block is a
finding unless the block names a `porting/` document or contains a
provenance/history marker — and check 7 — no file-level
`#![allow(dead_code)]` in the crate. Both validated by rejecting mutations
(an appended bare-codename comment and an inserted file-level allowance
each fail the gate; both reverted). `lib.rs` gains a "How to read this
crate" section giving the pipeline reading order and pointing first-time
readers away from `diagnostics/`.

Verification: `structure-check` OK (274 files), `cargo test -p transform`
(412 green), `cargo test -p xtask` (116 green), `cargo doc -p transform`
clean, clippy clean for the touched crates. Comment-only changes plus the
xtask gate: FIR-neutral by construction.

## E1: quarantine the observation-only surfaces under signal_fir/diagnostics/

Commit date: 2026-08-25

Source commit: this commit

Second E1 landing. `pv_slice` (the frozen PV vector pre-slice prototype) and
`shadow` (schedule-conformance reports) lived undistinguished next to
production modules, so a reader walking the production path had to open each
header to learn they are load-bearing nowhere. Both moved to a new
`signal_fir/diagnostics/` tree whose module header states the contract in
one place: observation only, never on the production path, consumed solely
by workspace integration tests and explicit diagnostic entry points.
`pub use diagnostics::{pv_slice, shadow}` keeps every existing import path
(`transform::signal_fir::pv_slice::...`, `...::shadow::...`) compiling
unchanged, so the `compiler` integration tests needed no edits; the
`signal_fir` module map now points at `diagnostics` instead of listing the
two modules as production neighbors. No production code changed.

Verification: `cargo test -p transform` (412 green), the two consumers
`pv_vector_slice` (3 green) and `p3_shadow_mode` (2 green), clippy clean.

## E1: tell the truth in loop_graph.rs and drop its dead half

Commit date: 2026-08-25

Source commit: this commit

First landing of experiment E1 from
`porting/transform-legibility-analysis-2026-08-25-en.md` (present-tense
documentation and truth maintenance), on branch `transform-legibility-e1`.

`signal_fir/loop_graph.rs` still opened with "Nothing here is wired into
scalar codegen yet, so it cannot affect existing output" while
`module/build.rs` routes every scalar per-sample slice through `LoopGraph`,
and its file-level `#![allow(dead_code)]` hid an 11-warning dead cluster.
The header now states who uses what today: the scalar slice routing is live;
the `-vec` chunk-driver half (`ChunkBuffer`, `partition_recursive_body`,
`rewrite_var_loads`, `emit_sample_loop`'s split emission) is currently
unreachable in production — the checked vector pipeline owns every accepted
`-vec` compile and a rejected one falls back to scalar, so no production
caller passes a vector compute mode into `build_module` anymore (verified:
`mod.rs` forces `fallback_compute_mode` to `Scalar` on every path that
reaches `build_module`, and `subcontainer_compile.rs` hardcodes `Scalar`).
Removing that half is recorded as a separate, behavior-neutral decision,
not taken here.

Deleted outright: the superseded signal-level loop-assignment section
(`LoopAssignment`, `assign_loops`, `assign_one`, `signal_value_children`,
`loop_of`) and its five tests — `vector/plan` owns signal-to-loop placement
now — plus the `LoopKind::Island` variant, never constructed in production
(its only consumer was one unreachable `emit_sample_loop` arm; islands are
handled by the checked pipeline's `clock_ad` stage). Helpers that only
tests call (`add_dep`, `len`, `is_empty`, `is_vectorizable`, `loop_kind`,
`ChunkBuffer::name`) are now `#[cfg(test)]` with a sentence saying so —
notably `add_dep`: the scalar path builds edgeless graphs, and the tests
keep pinning `topological_order`'s deterministic tie-breaking through it.
The file-level allow is gone; `pv_slice`'s two stale doc references to
`signal_value_children` now name the real walk
(`vector::analysis::signal_dependencies`).

Verification: `cargo check`/`clippy`/`test -p transform` (412 green),
`cargo test -p codegen` (goldens, 368 green), `cargo test -p compiler` —
the 4 `mem0_cpp_differential` failures observed there reproduce with and
without this change and are caused by the working tree's pending
deletions of `tests/impulse-tests/dsp-mem0/*.dsp` (restoring the files
makes all 4 pass with this change applied); they are unrelated to E1.

## Crate-wide legibility analysis of `crates/transform`

Commit date: 2026-08-25

Source commit: this commit

New twin analysis documents
`porting/transform-legibility-analysis-2026-08-25-{en,fr}.md` (EN canonical):
why `crates/transform` is still costly for a human to read after the June 2026
decompositions and the July R0–R9 cleanup, and three independent,
FIR-neutral restructuring experiments to fix it.

Measured state (all commands recorded in the doc so the tables can be
re-derived): `transform` is now the largest crate of the workspace (34,628
effective + 15,681 test LOC via `scripts/loc_report.py`; 62,399 raw lines over
150 files, 48% of them under `signal_fir/vector/`). A brace-balance scan
counts 1,589 functions of which 69 exceed 100 lines and 21 exceed 200 —
`build_module` alone is 767 lines. Both production lowerers dispatch on the
typed `SigMatch` view but duplicate every stateless leaf-emission arm
(only `map_binop` is shared); ≈200 comment lines explain present-tense code
through historical plan codenames; and one measured truth-drift instance:
`loop_graph.rs` still claims "nothing here is wired into scalar codegen yet"
while `module/build.rs:991` routes every scalar per-sample slice through it,
and its file-level `#![allow(dead_code)]` hides an 11-warning dead cluster
(probed by removing the allow under `cargo check`, then restoring it).

The diagnosis names five costs (L1 function-level scale, L2 twin-lowerer
duplication, L3 codename indirection, L4 truth drift, L5
production/diagnostic mixing) and maps them to three experiments: E1
present-tense documentation + truth fixes + `diagnostics/` quarantine for
`pv_slice`/`shadow` (zero FIR risk), E2 recipe decomposition of the 21
oversized functions behind a ratcheting max-length gate, E3 a shared
stateless `leaf_emit` module for the two lowerers — the same pattern that
closed the C-family emitter drifts at backend level. The doc also freezes
what must not be simplified (producer/checker duplication, deterministic
ordering, fail-closed fallback taxonomy) and the shared migration protocol
(clean rebuild, golden-FIR byte diff across the mode matrix, impulse oracle,
rejecting-mutation validation for every new gate).
