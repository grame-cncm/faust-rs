## `-svg`: a foreign function is drawn under its name, with its arity

Commit date: 2026-11-15

Source commit: this commit

Found while adding the block diagrams to the web page of `faust-gen-patches`:
every `ffunction` box (`ma.tanh`, `ma.copysign`, ...) was drawn as a block
labelled `?` with one input. `draw::translate` handed the whole
`ffunction(signature, incfile, libfile)` descriptor to `extract_name`, which
knows symbols and numbers only, and the arity was a literal 1.

C++ (`drawschema.cpp`, `isBoxFFun`) draws `makeBlockSchema(ffarity(ff), 1,
ffname(ff), ...)`: `ffarity` is `len(signature) - 2` and `ffname` is
`nth(names, gFloatSize - 1)`, the name of the precision compiled in (`tanhf`
in single precision, `tanh` under `-double`). The drawing had no precision at
all: the name of a folded expression without a definition name was printed
with `FloatSize::Single` whatever the options (`0.01f` under `-double`, where
C++ prints `0.01`).

- `draw::DrawConfig::float_size` (new field, default single; mapping
  `adapted`: C++ reads the global `gFloatSize`) carries the precision.
  `faust-rs -svg` sets it from `-double`, `faustprobe --svg` from its own
  `--double` (the probe strips the precision from the compile options it
  forwards, so it is set in `svg.rs`, not read back from them).
- `draw::translate::foreign_function` reads the arity and the name from the
  descriptor; a descriptor that is not of the parser's shape is still drawn
  as `?` with one input rather than panicking.
- `draw` re-exports `boxes::FloatSize`, the type of the new field: one new
  entry in `docs/code-graphs/public-api-baseline.txt`, so that
  `cranelift-ffi` can name it without depending on `boxes`.

Validation: four tests in `crates/draw/src/lib.rs` (the name per precision,
one input per argument, the malformed descriptor, the name of a folded
expression per precision); each of three mutations (first name always, arity
1, single precision in the expression name) fails exactly one of them.
Against the pinned C++ (2.84.3) on `process = ma.tanh, ma.copysign, ma.J0,
ma.Jn;`: the same labels and the same number of drawn lines, in single and in
double precision. No registry entry: the difference was a defect, never
recorded, and is closed.

Trap met on the way: `target/debug` held a `boxes` rlib built from another
branch (it knew `BoxMatch::SerializeOut`) that cargo took for fresh, so the
`xtask` gates failed to compile `propagate` on an untouched tree while
`clippy` and `test -p draw` passed. `cargo clean -p boxes` cleared it.
