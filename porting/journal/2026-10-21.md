# 2026-10-21

## Constant folding keeps distinct widgets distinct

Commit date: 2026-10-21

Source commit: this commit

Regression of WP2 (2026-10-10), present in `0.9.1`. Every argument of a
pattern-matched call is folded to a number when it is one (C++
`simplifyPattern` / `isBoxNumeric`). Since WP2 the fold
(`propagate::propagate_fold`) builds no UI program and gave every widget the
same placeholder control id, `FOLD_CONTROL_ID`. A widget signal carries its
control id and nothing else, so two widgets became one hash-consed signal:
`b - a` folded to `0`, `b / a` to `1`, `b < a` to `0`. The argument was
replaced by that constant, the widgets left the interface and the output was
a constant, whatever the widgets' values.

```faust
take(1, (x, xs)) = x;
take(1, x) = x;
take(n, (x, xs)) = take(n - 1, xs);
a = nentry("a", 1, 0, 10, 1);
b = nentry("b", 4, 0, 10, 1);
process = take(1, b - a);
```

`0.9.1`: no control, output `0`; C++ (2.90.14, `468a6dfa0`): two controls,
output `3`. Found on abclib's irregular decoder `abc_2d_decoder_ui(3, 8)`:
`circularScaledVBAP` compares two loudspeaker angles read with `ba.take`
inside another `ba.take` argument, so the whole VBAP path folded to `0`; the
eight angle controls and `angularoffset` were missing, and the eight outputs
were silent even at the default angles.

- `PropagateContext::control_ids` is now a `ControlIdSource`: `Ui`, the ids
  of UI extraction, unchanged; or `Fold`, where each widget gets its own
  placeholder id the first time the session meets it, counting down from
  `FOLD_CONTROL_ID`. The key is the one UI extraction uses (box node,
  group-path hash), so two widgets are one signal in a fold exactly when they
  are one control in the compiled program, as each C++ widget signal carries
  its own label path. The ids are kept in `FoldSession` (its `control_ids`
  map was always empty until now), so the cross-fold propagation memo stays
  consistent, and a session reset clears them with the rest. The `fold` flag
  is gone.
- The same widget in the same group keeps one id: `a - a` still folds to
  `0`, as in C++.
- Not reproduced in a fold: UI extraction aliases a widget re-referenced from
  an AD seed under another group to its primary control. A fold sees two
  signals there and misses that constant; it never invents one.

Tests: `crates/compiler/tests/fold_distinct_widgets.rs` (`take(1, b - a)`,
`b / a`, `a < b`, a pair argument, two elements of a list of widgets, one
widget in two groups, both widgets in the interface, and `a - a` still
folded); the four regression tests fail without the change. With the change,
`faustprobe` lists the twelve controls of `abc_2d_decoder_ui(3, 8)` and
matches the C++ rendering (Apple clang 21, `-ffp-contract=off`) within
`1e-7` at the default angles and with `a3 = 100`, `angularoffset = 30`.

Checks: `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets -D warnings`,
`cargo test --workspace --all-targets` (166 suites, 3375 passed, 0 failed,
4 ignored), `xtask golden-check` (292 cases) and the five structure gates
pass. `compile-budget-check` cannot measure on this machine (calibration
`karplus.dsp` 3 ms, below its 4 ms floor); measured directly instead, release
`faustprobe --list-params`, best of five: WP2's `g(n-1, x-1)` takes 0.031 s
at `n = 2000` and 0.055 s at `n = 4000`, as before the change.
`abc_2d_decoder_ui(3, 8)` goes from 0.056 s to 0.084 s because the VBAP path
it lost is compiled again.
