## The result memo keyed a box on the whole slot environment and on `suppress_fad`, so a definition read inside a `~` body was propagated again, and every clocked block in it allocated once more; the key is now the environment restricted to the box's free slots, and the flag only for a box holding a `fad`

Commit date: 2026-09-21

Source commit: this commit

Found by faust-diff-demo, the X-ray demonstrator of faust-diff-ts808's
learner: a TS-808 clipping stage identified while it runs, two descents
in parallel, a leader and a scout. The program cost 207 ms per second of
audio at 48 kHz where two independent descents cost 122 and one 55, and
the prepared signal DAG held 28 clocked blocks where the program has 12:
the solver's two nested `ondemand` blocks, the step block of every
descent, the twin of every block a `fad` augments. Reduced to four lines:

```
t = (clk, x) : ondemand(exp);
process = t + ((\(r).(t + 0.5 * r)) ~ _);
```

two blocks for one definition, `exp` twice in the C++. The result memo
(`propagate/result_memo.rs`) keys a call on `(box, slot environment, UI
path, mode, inputs)`, as C++ `propagate` does; a `~` whose left side is an
unapplied function is a `boxSymbolic`, its body is propagated with the
slot bound, and the closed definition `t` reached there had a key its
first propagation did not. For a plain signal the second propagation
rebuilds the same hash-consed tree; a clocked wrapper allocates a domain
per miss (`make_clock_env`), so the two propagations are two blocks that
both run, and the twin a `fad` makes of each doubles again. Every
`optimizers.lib` descent has this shape (`loop ~ (_, ...)`, `loop`
unapplied), so a loss reading a clocked model or a clocked target, and
the program reading the same outside the descent, paid one block per
reading. Three parts:

1. `flat::free_slots` computes, per flat box and memoised, the sorted
   list of its free slots: the `Slot` nodes below it that no `Symbolic`
   below it binds. `SlotEnv::restricted_id(slots)` interns the chain of
   their current bindings from the empty environment, in that order: a
   canonical id that two environments share when they bind those slots
   to the same signals, whatever else they bind. `propagate` keys the
   memo on it, the empty id for a closed box. A first version answered
   "mentions a slot" and kept every `Symbolic` on the full key; that
   left `ondemand(\(u).(exp(u) - 1.0))`, whose binder binds the only slot
   it mentions, and every `f ~ g` body, on the old behaviour. A program
   written as `process(xin, tin) = ...` mentions its two inputs' slots
   everywhere, so "closed" alone would have changed nothing for it: the
   restriction is what makes the key reusable under the lifted
   environment of a nested `~`, where `Input(0)` lifted is `Input(0)`.
2. `suppress_fad`, the flag of `RecFadMode::ExpandAfterRec`, changes the
   propagation of a `ForwardAD` box alone; it leaves the key of a box
   that contains none (`contains_forward_ad`). The target a loss reads
   inside a recursion, propagated under the flag, and the same target
   read outside were two propagations.
3. A `Rec` that contains a `fad` is memoised from its first call, like
   the identity-allocating nodes: its expansion after the group runs the
   forward-AD transform, whose twins are domains allocated outside the
   blocks' own memo entries, so a second propagation of the recursion
   during the warm-up expanded it again. That second propagation came
   from the output model of the X-ray, a clocked block written as
   `f ~ g` (the skip test of `ts808.lib`'s `stage_repeat_live`) whose
   body inlines the descent's box: a second twin of the model and a
   second step block for one learner.

What remains, recorded in the pair: 15 blocks for 12. The leader's

## A seed computed from another seed passes nothing: the semantics is kept, analysed against the alternatives and the other frameworks, and written into both notes

Commit date: 2026-09-21

Source commit: this commit

`process(x, y) = fad(x + y, (x + y, x, y))` gives `1, 0, 0`, and the
reporter expected `1, 1, 1`. `rad` gives the same, and the order of the
seeds changes nothing. Both modes treat a seed as detached: the forward
transform returns at a seed without visiting its operands
(`forward_ad.rs`, `transform_uncached`), the symbolic reverse collection
stops at a seed and the accumulation skips it (`reverse_ad.rs`,
`collect_dfs`, `run`), and the block sweep keeps the same stop set
(`block_reverse_ad.rs`).

`porting/fad-rad-seed-semantics-analysis-2026-09-21-en.md` sets three
candidate semantics side by side: A, the seed as an independent variable
(today); B, its own lane cut and the other lanes passing; C, the injected
perturbation, PyTorch's reading of an intermediate tensor. On the reporter's
program B and C give `1, 1, 1`. On `fad(loss, prev)` inside a `~` body, C
turns the state's tangent into an accumulation through its own history and
the descent no longer computes a gradient. On the library's
`descend_2D_clocked`, B and C both let `dp1/dp2` pass through the optimizer's
recursion, so a lane becomes a derivative along the trajectory instead of
`∂loss/∂p2` with `p1` fixed, and the recursion is augmented with `N` lanes.
In reverse mode B is not even local: one adjoint per node cannot be cut for
one lane and kept for another. The conversation's first answer, that
`1, 1, 1` was the more reasonable semantics, was reached on the reporter's
program alone and is reversed by these two.

The frameworks: PyTorch and TensorFlow give `1, 1, 1` (C) on graphs where
parameters are already detached by `no_grad` and every time step is a
distinct tensor; JAX, Zygote, Enzyme and ForwardDiff differentiate with
respect to arguments only, the program cannot be written, and its
transcription gives `1, 0, 0` (A). faust-rs's seeds have PyTorch's surface
and JAX's semantics. None was run; the statements are their documented
contracts.

A scan of the 212 `fad`/`rad` calls of the corpus, the impulse RAD lane and
the libraries found no seed computed from another seed: a change would
alter no test by the first shape and every multi-parameter descent by the
second.

Recommendation: keep A. Then a diagnostic refusing a seed whose computation
contains a different seed (`FRS-PROP-0005`, both modes, duplicated seeds
legal, the walk stopping at projections so the descents pass), a
stop-gradient primitive, and only later and as an option an injection mode
on feed-forward bodies. `docs/fad-note-en.md` §1 and §8 and
`docs/rad-note-en.md` §2.3 and §3.1 now state the rule, its two
consequences, the two correct spellings of the reporter's program, and the
diagnostic marked as planned and not implemented: until it lands the program
compiles and returns the zeros. The rule in plain words, "a signal you list
as a seed becomes an unknown of its own, and the compiler forgets how it was
computed", opens those paragraphs and closes §2 of both tutorials
(`libraries/optimizers-ddsp-tutorial-{en,fr}.md`, prose only, no new
program, so the tutorial tests read the same 35 blocks), with the
glossary's "Seed" entry saying it in one line.

## FRS-PROP-0005: a seed of `fad` or `rad` computed from another seed of the same call is refused, with the two spellings that mean something

Commit date: 2026-09-21

Source commit: this commit

The diagnostic the previous entry planned. `crates/propagate/src/dependent_seeds.rs`
walks each seed's computation, structurally, in the seed's own scope and at
the current sample: it does not enter a `DEBRUIJNREC` body, cross a
`DEBRUIJNREF`, a delay (`Delay1`, `Delay`, `Prefix`) or a clock-domain
wrapper, records a seed it meets without entering it, and reports the first
seed, in lane order, whose computation holds a *different* seed, with every
seed it depends on. `(s, s)` stays legal; the parameters of
`optimizers.lib`'s descents, each a clamp of a projection of the loop, are
not reported, nor is a seed that is the output of a recursion reading
another seed, nor `y'` seeded next to `y`: `ddsp_fad_diode_clipper_newton.dsp`
seeds `(k, v', v)`, the two variables of its implicit equation, and the
first version of the walk, which crossed delays, refused it ("fad seed 2
`proj0(~)'` is computed from seed 3 `proj0(~)`") in the workspace run. A
delayed copy of a seed is another variable of the current sample. The check runs in
`engine.rs` on both the `ForwardAD` and the `ReverseAD` arm, after the seed
list is lowered and before the transform.

`PropagateError::AdDependentSeed(Box<DependentSeed>)`: mode, 1-based lane,
a short rendering of the seed, and the lanes and renderings of the seeds it
is computed from. Boxed, because the plain variant grew the error past
clippy's `result_large_err` on every `Result` of the compiler crate. The
renderer is Faust-like and shallow (`input 0 + input 1`, `hslider #3 * 2`,
`sin(…)`): inputs are numbered because the names of `process`'s arguments
are gone after lowering, controls are named by their identifier because the
UI program is built after propagation. The diagnostic carries two notes
(the cause; which lanes would be 0 and that the tangent, or adjoint for
`rad`, does not pass through a seed), two `help` lines (the seed list
without the dependent seed; the dependent seed alone) and four facts
(`node`, `mode`, `seed`, `depends_on`). On `err_fad_dependent_seed.dsp`:

```text
error [FRS-PROP-0005] fad seed 1 `input 0 + input 1` is computed from seeds 2 `input 0` and 3 `input 1`
  = note: cause: a seed is differentiated as an independent variable; what computes it is a constant for every lane
  = note: lanes 2 and 3 would be 0 wherever the body reads `input 0 + input 1`, since the tangent of `input 0` and `input 1` does not pass through a seed
  = help: to differentiate with respect to `input 0` and `input 1`, drop `input 0 + input 1` from the seed list: fad(…, (input 0, input 1))
  = help: to differentiate with respect to `input 0 + input 1` as one quantity, seed it alone: fad(…, input 0 + input 1)
```

Tests: three unit tests in the module (reported with both lanes and the
`rad` message; independent, duplicated and single seeds pass; a seed read
through a recursion is not reported), four in
`crates/compiler/tests/diagnostic_errors.rs` on the two fixtures
`err_fad_dependent_seed.dsp` and `err_rad_dependent_seed.dsp` (code, message,
notes, the two helps, the facts) and on two programs that must stay legal
(a one-pole's output seeded with its coefficient; `(x, x)`), with their
golden snapshots. The code is in `codes.rs`, both code tables
(`faust-error-model-en.md`, `diagnostics-codes-reference-en.md`), and the
frozen table of `cli/tests.rs`, which the first workspace run caught.
`fad-note-en.md`, `rad-note-en.md` and the porting analysis now say the
diagnostic exists, and the notes show the text as rendered, not as planned.

What the walk does not see: a seed computed from another seed *through* a
recursion or a delay, since it does not enter one. That program compiles
and its lane is 0 through the seed, as the semantics says; the notes say
so.

Gates: `cargo fmt`, `clippy -D warnings` (after boxing the payload), `cargo
test --workspace --all-targets` (136 binaries, 2982 passed, 0 failed, 4
ignored; the first run caught the frozen code table of `cli/tests.rs`, the
