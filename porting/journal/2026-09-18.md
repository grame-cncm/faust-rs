# 2026-09-18

## CI: the three goldens the division-by-zero fixtures never had

Commit date: 2026-09-18

Source commit: this commit

The first CI run since 2026-09-16 (`993da3f1`, run 35278054172) failed on the
three platforms at the same step, `Golden output check`:

```text
xtask error: missing golden file .../tests/golden/rust/err_18_eval_division_by_zero/compiler_stdout.txt
```

`c56d54a3` ("A constant division by zero is a diagnostic, not a panic") added
three corpus fixtures, `err_18_eval_division_by_zero`,
`err_19_eval_division_by_zero_argument` and `err_20_eval_zero_over_zero`,
without their snapshots. Every `.dsp` of `tests/corpus` that
`is_rust_golden_eligible` accepts owes one, and `golden-check` stops at the
first that is missing, so the CI checked nothing after `err_17`. A Rust golden
is a fingerprint of the fixture's own text (name, bytes, lines, FNV-1a 64), so
nothing had to be decided: `cargo run -p xtask -- golden-gen-rust` wrote the
three files and left the 202 others byte for byte as they were (`git status`
showed three untracked directories and no modification). `golden-check` then
passes, 205 cases; with `bytes=1` written by hand in one of the new files it
fails on that case and names the line.

This was my omission, and not the only one the run hid. The step after the
golden check, `Structure check (Ubuntu)`, was skipped because of the failure;
it runs `code-graphs --check`, which would have failed too: the day's commits
added 112 public items to `cranelift-ffi`, `compiler` and `ffi-common`
(`EvalProgram`, `BlockTimer`, `Grid`, `PolyProbe::render`,
`CompilerError::diagnostics_report_json`, ...) and none refreshed
`docs/code-graphs/public-api-baseline.txt`. `1e88ef91` refreshed it. The gates
I ran before each commit were the crate's tests, clippy, fmt,
`ffi-boundary-check` and `libfaust-export-check`; `golden-check` and
`code-graphs --check` were not among them. Formatting, Clippy and the whole
`Test` step had passed on the three platforms.

On `1e88ef91` plus this commit, the six commands of the two steps pass
locally: `golden-check`, `cli-parser-check`, `error-model-check`,
`ffi-boundary-check`, `structure-check`, `code-graphs --check`.

Not addressed here: the `Security audit` workflow failed on the same push for
an unrelated reason, RUSTSEC-2026-0285 on `rustls 0.23.43` (published
2026-09-14, patched in 0.23.45), which `compiler` pulls through `ureq`.
