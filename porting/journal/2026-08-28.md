Commit date: 2026-08-28

Source commit: this commit

Final gate of the table-clamp plan, closing the loop on the observation
that started it: `--dump-sig-dag` showed a raw `SIGRDTBL` while the
generated C++ carried a clamp. The new `--dump-sig-dag-prepared` flag
runs the same staging pipeline FIR lowering consumes
(`prepare_signals_for_fir_verified_with_options`, honouring `-ct`) and
renders the prepared forest with the existing DAG dumper. On the
motivating program it now prints
`SIGRDTBL(tbl, SIGMAX(int(0), SIGMIN(SIGINTCAST(slider), int(15))))`
under the default `-ct 1`, and the raw access under `-ct 0`.
`--dump-sig-dag` keeps its meaning (the propagated, pre-normal-form

prepared variant.

lane restriction). A new test in `check_table.rs` locks the contract at
the library level: the prepared dump contains `SIGMAX`/`SIGMIN` under
`-ct 1` and neither under `-ct 0`. The plan document is marked Executed.

## G3: -ct end-to-end — CLI flag, options banner, --warn surface

Commit date: 2026-08-28

Source commit: this commit

Third gate of the table-clamp plan: the `-ct` option is now user-visible.
`-ct <0|1>` / `--check-table <0|1>` parses like the C++ compiler's flag
(default 1, out-of-range values rejected by clap's range parser, the
single-dash spelling normalized like `-mcd`), threads through
`compiler_from_cli` → `Compiler::with_check_table`, and echoes in the
generated "Compilation options" banner when non-default (`-ct 0`),
following the repo's print-only-non-defaults banner convention.

The `TableRangeWarning`s from G2 reach the user under `--warn`: a new
`Compiler::table_range_warning_messages` runs the staging pipeline on the
compiled signal forest and formats each clamped access as
`WARNING : RDTbl read index [lo:hi] is outside of table size (N)` — the
message C++ prints under `-wall` from `SignalTablePromotion` (minus the
trailing signal dump). They print as plain stderr lines from
`report_semantic_warnings`, bypassing the diagnostic bundle deliberately:
the pass has no source span yet.

Verified against faust 2.87.10 on the motivating program: `-ct 0`
generates the raw `ftbl0mydspSIG0[(int)((float)fHslider0)]` access
exactly like the reference's `-ct 0`, and the default generates the
reference-shaped full clamp. New `crates/compiler/tests/check_table.rs`
locks the contract (clamped by default, raw under `-ct 0`, provably
in-bounds accesses never clamped in either mode, rwtable write+read both
clamped, warning messages, no warnings under `-ct 0`), plus CLI
normalization/parsing tests. Full compiler suite green modulo the
pre-existing `expand_corpus` drift.

## G2: table clamping moves into the staging pipeline, FIR re-clamps retired

Commit date: 2026-08-28

Source commit: this commit

Second gate of the table-clamp plan. The `normalize::table_promote` pass
now runs as staging steps 2.10a/2.10b in `signal_prepare` — a fresh retype
followed by `Staging::promote_tables`, right after simplify #2 so table
sizes are integer constants (the C++ `signalTablePromote` ordering) —
gated by a new `PrepareOptions { check_table }` (default on) threaded from
a new `SignalFirOptions::check_table` through `Compiler::with_check_table`
→ `SignalLoweringContext` → `PrepareOptions`, including the generator
sub-module compiler (`GeneratorSubModuleSpec::check_table`), so a
generator's own inner table reads keep the same contract as the main
program. `PreparedSignals`/`SignalFirOutput` now carry the pass's
`TableRangeWarning`s for the future `--warn` surface, and
`SignalPrepareError::TableAccess` reports the C++ `faustexception` cases
verbatim.

Both FIR-level re-clamps are retired: the scalar
`table_index_with_bounds` + `normalized_table_index` pair
(`module/tables.rs`) and the vector twin (`vector/lower/signal.rs`),
including the modular wrap the vector write path used. Reads and writes
now lower to direct accesses; a `check_table`-gated
`debug_assert_index_checked` in both lowerers turns an index arriving
unclamped under `-ct 1` into a loud staging-order bug instead of a silent
second clamp.

Two deliberate behavior changes, both **toward** the reference compiler:
the emitted clamp is the full `std::max<int>(0, std::min<int>(...))` pair
(was: interval-minimal `min` only), and unknown-interval indexes are
clamped rather than modular-wrapped — on `tests/lean/table_unclamped.dsp`
and an rwtable equivalent the generated C++ is now shape-identical to
faust 2.87.10 for both the read and the write index. Validation: full
workspace tests green (the only failure, `expand_corpus`'s
`basics_lib_version` drift, pre-dates this work — verified via stash),
`signal_prepare` typing test updated to the new clamped contract, and the
impulse harness (`make clean`, rebuild, then `make interp` and `make cpp`
— the 94-program C++-oracle corpus, the latter compiling every generated
C++ with the system compiler) passes 100% against the recorded C++
references on both lanes.

## G1: normalize::table_promote, the signal-level table clamp pass

Commit date: 2026-08-28

Source commit: this commit

First gate of the table-clamp plan
(`porting/table-clamp-signal-promotion-plan-2026-08-28-en.md`). New module
`crates/normalize/src/table_promote.rs` ports C++ `SignalTablePromotion`
(`transform/sigPromotion.cpp:577-640`): a memoized `sig_map`-shaped
traversal (same Rec-sentinel discipline as `simplify`) that rewrites every
`SIGRDTBL` read index and writable `SIGWRTBL` write index into
`max(0, min(index, size-1))` unless the index interval from the canonical
`SigId → SigType` map proves the access already in `[0, size-1]`. Full-pair
clamp always (C++ byte parity — reference C++ keeps `max(0, min(...))`
because its interval-driven min/max pruning is disabled), untyped or
infinite intervals treated as `[INT32_MIN, INT32_MAX]` (the C++ untyped
fallback), table sizes resolved from `SIGWRTBL`/`SIGWAVEFORM` producers.
Each rewrite records a `TableRangeWarning` for the semantic-warning channel
(the faust-rs home of C++'s `-wall` report). Non-positive and non-constant
sizes are hard errors via the new `NormalFormError::TableAccess` variant,
matching the C++ `faustexception`s.

Eleven unit tests cover identity on provable bounds, full clamp on upper
overflow / signed / untyped / infinite intervals, write-index clamping,
read-only tables, nested write+read rewrites, both error paths, and
hash-consed sharing (one rewrite, one warning for a shared access).
`cargo test -p normalize` (89+11 green), rustdoc build, and the xtask
structure-check gate all pass. Not wired into any pipeline yet — that is
G2's job.

## Plan: move table index clamping to the signal level, add -ct

Commit date: 2026-08-28

Source commit: this commit

Investigation started from `--dump-sig-dag` on
`faustlibraries/tests/lean/table_unclamped.dsp`
(`rdtable(16, 1.0, int(hslider(...)))`): the dump shows a raw
`SIGRDTBL(tbl, idx)` while the generated C++ contains
`std::min<int>(..., 15)`. The clamp is invented late, during signal→FIR
lowering (`table_index_with_bounds`, `signal_fir/module/tables.rs:549`,
plus its vector twin), so it is invisible to every signal-level consumer
and cannot be disabled. The C++ reference compiler instead rewrites the
signal itself: `signalTablePromote` in `simplifyToNormalForm`
(`normalform.cpp:115`), i.e. `SignalTablePromotion::safeSigRDTbl/WRTbl`
(`sigPromotion.cpp:577-640`), gated by `-ct` (default 1).

Comparing outputs on the motivating file surfaced three real divergences
beyond the layering: faust-rs emits a minimal interval-driven clamp
(`min` only when the index is provably non-negative) where reference
faust 2.87.10 emits the full `std::max<int>(0, std::min<int>(..., 15))`
pair (C++'s interval-based min/max pruning is disabled as buggy,
`maxprim.hh:95`); faust-rs falls back to modular wrapping when the index
interval is unknown where C++ clamps; and the `wrtbl` write index is
always wrapped with no interval refinement at all.

Wrote `porting/table-clamp-signal-promotion-plan-2026-08-28-en.md`. Core
design: port `SignalTablePromotion` as `normalize::table_promote`, run it
as a new staging step after simplify #2 in `signal_prepare` (fresh retype
before it, C++ ordering so table sizes are constants), thread a
`check_table` option from a new CLI `-ct <0|1>` /`--check-table` through
`Compiler` → `SignalLoweringContext` → `SignalFirOptions` → new
`PrepareOptions`, and retire the FIR-level strategy down to a
`debug_assert!`. Decisions recommended in the plan: full clamp (strict
C++ byte parity), clamp instead of wrap for unknown intervals (semantic
change for out-of-range indexes that aligns with reference Faust), and a
new `--dump-sig-dag-prepared` flag so the clamp is finally visible in a
signal dump. Four gates: G1 pass + unit tests, G2 staging wiring + golden
regeneration + impulse comparison, G3 `-ct` end-to-end, G4 dump + docs.
