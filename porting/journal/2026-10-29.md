## Cmajor: streams declared in channel order

Commit date: 2026-10-29

Source commit: this commit

`emit_streams` declared the streams in reverse (`output2`, `output1`,
`output0`, then `input2`, ...), the ordering of the `sortIO` call of the
pinned C++ reference (`8eebea429`). A Cmajor host numbers a processor's
channels in the order its endpoints are declared: rendered by `cmaj render`,
the five outputs of a patch came out in reverse order (channel 0 was
`output4`), and a stereo patch had its channels swapped. C++ Faust `master-dev` no longer calls `sortIO` and declares
`input0..` then `output0..`, which `emit_streams` now does.

This is the explicit baseline update of the endpoint order that section 2.1
of `porting/cmajor-backend-port-and-test-plan-2026-08-04-en.md` reserves; the
section now records it. Mapping status: `1:1` with `master-dev`, `adapted`
from the pinned reference. With `FAUST_CPP_BIN` set to a `master-dev` build,
`pinned_cpp_and_rust_observable_contracts_match` failed on the stream order
of `diff-io` before the change and passes on its five cases after; set to
the pinned 2.84.3 binary it would now report the stream order. New test:
`streams_are_declared_in_channel_order`; the `CMAJ_BIN` runtime test passes.
Checked with `cmaj render`: `process = 1, 2, 3;` gives 1, 2, 3.

## Cmajor: a slider's step is written only when its default is on its grid

Commit date: 2026-10-29

Source commit: this commit

A Cmajor host starts each input event at its `init` annotation rounded to
the nearest multiple of `step` (the grid anchored on 0, not on `min`), and
that value overrides the exact default that the generated
`instanceResetUserInterface` sets. A slider whose default is off its step
grid therefore started elsewhere than in every other backend:
`hslider("v", 9.313225746154785e-10, -1e5, 10, 0.001)` started at 0, and the
`Q` of 0.707 with a step of 0.01 of several faustlibraries filter tests at
0.71. Measured with `cmaj render` (Cmajor 1.0.3209), by editing the
annotations of a generated patch: without `step` the exact default arrives;
without `init` the host sends `min`.

`init_on_step_grid` in `crates/codegen/src/backends/cmajor/mod.rs` decides
whether the `step` annotation is written: `init` is on the grid within two
float epsilons, since both values come rounded to float (0.3 stays a
multiple of 0.1, 0.9999995 is not one of 0.001). Tests:
`step_is_written_only_for_a_default_on_its_grid` (unit, `codegen`) and
`step_is_left_out_when_the_default_is_off_its_grid` (`compiler`,
`cmajor_backend.rs`), which also runs the result through the Cmajor
frontend check.

Mapping status: `1:1` with `cmajorStep` of
`compiler/generator/cmajor/cmajor_instructions.hh`, added to C++ Faust
`master-dev` in `c0290c9fc` the same day. Relative to the pinned C++
reference of the Cmajor port (`8eebea429`, Faust 2.84.3), which writes the
step unconditionally, this is a deliberate baseline update: an off-grid
default is the only case where the two differ, and the pinned differential
(`pinned_cpp_and_rust_observable_contracts_match`) uses on-grid sliders
only. The step decisions of `faust-rs` and of the rebuilt C++ Faust are the
same on ten on- and off-grid cases, in `-single` and `-double`.

Known gap, not changed here: `emit_streams` declares the streams in reverse
order (`output2`, `output1`, `output0`, then the inputs), the ordering of
the pinned reference's `sortIO`. C++ Faust `master-dev` no longer calls
`sortIO` and declares `input0..` then `output0..`. A Cmajor host numbers
the channels in declaration order: rendered by `cmaj render`, the five
outputs of a `faust-rs` patch come out in reverse order (channel 0 is
`output4`), so a stereo patch has its channels swapped. Moving to the
current order is a baseline update of the endpoint order, which section 2.1
of `porting/cmajor-backend-port-and-test-plan-2026-08-04-en.md` reserves for
an explicit decision.
