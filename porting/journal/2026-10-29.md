## `vector_mode` tests no longer import the installed Faust libraries

Commit date: 2026-10-29

Source commit: this commit

`fused_serial_groups_survive_dead_pure_root_removal` failed locally on
`phaser_flanger.dsp` with `Fallback(PureLowering)`: the corpus file imports
`demos.lib`, which resolved to the installed `/usr/local/share/faust`. Those
libraries are newer than the ones CI pins (faustlibraries `ecf2fdc2`): since
`69071402` `pf.vibrato2_mono` calls `ma.expm1`, which `f014604c` writes with
`sinh`, a foreign function, so the vector pipeline lowers it as scalar. The
test passed against the pinned libraries; it depended on the installed ones,
which AGENTS.md section 3 forbids.

phaser_flanger stood for one case: a fused scalar transport whose load is
removed with the dead pure roots. Reinstating the presence rule that
`f04276d9` replaced, and reducing until it rejects, gives a stdlib-free
source: a feedback comb (the fused group) and an outer `attach` that discards
the value the inner one passes through. It replaces the corpus file in the
test and is also held to the scalar bit-exactness oracle, which phaser_flanger
was not; reinstating the presence rule fails the test.

The Karplus regression added this morning (`pm.ks(200, 0.5)`) imported
`stdfaust.lib` too. It is now the `physmodels.lib` `chain`/`terminations`
structure written inline, with a swap for `ro.crossnn(1)` and an integer
delay of 100 samples per direction for `de.fdelay4`: the same two-level
pass-through recursion slots. Before `77568133` its `-vec` output differs
from scalar from frame 102 on; it renders 1,024 frames. `vector_mode.rs`
imports no library any more.

## Cmajor: the step is written only when the host's snapping gives the default back exactly

Commit date: 2026-10-29

Source commit: this commit

The rule of the morning kept a slider's `step` when `init` was a multiple of it
within two float epsilons. The Cmajor host does not compare: it starts the input
at `std::round(init / step) * step`, every value read from the annotations as
`float` (`PatchParameterProperties::snapAndConstrainValue`,
`include/cmajor/helpers/cmaj_PatchHelpers.h`). An on-grid default can come out one
float away: `hslider("d", 0.2, 0.001, 1.45, 0.0001)` starts at `2000 * 0.0001f =
0.19999999`, and `floor(48000 * d)` gives 9599 instead of 9600. faustlibraries'
`greyhole_demo_test` rendered one sample of delay short under Cmajor for that
reason (level gap 2.1e-2 against the C++ build), found by its new
`make check-backend-outputs`.

`init_on_step_grid` now computes the host's snapping in `f32` and keeps the step
only when it gives `init` back exactly. Tests: `step_is_written_only_for_a_default_on_its_grid`
(`codegen`, now with `0.5 / 0.001`, `1000 / 0.1` kept and `0.2 / 0.0001` left out)
and `step_is_left_out_when_the_default_is_off_its_grid` (`compiler`, a `0.2 /
0.0001` slider); both fail on the former rule.

Mapping status: `1:1` with `cmajorStep` of
`compiler/generator/cmajor/cmajor_instructions.hh`, changed the same way in C++
Faust `master-dev`. Checked with `cmaj render` on the C++ side: eleven sliders,
on and off their grid, all start at their exact default in `-single` and
`-double`.

## `-vec`: a recursion slot aliasing another recursion was fed back two samples late

Commit date: 2026-10-29

Source commit: this commit

grame-cncm/faust-rs#24 (Bart Brouns): a smoother DSP whose `-vec` output had
jumps the scalar output did not have. It reduces to a recursion slot whose
body is a bare projection of another recursion group:

```
process = (f ~ _) with { f(prev, x) = (+(prev*0.1 + x) ~ *(0.5)); };
```

`-vec` computed `y[n] = x[n] + 0.5 y[n-1] + 0.1 y[n-2]` instead of
`x[n] + 0.6 y[n-1]`, for every vector size and loop variant, and certified
the result. The vector analysis gave `SIGPROJ(i, SYMREF) -> body_i` the kind
`Delayed{1}`, although the `~` feedback delay is already the explicit
`SIGDELAY1` above the back-reference; C++ `getSignalDependencies` makes that
edge immediate. X2b (`3ac62e8d`, 2026-07-19) had reconciled the state facts
with the extra delay instead of removing it: it gave the alias's body a
one-sample history and lowered the alias as `body@1`, which the explicit
`SIGDELAY1` then delayed again. Its regression, `pm.ks(200, 0.5)`, was
itself miscompiled from frame 395 on, past the 64 frames its test rendered.

Fix: the edge is `Immediate` (C++ parity); the X2b widening is removed from
the state-plan producer and checker, and its history read from the pure
lowerer. Four hand-built `transform` tests that wrote the feedback as a bare
`SIGPROJ(i, SYMREF)` now use the explicit `SIGDELAY1` that `propagate` and
`CsigSelfN` emit (a bare back-reference is now an instantaneous cycle).
Plan and results: `porting/vector-symref-projection-edge-fix-plan-2026-10-29-en.md`;
the X2b section of `vector-plan-contexts-divergence-plan-2026-07-18-en.md`
is marked superseded.

Tests: three stdlib-free alias reproducers in `vector_mode.rs` (nested,
independent, two-level chain), certified and bit-exact over 256 frames, all
strategies, both loop variants, `-vs` 32 and 24; the Karplus check renders
1,024 frames; two analysis tests pin the C++ edge rule. All fail on the base;
restoring `Delayed{1}` fails four of them.

Validated:

- issue DSP: six outputs bit-identical scalar vs `-vec` over 96,000 frames
  under five control settings, and native C++ scalar/`-vec` hashes equal;
- emission differential over the 632 `.dsp` of `tests/` and `examples/`:
  100 scalar emissions reordered by the `hgraph` schedule, all rendering
  bit-identically to the base; 60 `-vec` emissions changed, no change in
  vectorization, all bit-exact against scalar; seven of them were
  miscompiled by the base and certified (`ddsp_fad_string_self_tuning`,
  `ddsp_fad_waveguide_string_pitch`, the four `opt_*_string`,
  `rep_71_degenerate_unary_recursion`);
- C++ impulse oracle, caches deleted: `cpp`, `cpp-vec0`, `cpp-vec1`,
  `interp-vec0`, 93 comparisons each, all equal;
- compile cost (basket, best of 5, interleaved): new/base 0.984–1.022;
- `cargo fmt`, `clippy -D warnings`, workspace tests, the five structure
  gates, `vector-interp-opt-check`.

Not run to a verdict here: `vector-coverage-check` and the `vector_mode`
test `fused_serial_groups_survive_dead_pure_root_removal` import the
installed `/usr/local/share/faust`, whose `sinh` is a foreign function, and
fail on `phaser_flanger` with or without this change. `compile-budget-check`
is below its calibration floor on this machine.

## Cmajor: streams declared in channel order

Commit date: 2026-10-29

Source commit: this commit

`emit_streams` declared the streams in reverse (`output2`, `output1`,
`output0`, then `input2`, ...), the ordering of the `sortIO` call of the
pinned C++ reference (`8eebea429`). A Cmajor host numbers a processor's
channels in the order its endpoints are declared: rendered by `cmaj render`,
the five outputs of a patch came out in reverse order (channel 0 was
`output4`), and a stereo patch had its channels swapped. C++ Faust `master-dev` no longer calls `sortIO` and declares
`input0..` then `output0..`, which `emit_streams` now does.

This is the explicit baseline update of the endpoint order that section 2.1
of `porting/cmajor-backend-port-and-test-plan-2026-08-04-en.md` reserves; the
section now records it. Mapping status: `1:1` with `master-dev`, `adapted`
from the pinned reference. With `FAUST_CPP_BIN` set to a `master-dev` build,
`pinned_cpp_and_rust_observable_contracts_match` failed on the stream order
of `diff-io` before the change and passes on its five cases after; set to
the pinned 2.84.3 binary it would now report the stream order. New test:
`streams_are_declared_in_channel_order`; the `CMAJ_BIN` runtime test passes.
Checked with `cmaj render`: `process = 1, 2, 3;` gives 1, 2, 3.

## Cmajor: a slider's step is written only when its default is on its grid

Commit date: 2026-10-29

Source commit: this commit

A Cmajor host starts each input event at its `init` annotation rounded to
the nearest multiple of `step` (the grid anchored on 0, not on `min`), and
that value overrides the exact default that the generated
`instanceResetUserInterface` sets. A slider whose default is off its step
grid therefore started elsewhere than in every other backend:
`hslider("v", 9.313225746154785e-10, -1e5, 10, 0.001)` started at 0, and the
`Q` of 0.707 with a step of 0.01 of several faustlibraries filter tests at
0.71. Measured with `cmaj render` (Cmajor 1.0.3209), by editing the
annotations of a generated patch: without `step` the exact default arrives;
without `init` the host sends `min`.

`init_on_step_grid` in `crates/codegen/src/backends/cmajor/mod.rs` decides
whether the `step` annotation is written: `init` is on the grid within two
float epsilons, since both values come rounded to float (0.3 stays a
multiple of 0.1, 0.9999995 is not one of 0.001). Tests:
`step_is_written_only_for_a_default_on_its_grid` (unit, `codegen`) and
`step_is_left_out_when_the_default_is_off_its_grid` (`compiler`,
`cmajor_backend.rs`), which also runs the result through the Cmajor
frontend check.

Mapping status: `1:1` with `cmajorStep` of
`compiler/generator/cmajor/cmajor_instructions.hh`, added to C++ Faust
`master-dev` in `c0290c9fc` the same day. Relative to the pinned C++
reference of the Cmajor port (`8eebea429`, Faust 2.84.3), which writes the
step unconditionally, this is a deliberate baseline update: an off-grid
default is the only case where the two differ, and the pinned differential
(`pinned_cpp_and_rust_observable_contracts_match`) uses on-grid sliders
only. The step decisions of `faust-rs` and of the rebuilt C++ Faust are the
same on ten on- and off-grid cases, in `-single` and `-double`.

Known gap, not changed here: `emit_streams` declares the streams in reverse
order (`output2`, `output1`, `output0`, then the inputs), the ordering of
the pinned reference's `sortIO`. C++ Faust `master-dev` no longer calls
`sortIO` and declares `input0..` then `output0..`. A Cmajor host numbers
the channels in declaration order: rendered by `cmaj render`, the five
outputs of a `faust-rs` patch come out in reverse order (channel 0 is
`output4`), so a stereo patch has its channels swapped. Moving to the
current order is a baseline update of the endpoint order, which section 2.1
of `porting/cmajor-backend-port-and-test-plan-2026-08-04-en.md` reserves for
an explicit decision.
