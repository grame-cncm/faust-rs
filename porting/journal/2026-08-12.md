## Phase E3: expansion document assembly

Commit date: 2026-08-12
Source commit: this implementation commit

- Added `crates/compiler/src/expand.rs`: `Compiler::expand_source_to_dsp` and
  `expand_file_to_dsp` build the whole `-e` document — version line, normalized
  `compile_options`, `library_path<i>` declarations, the `declare` metadata
  header, then the serialized box program.
- Ported `reorganizeCompilationOptionsAux` including its two subtleties: a
  following argument counts as an option value only when it does not itself
  start with `-`, and options the normalizer does not know keep their original
  relative order at the end.
- Rewrote `Compiler::expand_dsp`, which had returned its input verbatim since
  the facade was created, on the real expansion. Its `compile_options`
  short-circuit is reproduced with the C++ quirk intact and documented: the
  test never matches a real expansion, because the document starts with
  `declare version`.
- Two parity defects surfaced only by diffing against the recorded corpus, both
  invisible to unit tests written from the sources:
  - the unshared printer uses different composition-operator spellings from the
    shared one (`,` and `~` unpadded, `compiler/boxes/ppbox.cpp:311-319` against
    `:592-600`), so an abstraction body printed `\(x1).(x1, x1 : +)` where C++
    prints `\(x1).(x1,x1 : +)`;
  - library-scoped metadata keys are recorded with canonical absolute paths in
    this port, so the header read `_usr_local_share_faust_maths_lib_name`
    instead of `maths_lib_name`. Reusing the JSON path's `metadata_source_path`
    relativization fixes it and keeps the two headers consistent.
- Added `FRS-COMP-0007` for expansion failures, with its entries in the
  diagnostics reference and the error-model document. The frozen-code gate
  caught the omission before the commit, which is what it is for.
- Result: **33 of 33 fixtures with a recorded oracle expand byte-identically to
  the C++ compiler**, modulo the three lines that cannot match by construction
  (version, option spelling, absolute library paths). The two extension
  fixtures expand as expected.
- Corrected a claim from the plan while verifying it. Expansion is *not*
  idempotent after one pass, and neither is the reference — checked against it
  on the same corpus. The second pass grows the header (an expansion declares
  its own `version` and `compile_options`, which the next pass reads as
  metadata) and can shrink the body (re-evaluating `(65536 : int)` folds it to
  `65536`). The property that actually holds, and that the test now asserts, is
  convergence: the third pass equals the second.
- Fixture `033_deep_seq` was reduced from 2000 to 200 stages: faust-rs rejects
  the deeper program with a 1024-frame evaluator depth budget where C++ accepts
  it. That is a pre-existing evaluator limit unrelated to expansion, and it is
  now visible in the corpus rather than hidden.

## Phase E2: split the pipeline at the evaluation boundary

Commit date: 2026-08-12
Source commit: this implementation commit

- Split `pipeline_to_signals` into `pipeline_to_boxes` and
  `pipeline_boxes_to_signals`, joined by the new `BoxCompileOutput`. The cut is
  where C++ `libcode.cpp:1378` branches for `-e`: after the process box is
  evaluated and its arity inferred, before any signal is propagated.
- Kept every evaluation-stage rule on the prefix side — evaluator source
  loading, top-level metadata aggregation, diagnostic enrichment, owner
  attribution, eval guidance — so a caller that stops at the box boundary
  reports evaluation failures exactly as a full compilation does, rather than
  growing a second, weaker error path.
- Carried the flattened box, the arity memo and the evaluator definition names
  as private fields so completing the pipeline repeats no work. `process_flat`
  is deliberately not the tree a serializer should print; `process_box` is, and
  the field documents that.
- `SignalCompileOutput` keeps its public shape, so no caller changed.
- Checked independently rather than by inspection: the 199-case golden
  snapshot suite and the full compiler test suite both pass unchanged. A
  mutation that drops the evaluator metadata snapshot in the new prefix is
  invisible to the golden corpus but fails two compiler tests
  (`compiler_compile_file_to_signals_aggregates_component_metadata` and
  `c_family_callbacks_replay_master_and_component_metadata_with_relative_keys`),
  which is the coverage that matters for the header the expansion path will
  build from this snapshot.

## Phase E1: Faust-syntax box printers

Commit date: 2026-08-12
Source commit: this implementation commit

- Added `crates/boxes/src/print.rs` with `box_pp` (unshared expansion),
  `box_pp_shared` (the `ID_`-sharing printer behind `-e`), and `format_real`.
  Both printers are built on the existing `match_box` vocabulary, so they cover
  every box shape the evaluator can produce rather than a diagnostics subset.
- Three deliberate deviations from `compiler/boxes/ppbox.cpp`, each documented
  at its site: the memo table, definition trace and identifier counter are
  session-local instead of living in `gGlobal`, so two expansions in one
  process cannot interleave their numbering; the traversal is an explicit
  worklist rather than `operator<<` recursion, because evaluated diagrams reach
  thousands of levels; and an unprintable node returns `BoxPrintError` instead
  of throwing from inside a stream operator.
- Refused rather than approximated the shapes with no source syntax:
  `with { ... }`, `letrec`, closures, and partially-applied pattern matchers
  carry payloads that live in an evaluator side-table or an environment tree.
  C++ prints `closure[...]`, `PM[...]` and a raw tree dump inside `with { }`,
  none of which re-parse. None of these can occur in a successfully evaluated
  `process`, so refusing costs nothing and keeps unparseable text out of the
  output.
- Ported `T(double)` faithfully, including the detail that decides the digits:
  C++ narrows to the target precision *before* formatting, so 2*pi prints as
  `6.2831855f` and not the `6.2831853f` that formatting the unnarrowed `f64`
  produces. Rust has no `%g`, so the exponent-versus-fixed rule, trailing-zero
  stripping, and two-digit signed exponent are reproduced explicitly.
- Fixed the upstream `downsampling` defect in passing: the Rust printer emits
  `downsampling(...)`, where `faust -e` throws.
- Added 11 tests. Beyond the literal tables captured from the C++ binary, the
  structural ones assert properties rather than expected text: definitions
  precede their first use, no identifier is defined twice or left unused,
  24 doubling levels produce 24 definitions rather than 16 million
  occurrences, a 50000-level chain does not exhaust the stack, and nothing
  inside a binder is hoisted.
- Verified the checks reject their failure modes: disabling the memo lookup
  fails the sharing and linearity tests, reversing the definition order fails
  the definition-before-use test, and letting binder bodies share fails the
  hoisting test.

## Phase E0: capture the C++ `-e` reference corpus

Commit date: 2026-08-12
Source commit: this implementation commit

- Added `tests/expand/` with 34 fixtures, one per construct family:
  composition operators, iterative constructions, every UI widget and group,
  tables and waveforms, foreign functions/constants/variables, `select2`/
  `select3`, delays, routes, pattern matching, `with{}`, shared sub-diagrams,
  library imports, `ondemand`/`upsampling`/`downsampling`, `fad`, and a
  2000-stage `seq` for the traversal-depth case.
- Added the `xtask expand-oracle` workflow, which captures each fixture's
  `faust -e` output into `tests/expand/oracle/` and verifies it with `--check`.
  Every capture is fed back through the reference compiler, so a fixture whose
  expansion does not re-compile fails at capture time with the compiler's own
  error instead of surfacing later as an apparent port defect.
- Normalized three host-dependent lines to placeholders (`declare version`,
  `declare compile_options`, `declare library_path<i>`), keeping their presence
  and position asserted while eliding values that would tie the corpus to the
  capturing machine.
- Established the printing rules by observation rather than from the sources
  alone. The parenthesization of a memoized definition is fixed by the operator
  priority at its *first* visit (`streambinopShared`), which is why the same
  `*(0.99)` prints as `ID_1 = (ID_0 : *)` under `~` but as `ID_1 = ID_0 : *` at
  the top level. Real literals are `%g`-shaped (`4.4e+02f`, `3.1415927f`),
  `ffunction` prints `gFloatSize` names separated by `|`, and `route`/
  `ffunction` use comma separators without a following space while `fconstant`
  and `fvariable` use `", "`.
- Found an upstream C++ bug while capturing: `boxppShared::print()` tests
  `isBoxUpsampling` twice (`compiler/boxes/ppbox.cpp:615-617`) and never
  reaches a `BoxDownsampling` branch, so `faust -e` on any program containing
  `downsampling(...)` fails with
  `boxppShared::print() : BoxDownsampling[...] is not a valid box`. The
  non-shared `boxpp` printer handles the node correctly at
  `compiler/boxes/ppbox.cpp:467`, so the defect is reachable only through `-e`.
  The fixture is kept and reported as skipped; faust-rs will print
  `downsampling(...)`.

## Analyze the `-e` export-DSP option and plan the `libfaust.h` FFI surface

Commit date: 2026-08-12
Source commit: this documentation commit

- Added `porting/export-dsp-e-option-and-libfaust-api-port-plan-2026-08-12-en.md`,
  covering both the `-e` / `--export-dsp` option and the backend-agnostic
  `libfaust.h` / `libfaust-c.h` header pair, since `expandDSP*` is the header's
  central entry point and is exactly the `-e` code path.
- Established the C++ reference contract from `master-dev-ocpp-od-fir-2-FIR19`
  at `8eebea429`: the option branches in `libcode.cpp:1378` after parse, eval
  and the `numOutputs == 0` rejection but before propagation, and
  `expandDSPInternalAux` emits `declare version`, the normalized
  `declare compile_options`, one `declare library_path<i>` per imported source
  except the DSP file itself, the whole metadata set through
  `printDeclareHeader`, then the `boxppShared` serialization.
- Captured ground truth by running the installed `faust 2.87.4` binary rather
  than reading the sources alone. Two measured facts became the acceptance
  criteria: the expanded file re-compiles, and its generated C++ is identical
  to compiling the original except for the metadata block (mangled keys, added
  `library_path*` and `version`, different `compile_options`).
- Documented the properties of `boxppShared` that a port must preserve: DAG
  sharing through the `ID_` memo table, definition-before-use ordering, and the
  deliberate fallback to the non-shared printer for `BoxAbstr` and
  `BoxSymbolic`, whose bound variables would become free if hoisted.
- Recorded two C++ quirks instead of silently correcting them: the
  `expandDSPFromString` `startWith("declare compile_options ")` short-circuit
  never fires on real `-e` output because `declare version` is printed first,
  contradicting the invariant stated at `libcode.cpp:1194`; and
  `faust -e prog.dsp` without `-o` opens an empty output path, producing no
  output and exiting 0.
- Surveyed the Rust boundary: `BoxMatch` already covers every box shape and is
  a ready substrate, but there is no `boxpp`/`boxppShared` port
  (`render_human_box_expr` is a lossy, depth-capped, non-sharing diagnostics
  renderer and must not be reused), no eval-only pipeline, no
  `reorganizeCompilationOptions`, no `%g`-shaped real formatter, a stub
  `Compiler::expand_dsp` returning its input, and a fake SHA-1 that is an
  FNV-1a value repeated four times to fill 64 hex characters.
- Chose the header strategy imposed by the ABI: C++ `std::string` signatures
  cannot be exported from Rust, so `libfaust.h` follows the existing
  `libfaust-box.h` pattern as a header-only inline wrapper over a new
  `libfaust-c.h`, each wrapper releasing its `const char*` through the
  `freeCMemory` already exported unconditionally by `interp-ffi`. Both headers
  live in a new `crates/libfaust-ffi/` rlib linked into `faust-ffi` and enter
  the `xtask libfaust-export-check` gate.
- Structured the work as phases E0-E7, each with a producer, an independent
  checker, and mutations that must break that checker. The central check
  re-parses and re-evaluates the emitted `ID_` program and asserts structural
  DAG equality with the input, which is what catches a dropped memo table
  (exponential tree re-expansion) and an incorrectly hoisted abstraction body.
- Stated the parity contract explicitly: byte parity with C++ output is not
  promised (version string, argv spelling, installation-dependent library
  paths, `ID_` numbering), while self-containedness, re-compilability,
  idempotence, and codegen equality after round-trip are.
