# 2026-10-01

## Soundfile channel wrap generated as `chan % fChannels`

Commit date: 2026-10-01

Source commit: this commit

Follow-up of grame-cncm/faust#1322, in step with the C++ `rework-soundfile`
branch (`49c6d9367` compiler, `5c1b9b257` architectures; plan
`PLAN_PR_1322_soundfile_channel_wrap-en.md` in that checkout, whose §8 asks
faust-rs to follow). A `soundfile(label, N)` read beyond the resource's real
channels now reads channel `chan % fChannels` in the generated code instead
of relying on the runtime duplicating channel pointers up to `MAX_CHAN` (64).

- FIR: new value node `LoadSoundfileChannels { var }` (`fSoundN->fChannels`,
  `Int32`), through encoding, builder, matcher, checker, inliner, dump and
  compute cost. `fir_match_children` stays exhaustive.
- Lowering: one rule, `leaf_emit::emit_soundfile_buffer`, shared by the
  scalar and vector lowerers. It builds `Rem(chan, LoadSoundfileChannels)`,
  except for constant channel 0, as C++ `wrapChannel` does.
- Backends: C/C++ `->fChannels`, Rust `self.fSoundN.fChannels`, Julia
  `dsp.fSoundN.fChannels`, WASM `i32.load` at offset 16 (after the four
  4-byte pointers, both precisions), Cranelift `i32` load at `4 * pointer
  size`, AssemblyScript host import `env._soundfileChannels(slot)`, Cmajor
  still refuses soundfiles. The interpreter adds `kLoadSoundFieldInt`
  selector 2, which pops no part; `Soundfile::read_sample` no longer wraps.
- Fixtures: the interpreter, Cranelift probe, `faust_minimal.h`, the mem0 C
  header, Rust, Julia, WASM and AssemblyScript impulse hosts provide the
  `fChannels` real channel buffers only, set `fChannels`, and give each
  channel its own phase, `sin(part + chan + 2*pi*i/4096)`, like the C++
  branch's `TestMemoryReader`. The `sound` reference must therefore be built
  from a C++ checkout carrying that fixture (impulse README, Requirements).
- Registry: DIFF-BEH-016 (ahead of the pinned `8eebea429`, which duplicates
  pointers up to 64 channels).

Tests: `crates/compiler/tests/soundfile_channel_wrap.rs` (interpreter, scalar
and `-vec -lv 0/1`, 1-, 2- and 3-channel soundfiles read as 70 outputs; C++
text wraps every channel but 0, scalar and vector), FIR checker/inliner unit
tests for the new node, WASM `i32.rem_s` + offset-16 assertion, updated
fixture unit tests, re-recorded `faustprobe` snapshot `corpus_sound`.

Validation: `cargo fmt --all`, workspace Clippy and tests, the five structure
checks (`code-graphs` regenerated: one new public item,
`FirBuilder::load_soundfile_channels`), and `golden-check` passed. Impulse
lanes on `sound` and on a stereo soundfile read as 5 outputs, against a
reference from the C++ `rework-soundfile` build (`1bbbd4315`, with
`CPP_TESTS`/`FAUST_ARCH` from that tree): `cpp`, `c`, `interp`, `cranelift`,
`wasm`, `assemblyscript`, `rust`, `julia`, all `-vec0`/`-vec1` variants,
`-ec`/`-os`/`-ec -os` (C, C++, Rust) and the three `-mem0` lanes passed; with
the wrap disabled in `emit_soundfile_buffer`, the `interp`, `cranelift`,
`wasm`, `assemblyscript`, `rust`, `julia` and `cpp-ec` lanes and both new
integration tests fail. The canonical `compile-budget-check` stops on this
machine (`karplus.dsp` calibrates at 3 ms, below the 4 ms floor); against a
temporary copy of the baseline with only the floor at 3 ms, it passed. The
local `cli-transcript-check` reports 56 differences, the AssemblyScript
prelude's new `_soundfileChannels` import among them; its snapshots date from
2026-08-14 and were not re-recorded.
