## faustprobe: color-coded compile failures

Commit date: 2026-10-30

Source commit: this commit

`faustprobe --color auto|always|never` colors the human text of a compile
failure, with the rules of `faust-rs`. That text reaches the binary as a string
through `getCCompleteCraneliftDSPFactoryError`, already rendered, so no argument
can carry the choice: `cranelift_ffi::factory::set_complete_error_color` sets it
for the calling thread, next to the thread-local `COMPLETE_ERROR` it concerns.
It is off by default and out of reach of C, so hosts keep plain text. A
thread-local is hidden state, but it is per thread as the record it qualifies
is, and a compile on another thread falls back to plain, which is safe.

The decision itself moved from the CLI to
`compiler::diagnostics_human::StderrColor`, shared by both binaries. The text
stays machine-readable where the probe reads it: `--eval` searches for
`path:line:` and `undefined symbol`, and the polyphonic fallback for
`[FRS-CGEN-CLIF-`, each inside one styled run, so that none is split by an
escape. `color_survives_the_rewriting_of_an_eval_error` compares both kinds of
`--eval` failure with their plain output. The notes `--eval` appends, the
summary line and every error other than a compile failure stay plain; under
`--error-format json` the probe does not ask for color at all.

Validation: `compile_error_probe`, `output_snapshots`, `eval_probe` and the
`complete_error` tests pass; on a pseudo-terminal, color by default and with
`--eval`, none under `TERM=dumb`, `NO_COLOR` or `--color never`, and no escape
in a successful render. `compile-budget-check` did not run: the change is
confined to the failure path.

## Diagnostics: carets stay under their code on long line numbers

Commit date: 2026-10-30

Source commit: this commit

The blank gutter of a snippet was a fixed `    |` while the numbered one grew
with the line number, so carets landed one column to the left on lines 10 to
99, two on lines 100 to 999, and so on: most errors of a real file. The gutter
is now as wide as the longest line number the diagnostic shows, the last line
of a multi-line span included, with numbers right-aligned, so that the rows of
different labels line up too. Output is unchanged when every shown line number
has one digit. The human rendering is presentation, so no compatibility entry
is needed; the faustprobe snapshot `eval_with_local.txt` shows the new form.

## CLI: color-coded human diagnostics

Commit date: 2026-10-30

Source commit: this commit

User feedback: the only thing missing from the error messages was color.
`--color auto|always|never` (default `auto`) now styles the human channel of
`faust-rs`: severity, code and primary carets in the severity's color, location
and message in bold, gutters and secondary labels in blue, and `note`, `help`,
`fix`, `trace` and the debug lines each with their own tag color.

`diagnostics_human::Palette` holds the styles and is empty when color is off,
so there is one code path and the escapes are the only difference:
`colored_diagnostics_are_the_plain_text_plus_escapes_only` strips a colored
render of a diagnostic using every section and compares it to the plain one.
`HumanRenderOptions::color` defaults to `false` and the renderer never probes a
terminal, so the FFI `rendered_diagnostics` text is unchanged. The CLI resolves
the choice in `print_human_bundle`, through `anstream`, which reads `NO_COLOR`,
`CLICOLOR`, `CLICOLOR_FORCE` and `TERM`, and translates ANSI on the Windows
consoles that need it. `anstream` and `anstyle` were already in the build
through `clap`, so no crate was added. `report_semantic_warnings` now shares
that writer instead of having its own copy of the render call.

Validation: plain stderr compared with a pre-change binary on the error
fixtures at all four verbosities, 145 of 148 identical, the other 3 differing
only by the debug/release recursion budget of `err_34`, a profile difference.
Checked on a pseudo-terminal: color by default, none under `TERM=dumb`,
`NO_COLOR` or `--color never`. `cargo fmt`, clippy, the five structure gates
and `xtask golden-check` pass, as do the `faust-rs` CLI unit tests selected by
`color` and all of `cli_diagnostics_channel`. The `cargo test --workspace` run
was stopped before it finished and `compile-budget-check` did not run; the
change is confined to the failure path of the CLI.

Spotted in passing and left alone, since fixing it changes the plain text: the
blank gutter is a fixed `    |`, so carets land one column to the left on lines
10 to 99, and further on longer line numbers.
