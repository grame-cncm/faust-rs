## Wrapping integer semantics: faust_wrap_* in generated C/C++, -fwrapv in the harness

Commit date: 2026-08-26

Source commit: this commit

`make cpp` failed on `dsp/table.dsp` with massive numeric divergence from
frame 0. The investigation cleared every recent suspect: the generated C++
for `table.dsp` was byte-identical from the 2026-08-14 state through the
whole legibility campaign to HEAD, the interpreter lane matches the
on-disk reference exactly, and the same generated file compiled at `-O0`
or with `-fwrapv` is also exact. Only the optimized no-wrapv build
diverged — and so does the *reference* C++ (emitted by the pinned C++
Faust) when rebuilt today: Apple clang 21 (new since the references were
last generated on 2026-08-14) now exploits the signed-overflow UB in the
noise LCG (`1103515245 * i + 12345` in `int`) when it sits in the
countable 65536-iteration table-fill loop. Rebuilding the references
without a fix would have broken them the same way.

Primary fix — make the semantics explicit in the generated code, as every
other backend already does (Rust `wrapping_*`, Julia `faust_wrap_int32`,
WASM/Cranelift/AssemblyScript by spec, the interpreter's `wrapping_*`
executor): the shared C-family emitter now renders every `Int32`
`Add`/`Sub`/`Mul` — index arithmetic included — as `faust_wrap_add` /
`faust_wrap_sub` / `faust_wrap_mul`, tiny `inline` helpers both preambles
define next to `faustmini`/`faustmaxi` (arithmetic on `uint32_t`, defined
modulo 2^32, converted back; the same technique the emitter already used
for `LRsh`). C uses `static inline FAUST_UNUSED`, C++ plain `inline`
(clang's `-Wunused-function` fires on unused `static inline` in C++ under
`-Werror`). Comparisons, bitwise operators, and division keep their plain
infix spelling. This deliberately diverges from the canonical C++ Faust's
emission until it adopts the same helpers; the harness-flag fix landed
there separately (`5fa4158e1` on its `master-dev`).

Secondary fix — `-fwrapv` on every optimized C/C++ compile in the harness
(`common.mk` CXXFLAGS with an explanatory comment, `Make.mem0` O2/O3
lanes, `Make.execopts`): still required for compiling the *reference*
side, whose generator has not adopted the helpers yet.

Also restored `tests/impulse-tests/dsp-mem0/` (3 files) and `dsp-rad/`
(28 files), deleted uncommitted in the working tree since before the
campaign: both corpora are tracked and load-bearing
(`mem0_cpp_differential`, the RAD lanes, `mem0-smoke`), and their
committed references were orphaned by the deletion.

Verification with the new emission (release binary rebuilt — the first
harness run after the emitter change had silently used the stale one):
clean `rm -rf ir build` then all 8 scalar backends 94/94 referenced DSPs
(`faust_wrap_mul(1103515245, iRec0)` visible in `build/cpp/table.cpp`,
`faust_wrap_sub(fIOTA, …)` in the echo delay index), `mem0-smoke` green
(`-Werror` exercising the helpers in C and C++), `rad-cpp`/`rad-interp`/
`rad-rust` 28/28, `cargo test` transform 404 / codegen 369 / compiler
638 all green, golden-check 199/199, structure-check green.
