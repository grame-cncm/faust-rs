# 2026-10-24

## Delay amounts: refuse the whole integer range and `hi >= INT_MAX`

Commit date: 2026-10-24

Source commit: this commit

A delay read at an offset that follows an oscillator through `int()`
(`wp @ (int(10 + 80 * lfo) - 1)`, from the faust-elements reverb) has an
amount typed `[INT_MIN - 1, INT_MAX - 1]`: `int()` of an unbounded value
saturates to the `i32` range. C++ refuses it for its negative lower bound;
`check_delay_interval` tolerates a negative lower bound and accepted it,
sizing the line to 2^31 samples (`float fRec1[2147483648]`, an 8 GiB class
that crashes a C++ host allocating it on the stack; `faustprobe` rendered it).

- `sigtype::check_delay_interval` now also refuses an upper bound of
  `INT_MAX` or more (the C++ condition `i.hi() < INT_MAX`, which the port had
  dropped) and an interval spanning the whole integer range
  (`hi - lo >= 2^32 - 1`). The tolerance of a negative lower bound is kept and
  now registered (`DIFF-BEH-026`).
- Tests: four `sigtype` unit tests; two end-to-end tests in
  `crates/compiler/tests/diagnostic_errors.rs`, the reduced case refused with
  `delay-interval` and the same delay clamped compiling without a 2^31 line.
  `prepare_signals_for_fir_keeps_sampling_frequency_in_delay_amounts_after_simplify`
  now bounds its sample rate as `ma.SR` does: `int()` of a bare
  `fSamplingFreq` spans the whole integer range, an amount C++ refuses too.
- Gates: `cargo fmt`, clippy, `cargo test --workspace --all-targets`,
  `golden-check`, the five structure checks and `compile-budget-check` pass
  (the budget check reports six stale baselines, all faster than recorded,
  unrelated to this change).
- Considered and not done: full C++ parity (`lo >= 0`). It refuses `rep_67`,
  which C++ compiles because it checks delays after normalization, where
  `x @ 100 @ (s - 100)` folds; faust-rs does not apply the delay normal form
  at the top-level rate. Porting it changes generated code for many delay
  programs and breaks `BlockReverseAD` on folded delays read on a recursion
  output; left for a separate change.
