## Analyze error and diagnostics ownership

Commit date: 2026-07-28

Source commit: `98496b4a`

Added
`porting/error-diagnostics-separation-analysis-and-porting-plan-2026-07-28-en.md`
in response to the review concern that the `errors` crate does not contain
idiomatic Rust errors.

The audit distinguishes phase-local operational errors from structured
diagnostic reports. `EvalError`, `PropagateError`, `SignalFirError`, backend
errors, and `CompilerError` already use typed `Result`/`Display`/`Error`
surfaces; `crates/errors` instead owns severity, stages, stable codes, labels,
notes, help, and bundles. The crate name is therefore misleading, while making
`Diagnostic` or `DiagnosticBundle` implement `std::error::Error` would be the
wrong correction.

The proposed E0-E5 migration freezes compatibility contracts, renames
`errors` to `diagnostics`, removes unused scaffold identity APIs, changes
phase-to-diagnostic conversion to borrow errors, restores
`CompilerError::source()` chains and typed signal-type failures, removes the
parser's duplicate severity/message-classification model, and adds narrow
architecture guardrails. The plan preserves `FRS-*` codes, human/JSON output,
CLI status, C ABI, and compiler behavior. It records the Rust package rename as
an `adapted` public API change and requires an external-consumer decision
before implementation.

This commit is documentation and planning only; it does not change runtime or
public API behavior.

Validation: `cargo fmt --all`;
`cargo clippy --workspace --all-targets -- -D warnings`;
`cargo test --workspace --all-targets`;
`cargo run -p xtask -- golden-check`; `git diff --check`.

## Plan consolidation of custom CLI parsers

Commit date: 2026-07-28

Source commit: `0054dcaf`

Added
`porting/cli-parser-consolidation-analysis-and-porting-plan-2026-07-28-en.md`
in response to the code-review concern about multiple custom CLI argument
parsers.

The analysis confirms that the production compiler already follows the desired
legacy-normalization-then-Clap model, while the main debt is concentrated in
the two impulse runners, the `xtask` dispatcher and its command-local parsers,
and several developer binaries/examples. It separately classifies FFI
`argc`/`argv`, already-received compiler options, data-format parsers, and the
dependency-free impulse architecture as non-process-CLI protocols that must
not be migrated blindly.

The C0-C4 plan covers semantic baselines, runner migration, a typed Clap
subcommand tree for `xtask`, secondary tools, and a CI policy check. It
preserves successful and legacy Faust invocations while proposing standard
Clap diagnostics and exit status for invalid command lines. The public mapping
is 1:1 for successful workflows, adapted for invalid CLI behavior, and
unchanged for the FFI argument protocol.

Documentation validation: reviewed all direct `std::env::args` consumers and
known `xtask` option loops; verified repository-relative paths and
`git diff --check`.
