# 2026-08-14

## Julia backend: real `metadata!`, real `getJSON`, `@inbounds` on `compute!`

Commit date: 2026-08-14

Source commit: this commit

Audited the two backends named by `DIFF-GAP-005` ("WASM and Julia are functional
on validated paths but do not claim the complete … maturity of the C++
implementations") against the pinned C++ reference `8eebea429`, and replaced the
blanket disclaimer with an enumerated inventory in
[`wasm-julia-maturity-diff-gap-005-analysis-and-plan-2026-08-14-en.md`](../wasm-julia-maturity-diff-gap-005-analysis-and-plan-2026-08-14-en.md)
(`G5-W1`…`G5-W6`, `G5-J1`…`G5-J7`). The WASM half of the inventory is
specification only: the emitter was deliberately left untouched in this change.

Three Julia items are closed.

- `G5-J1` — `metadata!` was emitted with an **empty body in every case**. Not
  only were the compiler-synthesized `compile_options` / `filename` / `name`
  entries missing: source `declare`s were dropped too. A Julia host calling
  `metadata!` got nothing. The C-family metadata transport
  (`metadata_name` / `metadata_filename` / `metadata_entries` plus
  `c_family::ordered_compilation_metadata`) is now shared with Julia, so the
  three backends declare the same keys, in the same C++ key order, from the same
  snapshot. Verified against C++ `-lang julia` on a source with
  `declare name/author/version`: same five declarations, same order.
- `G5-J2` — `getJSON` returned the literal `"{}"`. It now returns the real
  description, built by the facade through the existing
  `build_strict_json_description` and embedded as a flat Julia string literal
  (`JsonDescription::render_flat`, the Rust counterpart of C++
  `JSON(true)` + `flattenJSON`). Agrees with the C++ payload on `name`,
  `filename`, `inputs`, `outputs`, `size`, and the whole `ui` tree.
- `G5-J3` — `compute!` is emitted as `@inbounds function compute!`, as the
  reference does. Every table and buffer access in the audio loop was paying a
  bounds check.

Two defects found while implementing, neither of them in the audit:

- The embedded description took its `name` from the FIR module, which carries
  the **class** identity (`-cn`, default `mydsp`), not the DSP name. A DSP
  compiled without `declare name` advertised `"name": "mydsp"` next to
  `"filename": "simple.dsp"`, contradicting its own `metadata!` callback. This
  is the mirror image of the `-mem0` `memory_layout` zone-naming defect fixed on
  2026-08-13. The description now takes the resolved DSP name; a regression test
  pins `-cn` against it.
- `julia_string_literal` did not escape `$`. Julia interpolates it inside a
  double-quoted literal, so any label — or any embedded JSON — containing `$`
  produced source that does not compile. Deliberate deviation from C++
  `flattenJSON`, which leaves `$` alone.

`G5-J5` was filed by the audit as a correctness defect (`REAL(...)` assigned to a
`FAUSTFLOAT` field) and is **withdrawn**: Julia's `setproperty!` converts to the
declared field type, so the store is correct whatever the host defines
`FAUSTFLOAT` to be. Only the spelling differs. `G5-J4` (internal FIR `Label`
comments reaching the generated source) turned out not to be a Julia matter
either — the labels come from the shared lowering and the Rust backend prints
them too — so it moves to the cross-backend phase with the 200 stored Rust
golden files it would re-record.

Validation: `make -f Make.julia -j8` runs 94 comparisons against genuine C++
references and all 94 pass with the new emitter, so the generated Julia still
compiles and computes identically. Workspace tests, clippy, golden-check, the
four structure gates, and a re-recorded `cli-transcript-check` are green; the two
re-recorded transcripts contain only the three intended changes.

Pre-existing and unrelated: `compile-budget-check` fails on
`reverb_designer: vector` (≈955 units against a 953.982 ceiling) on this machine.
Confirmed by re-running the gate with these changes stashed — it fails
identically on the clean tree.
