# 2026-08-08

## Exact canonical propagation memo removes the Jiles-Atherton repeat factor

Commit date: 2026-08-08

Source commit: this commit

Box-to-Signal propagation now has a compilation-scoped exact result table
adapted from C++ `propagate()`. Its fixed key contains `FlatBoxId`, canonical
`SlotEnvId` and `UiPathId`, a clock/domain/AD mode tuple, and a compact input
bus. Zero-, one-, and two-signal buses live directly in the key; larger buses
are interned once and share immutable storage. Rustdoc records the upstream C++
sources, key equivalence, ownership, provenance argument, and side-effect
limitations.

Safety is explicit. A linear whole-root analysis disables result replay for any
graph containing forward/reverse AD or a clocked wrapper, and non-empty pending
FAD state is a per-call barrier. This preserves seed accumulation and fresh
clock-domain instance identity. The first exact miss records all descendant
signal origins; a hit replays the same canonical signals for the same Box nodes
and records only its own boundary. Tests cover small and large bus identity,
slot/UI key separation, warm-up behavior, stored-result replay, and AD/clock
exclusion.

Immediate caching fixed the primary cases but cost too much across small DSPs:
the 1,110-case corpus measured 79.17 seconds. The accepted adaptive policy does
no cache hash or bus allocation during the first 1,024 eligible entries, then
activates for proven-large traversals. The repeated corpus measures 71.25
seconds against the original 70.86-second faust-rs reference (+0.55%). All 1,110
symbols still compile in both compilers.

The retained smoothed stereo sentinel drops from about 1.23 to 0.215 seconds in
propagation and from 10,836,611 to 4,845 entries. After the 1,024-entry warm-up,
the 3,803-entry count exactly matches C++; 851 of 3,821 probes hit high-level
subtrees. Raw stereo drops from 0.889 to 0.165 seconds, eliminating about 85% of
the smoothing differential. Maximum resident set size is neutral/slightly
lower (21.51 to 21.15 MiB).

The requested production symbols improve from 1.030 to 0.081 seconds in
propagation for `ja_transformer_demo_test` (12.7x), and from 0.982 to 0.168
seconds for `ja_processor_stereo_ui_test` (5.8x). The retained sentinel and both
production cases generate byte-identical C++. With the repeat factor removed,
origin attribution is about 0.0005 seconds rather than 0.538 seconds, so no
provenance redesign is justified in this change. Workspace Clippy and the full
workspace test suite pass. The mandatory budget command reaches only the
pre-existing machine calibration refusal: `karplus.dsp` measures 4 ms, below
the configured 5 ms floor.

## Canonical slot and UI contexts establish the exact-memo key prefix

Commit date: 2026-08-08

Source commit: this commit

Propagation no longer represents symbolic slot bindings with a mutable hash
map. A compilation-scoped persistent chain interns every
`Bind(parent, slot, signal)` node and exposes a compact `SlotEnvId`; restoring a
lexical scope is one identity assignment, while lookup walks the measured-small
binding chain and preserves shadowing. `Rec` rebuilds its lifted chain in lexical
order and memoizes the resulting environment by `(SlotEnvId, threshold)`. The
normalized grouped-UI path is likewise owned by an interner-backed
`UiPathContext`, giving equal paths the same `UiPathId` while leaving navigation
and control hashing unchanged. Rustdoc records how both identities adapt the
canonical `Tree*` slot/path fields used by C++ `propagate()`.

Four structural unit tests cover equal-history interning, slot shadowing and
restoration, repeated chain construction, and UI path restoration. All 103
propagate unit/integration tests, workspace Clippy, and the complete workspace
test suite pass. The mandatory compile-budget command still refuses the
machine's pre-existing calibration debt (`karplus.dsp` measured 4 ms against
the 5 ms floor). The smoothed stereo sentinel's generated C++ is byte-identical
to the preceding compiler. Its release propagation remains neutral at about
1.23 seconds, while environment lift memoization reduces `liftn` calls from
473,425 to 2,257. This confirms that the representation is cheap enough to
retain, but also that lifting was not the dominant defect: the 10.8 million
propagation entries remain for the next exact result-memo stage.

## Rust propagation profiling assigns the defect to millions of repeated entries

Commit date: 2026-08-08

Source commit: this commit

The propagate crate now honors the same opt-in `FAUST_PROPAGATE_PROFILE`
environment variable as C++ Faust. The normal path reads the switch once and
keeps no clocks or counters when it is absent. Profiled runs report calls and
inclusive time by C++-comparable Box family, average input/output bus widths,
average slot bindings, `liftn` calls/hits, and provenance calls/time. Rustdoc in
the new profile module records the C++ source mapping and explains the extra
Rust dimensions.

The retained sentinel makes the architectural gap concrete. Smoothed stereo
performs 10,836,611 Rust propagation calls versus 3,803 in C++; raw stereo does
8,009,171 versus 2,939. The Rust profiler itself raises wall time, but the
operation counts are deterministic enough to locate the defect. Provenance
takes 0.538 of 1.980 profiled seconds for smoothed stereo and 0.412 of 1.424 for
raw stereo, about 27–29%. `liftn` is invoked 473,425 times by the smoothed case,
but 99.8% are existing memo hits; raw has only 2,150 calls. The one-second gap
is therefore driven first by millions of repeated propagation entries, with
provenance as a separable residue. It is not explained by expensive work inside
one `liftn` miss.

Targeted propagate tests and workspace Clippy pass. The full workspace test run
reached one unrelated parser search-path test failure; its immediate exact
rerun passed, identifying the failure as environmental rather than a propagation
regression. The mandatory compile-budget command still refuses this machine's
pre-existing 3 ms `karplus.dsp` calibration result against the 5 ms floor. With
profiling disabled, generated C++ remains byte-identical to the
pre-instrumentation compiler on the sentinel.

## A self-contained budget sentinel retains the smoothed-parameter propagation defect

Commit date: 2026-08-08

Source commit: this commit

P0 of the Jiles-Atherton propagation plan now has a repository-owned DSP that
does not import the locally installed Faust libraries. It defines the same
recursive one-pole control smoothing, a reduced nonlinear recursive core with
four cascaded substeps, and raw/smoothed mono/stereo top-level symbols. Three
reduced cores in series preserve the absolute cost difference of the production
cases without copying filters.lib: release propagation is 0.873 seconds for
`raw_stereo` and 1.284 seconds for `smooth_stereo`, a 0.410-second differential.

`process = smooth_stereo` is now a required normalized front-end case in
`compile-budget-check`, so the basket cannot silently lose the only retained
input with this propagation-heavy shape. A local budget run measured it at
509.333 calibration units; the checked-in baseline is 510.000. The machine's
existing calibration-floor debt remains: `karplus.dsp` takes 3 ms here, below
the configured 5 ms floor. The floor was lowered to 1 ms only for the diagnostic
measurement and restored before this commit. `cargo test -p xtask --all-targets`
passes; the ordinary budget correctly refuses the sub-floor calibration.

## Jiles-Atherton exposes the missing prerequisite for C++-style propagation memoization

Commit date: 2026-08-08

Source commit: this commit

`examples-compare --per-symbol` found two one-second faust-rs outliers in the
faustlibraries corpus: `ja_processor_stereo_ui_test` and
`ja_transformer_demo_test`. Stage timing assigns about 0.95 seconds of each to
Box-to-Signal propagation. Parameter-by-parameter differential probes reduce
the trigger to the smoothed saturation parameter: replacing a raw `Ms` slider
with the same slider followed by `si.smoo` raises stereo propagation from about
0.49 to 0.90 seconds in both independently written DSPs. The generated C++ grows
by only a few hundred bytes, so the extra work is an intermediate compiler cost,
not a materially larger final program.

Direct profiling of C++ Faust corrected the first optimization plan. C++
`propagate()` has an exact compilation-scoped result memo keyed by slot
environment, UI path, Box, and input signals. It is cheap because all of those
values are canonical hash-consed `Tree*` identities: even the complete slot
environment and path each compare as one pointer. On the two reference cases it
performs only about 2,400 calls, with 14–18% cache hits, and completes the
profiled propagation pass in 0.96–1.64 ms. Hits on `seq` nodes skip complete
subgraphs, so raw hit rate understates the avoided work. C++ also stores Box
arity and De Bruijn aperture on canonical nodes and does not run faust-rs's
per-boundary signal-origin forest attribution.

The earlier Rust whole-call memo experiment remains valid negative evidence: a
key built around a mutable `AHashMap` slot environment and owned `Vec<SigId>`
results made the reference case slower and retained 748,000 entries for 12%
hits. What it refutes is that representation, not exact result memoization. The
revised plan therefore requires persistent canonical `SlotEnvId` and `UiPathId`
values, a compact propagation-mode identity, and a non-allocating input/output
bus key before retesting the C++ strategy. Rust-only side effects—FAD state,
clock tables, UI/control identity, and diagnostic provenance—must be represented,
replayed, or make a call explicitly ineligible. DSP-level removal of smoothing
is outside scope; output and diagnostics must remain identical.

The analysis, measurements, rejected experiments, phased implementation plan,
performance targets, and semantic validation obligations are recorded in
`porting/ja-smoothed-parameter-propagation-analysis-and-optimization-plan-2026-08-08-en.md`.
