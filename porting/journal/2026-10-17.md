# 2026-10-17

## `ondemand`: a held block-rate value is stored in the prologue

Commit date: 2026-10-17

Source commit: this commit (parent `75bca56b`).

**Problem.** faust-coopiano's D4 (`on_change` without `sAndH`, `coopiano.lib`
0.2.4) made the light body 26–28 % of a core in wasm (node, pedal up) instead
of 18 %. Its guards hold purely block-rate values, 5,010 of them. Each was read
only by its hold store `fPerm<i> = v;` after the prologue, so it was declared
before the sample loop and live across it. The light body's wasm locals went
from 6,537 to 14,045. No corpus program has this shape.

**Change** (`clocked.rs`, `emit_lazy_prologue`). A hold store of a lazy value
moves into the prologue when nothing else in the guard reads or writes its
field. The field already holds the value at the block's later fires, so the
result is exact. The value becomes a prologue local. Plan, section 8.4;
DIFF-BEH-024 updated.

**Results on coopiano** (wasm, node, percent of a core):

| Module | 0.2.3 | 0.2.4 before | 0.2.4 after |
|---|---|---|---|
| voice | 5.1–5.2 | 5.1–5.3 | 5.1–5.2 |
| body, pedal up | 41.5–44.1 | 45.2–47.4 | 43.6–44.8 |
| light body, pedal up | 17.9–18.5 | 25.8–27.8 | 21.2–24.6 |

Locals: voice 2,709, below 0.2.3's 2,956. The light body keeps about 3 points
more than with 0.2.3. That comes from two call sites with a constant input
(`21.0 + g`, `0.0`): without `sAndH`, about 5,900 init-time constants land in
its struct. Keeping `sAndH` at those two sites gives 18.8–18.9 %.

**Validation.**
- Unit tests: expectations updated, a kept-value recursion case, and a numeric
  case with a clock firing every fourth sample. Three mutations are each
  caught.
- Gates green: 3,313 tests, the five structure gates, `golden-check`.
- Against `75bca56b`, unchanged code:
  - the C++ of all 632 corpus programs;
  - the `-vec -lv 0/1` C++ of the 133 impulse DSPs.
- The wasm outputs are bit-identical to those of main-dev before point 6.
- Compile-cost A/B: 0.93–1.03.

## wasm and W7: local bookkeeping linear in the number of locals

Commit date: 2026-10-17

Source commit: this commit (parent `aa7027e7`).

**Problem.** Two places in the wasm compile path scanned a list once per
local, so their cost grew with the square of the number of locals in a
function.
- `collect_compute_locals` (`crates/codegen/src/backends/wasm/mod.rs`)
  deduplicated each declaration by scanning the locals already collected.
- W7's slot assignment (`fir::schedule::coalesce::assign`) named each new slot
  by counting the existing slots of its type.

Found while implementing point 6: a prototype that left 38,616 locals in the
coopiano voice's `compute` compiled 40 % slower, and a profile put the time in
these two functions.

**Change.**
- The collector keeps a `HashSet` of known names beside the ordered list
  (`LocalSpecs`). The first declaration still fixes a local's position and
  type.
- Each W7 pool counts the slots it created. A pool holds one type, so the
  names are the same as before.
- The interp and Cranelift backends and W7's checker were checked and already
  use hash sets.
- W7's checker still clones its live-locals map at each `if`
  (`check_reuse::join`), as noted in the point-6 plan, section 7. That cost
  grows with the number of `if`s times the number of locals, and it is not
  changed here.

**Validation.**
- New unit tests: `compute_locals_are_collected_once_in_first_declaration_order`
  (wasm) and `slots_are_numbered_per_type` (W7). Two mutations were tried, a
  global slot counter and last-declaration-wins, and each test caught its
  mutation.
- Output byte-identical against `aa7027e7` over the 632 `.dsp` files of
  `tests/` and `examples/`: wasm `-double` (514, `.wasm` and `.json`), wasm
  single (515) and interp `.fbc` (514). The other programs fail identically
  with both binaries.
- Gates green: 3,313 tests, the five structure gates, `golden-check`.
- Compile time, wasm, at the same output:

| Program | Locals | Before | After |
|---|---|---|---|
| `_ <: par(i, 8000, max(sin(m * (i + 1))))` | 16,003 | 0.67 s | 0.39 s |
| same, 16,000 outputs | 32,003 | 1.90 s | 0.82 s |
| same, 32,000 outputs | 64,003 | 6.11 s | 1.79 s |
| coopiano voice without its workaround | 5,210 | 10.6 s | 10.4–10.6 s |

The C++ compile of the stress programs takes 0.28, 0.65 and 1.30 s, so the
wasm backend is now within 1.4 times of it. The compile-budget basket, compared
by hand because the gate refuses to run on this machine, gives ratios of
0.97–1.02 on C++, `--check` and wasm. One 2 ms case reads 0.90, which is noise.

## `ondemand`: block-rate work leaves the domain (point 6, option c)

Commit date: 2026-10-17

Source commit: this commit (parent `f4c9c717`).

Implements option c of
[`ondemand-block-rate-in-domain-analysis-and-plan-2026-10-17-en.md`](../ondemand-block-rate-in-domain-analysis-and-plan-2026-10-17-en.md)
(section 8), as decided by the user. D1: grouped per guard. D2:
`downsampling` keeps the hoisting. D3: so does `-ec`. D4: coopiano is
simplified later, separately. Registry: DIFF-BEH-024.

- **Change.** A `Block` value that only a boolean `ondemand` guard's payload
  needs is computed at the first fire of each block, in one prologue at the top
  of the guard: `if (iSlowODDone<n> == 0) { …; iSlowODDone<n> = 1; }`, instead
  of before the sample loop at every block. The outputs are bit-identical (a
  block-rate value is constant within a block).
- **Two refinements over the prototype**, both found on the coopiano voice:
  - values only the prologue reads are its locals; declared before the loop,
    they gave wasm `compute` 38,616 locals and made compilation 40 % slower;
  - a value also needed outside the guard stays hoisted
    (`placement::guard_exclusive_block_signals`), otherwise it is computed
    twice when the clock fires.
- **Tests.** `crates/compiler/tests/ondemand_lazy_block.rs`: eight tests and a
  FIR walker for the prologue contract; five mutations, each caught.
- **Validation.**
  - Gates green: 3,311 tests, the five structure gates, `golden-check`,
    `vector-coverage-check` (1,568 certified pairs) and
    `vector-interp-opt-check`.
  - Over the 632 `.dsp` of `tests/` and `examples/`: 15 programs change their
    C++, all `ondemand_*` impulse tests; wasm `-double`/`-single` gives 1,024
    bit-identical and 5 trapping identically.
  - The `ondemand_*` impulse tests pass on seven lanes.
- **coopiano voice without its `sAndH` workaround** (wasm, C4): 44,900 → 22,270
  instructions and 11,400–11,700 → 4,990–5,080 cycles per sample. The workaround
  version costs 20,150 and 4,880–4,910. Compilation 10.4–10.6 s → 10.6–10.7 s,
  bit-identical outputs.

## `ondemand` block-rate work: analysis and plan (point 6)

Commit date: 2026-10-17

Source commit: this commit (parent `8b6d7930`).

Point 6 of faust-coopiano's `faust-rs-issues/RAPPORT.md`. Analysis only,
recorded in
[`ondemand-block-rate-in-domain-analysis-and-plan-2026-10-17-en.md`](../ondemand-block-rate-in-domain-analysis-and-plan-2026-10-17-en.md).

- **Cause and parity.** A boolean `ondemand` whose payload reads only
  block-rate values computes it before the sample loop, at every block:
  `place_by_variability` hoists every `Block` signal whatever guard is open.
  The pinned C++ does the same, while `docs/ondemand-note-en.md` promises the
  body does not run. Without its `sAndH` workaround, the coopiano voice costs
  2.2 times as much in wasm.
- **Two throwaway prototypes**, bit-identical on the whole corpus and exact
  against the C++ references on the 16 programs they change (`cpp`, `c`,
  `wasm`, `cpp-vec0`, `cpp-vec1`):
  - option a (compute at each fire) costs up to 57 times more when the clock
    fires every sample;
  - option c (compute at the first fire of each block, one flag per guard) is
    never measurably slower. It brings the voice without the workaround to
    5,000 cycles per sample, against 4,850 with it.
- **Per-value flags do not scale.** They took 115 s to compile the voice and
  overflowed V8's local limit. The plan therefore groups the lazy values per
  guard.
- **Side finding.** W7's checker (`check_reuse::join`) is quadratic in the
  number of `if`s.
- **Decisions D1 to D4 wait for the user.**

## W7: locals reused in `compute` (Safari's AudioWorklet stack)

Commit date: 2026-10-17

Source commit: this commit (parent `f69129c1`).

**Problem.** faust-coopiano's web page was silent in Safari (macOS Tahoe):
`An error was thrown from AudioWorkletProcessor::process()`. Reproduced under
`jsc`, Safari's engine: `RangeError: Maximum call stack size exceeded` in the
wasm `compute` once the stack is 512 KB, the size of a secondary thread on
macOS. JavaScriptCore's baseline tier gives each wasm local a stack slot, and
the voice's `compute` declares 37,720 of them (one per FIR stack variable).
V8 is not affected.

**Change.** A third stage of `fir::schedule` (design note
`porting/fir-local-reuse-w7-design-2026-10-17-en.md`, done as a FIR pass by the
user's decision): stack scalars whose live intervals do not overlap share a
*slot* declared once at the top of `compute` (`fReuseN`, `fReusefN`,
`iReuseN`, `lReuseN`); declarations become stores to the slot. Intervals come
from a program-order numbering, extended over a loop for a variable declared
before it or carried around its back edge; linear scan per type. An
independent checker (`check_reuse.rs`) tracks which variable each slot holds
on every path (joins at branches, fixed point at loops) and accepts a read of
`x` through `s` only where `s` holds `x`; a rejection drops W7 and asserts in
debug builds.

**Results.** `compute` locals: voice 37,720 → 2,177, imaged body 22,326 →
4,410, light body 19,391 → 2,946. Under `jsc` the faust-coopiano processor
(8 voices, both bodies) runs in 256 KB of stack. JavaScriptCore: voice 97 →
80 ms per second of audio, light body 452 → 398. V8, Cranelift and the
interpreter: unchanged speed. Compile time: +3 % (imaged body, faustprobe).

**Validation.** 12 tests in `crates/fir/src/schedule/tests_reuse.rs` (5 of the
producer, 7 mutations each rejected for its own reason); `fir_schedule.rs`
(interpreter outputs bit-identical, verified, idempotent); debug corpus 516
programs, 385 changed, no rejection, all verified; impulse tests of interp,
Cranelift and wasm with every `.ir` byte-identical; faust-coopiano's wasm
modules and the bank sample-identical; faustprobe `--ref` at zero tolerance.
Registry: DIFF-BACK-009 extended.

## FIR scheduling of `compute` for the JIT backends (W2/W3)

Commit date: 2026-10-17

Source commit: this commit (parent `ccca27eb`).

**Problem.** V8 (TurboFan) keeps wasm loads in program order, and the FIR
emits every recursive read at the top of the sample loop and reloads what it
has just stored (`fRec0[1] = fRec0[0];` after `fRec0[0] = fTemp3;`). On
faust-coopiano's light body this left a load 23,000 statements before its use
and ran at 1.4x em++'s cycles (plan
`porting/wasm-compute-speed-analysis-and-plan-2026-10-16-en.md`, C2/C3).
Cranelift and the interpreter keep the same order.

**Change.** New FIR-to-FIR pass `fir::schedule` (design note
`porting/wasm-w2-w3-sinking-forwarding-design-2026-10-17-en.md`), on `compute`
only:

- W3 (`forward.rs`): after a store of a constant or a single-assigned local to
  a constant struct address, later loads of that address in the same
  straight-line region read the value;
- W2 (`sink.rs`): a pure declaration moves down to eight solid statements
  before its first reader or the first statement that may write what it
  reads; the slack keeps a load's latency off serial critical paths (with no
  slack the voice lost 25 %);
- an independent checker (`check.rs`, its own walker, purity rule and
  conflict test) must accept each stage; a rejection drops that stage for the
  function and asserts in debug builds.

The interp, Cranelift and wasm backends apply it (`keep_fir_order` option to
turn it off for differential tests); C, C++ and the other text backends keep
FIR order. Registry: DIFF-BACK-009.

**Results** (wasm cycles per sample, V8 `--no-liftoff`): 400-mode bank
2,510–2,610 → 2,060–2,200; voice 5,200–5,460 → 4,850–5,030; light body
27,000–27,400 → 16,800–18,300 (em++'s level); imaged body 46,500–52,700 →
42,300–43,800. Cranelift compute: bank 398 → 331 ms, imaged body 2.27 →
1.88 s. Compile time of the imaged body: +10 % (wasm), +12 % (faustprobe);
the pass takes 0.32 s of it. The interpreter was not timed.

**Validation.** 28 unit tests in `fir` (producers, checker, mutations it must
reject) and 2 consistency tests of the two alias implementations;
`crates/compiler/tests/fir_schedule.rs` (interpreter outputs bit-identical
with and without the pass, scheduled module verified, idempotence). Outside
the suite: all 516 compiling `.dsp` of `tests/` and `examples/` scheduled in
debug with no rejection and verified (97 change); impulse tests of interp,
Cranelift and wasm with every `.ir` byte-identical to the parent's;
faust-coopiano's wasm modules sample-identical; faustprobe `--ref` at zero
tolerance; C++ output unchanged.

## Clocked lowering: a block reached from a sibling payload sees only its parent region

Commit date: 2026-10-17

Source commit: this commit (parent `63cabd02`).

**Problem.** `faust-coopiano`'s hammer program (`dsp/coopiano_hammer.dsp`, the
voice with its hammer force as output) failed FIR verification once its
phantom bound moved into an `ondemand` domain:
`FRS-FIR-0001 use of undeclared variable 'fTemp19504'` on every backend
(point 16 of `faust-coopiano/faust-rs-issues/RAPPORT.md`). Reduced case:

```faust
s(x) = x * 0.5;
ga(x) = (button("a"), s(x)) : ondemand(\(v).(v + 1.0));
b(x) = (button("b"), s(x), ga(x)) : ondemand(\(v, g).(v * v * g));
core(u, x) = u * 0.5 + x, b(x) + u;
process = core ~ _ : _, !;
```

`b`'s payload reads `ga`'s hold field, so `ga`'s block is lowered while `b`'s
is open (`ensure_guarded_block` from inside `b`'s body), and emitted in the
sample loop, before `b`'s. `s` is first lowered inside `b` (payloads emit
their whole value in the block). `RegionCache::get_at` walked every scope
below the current one, so `ga`'s body found `b`'s `fTemp2` and read it
outside the block that declares it. Open blocks form a stack, but a block's
region is not always the one below it in that stack. This broke the
visibility rule of `region.rs` ("child values never escape into siblings").

**Change** (`crates/transform/src/signal_fir/module/`):

- `region.rs`: `RegionCache` keeps a parent link per scope. `get_at` follows
  the links; `open_child_under(parent)` replaces `open_child`.
- `clocked.rs`: `parent_block_depth(domain)` is the depth of the open block of
  the domain's parent (`0` for a top-level domain; the innermost block if the
  parent is not open). `ensure_guarded_block` builds the whole block (clock
  precondition, hold fields, body, guard, downsampling counter) with the
  append surface redirected there (`build_guarded_block`), and the body's
  cache scope hangs under it.

**Validation.**

- `clocked_emission_structure.rs::block_reached_from_a_sibling_payload_sees_only_its_parent_region`
  (the reduced case: fails on the parent commit with the FIR verifier,
  passes now) and the `region.rs` unit test
  `child_opened_under_an_outer_parent_skips_the_open_sibling`.
- Codegen identity: every `.dsp` of `tests/` and `examples/` compiled to C++
  by the parent commit and by this one. 595 compile, all byte-identical; the
  37 others fail identically with both.
- `faust-coopiano` without its workaround barrier: the hammer program
  compiles, and its output equals the barrier version's bit for bit (A0,
  velocity 1, 22050 samples).
- `cargo fmt`, `clippy -D warnings`, `cargo test --workspace --all-targets`,
  the five structure gates; `porting/MEMOIZATION.md` §2.12 updated (rescoped
  memo).
