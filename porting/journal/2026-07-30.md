## Extract diagnostics-v2 rendering into the compiler library

Commit date: 2026-07-30

Source commit: `22434645`

P1 moves the machine renderer out of the binary-only CLI module into the
public `compiler::diagnostics_json` library module. The new Rustdoc-documented
API carries explicit compiler metadata, request metadata, source-text policy,
and field selection. Its dedicated
`render_complete_diagnostics_v2_json` entry point always includes every
retained typed field, including debug evidence, so the later WASM FFI query
does not need a presentation parameter.

The CLI now delegates to the shared renderer. Its existing standard/debug JSON
contract is preserved, while FFI callers get a separate complete-report
entry point. Source text can be omitted, restricted to the primary memory
source, or included for all memory/virtual sources without changing source
ids, hashes, or diagnostic ranges.

Added direct library tests for complete debug retention, request metadata,
source-text independence, and the legacy standard view.

Validation: `cargo fmt --all`;
`cargo test -p compiler diagnostics_json --lib`;
`cargo test -p compiler --bin faust-rs cli::tests::diagnostics_json`;
`cargo clippy -p compiler --all-targets -- -D warnings`;
`cargo run -p xtask -- diagnostics-quality-check`.

## Freeze the WASM structured-diagnostics integration contract

Commit date: 2026-07-30

Source commit: `3355962f`

P0 is frozen for the WASM-only implementation. The result-owned record design
is approved, the raw symbol is fixed as
`faust_wasm_result_get_error_diagnostics(result_handle)`, and every FFI query
returns the complete diagnostics-v2 report without a diagnostic-level
parameter. The returned JSON uses an independently owned text-result handle;
the existing compatibility message and compile-result lifetime remain
unchanged.

The TypeScript contract is likewise fixed:
`FaustCompilerError.getErrorDiagnostics()` owns the authoritative report for
one failed request, while `FaustCompiler.getErrorDiagnostics()` is only a
last-error convenience. FFI reports omit source text by default but retain
source identities, hashes, and ranges. The `faustasm` name from the original
request is resolved to the `faustwasm` repository on branch `rust`.

Validation: inspected the current `wasm-ffi` result/text handle tests and the
`faustwasm` Rust adapter at baseline `74a5132`; no ABI or code change in this
phase.

## Document structured diagnostics integration plans for WASM and native FFI

Commit date: 2026-07-30

Source commit: `b5478ed4`

Added two proposed implementation plans based on the current structured
diagnostics baseline. The WASM-specific plan records where `wasm-ffi` reduces
`CompilerError` to text, and defines an additive result-handle query plus the
`faustwasm` `getErrorDiagnostics()` surface needed to preserve complete
machine-readable diagnostics without breaking existing error-message callers.

The companion FFI plan generalizes the contract across WASM, Interpreter, and
Cranelift backends. It requires a complete, parameter-free diagnostic report
before an FFI boundary stringifies an error, and proposes explicit build-result
handles because a failed native
factory construction otherwise returns no object on which an error query can
be made. Diagnostics retained by a successful factory, such as warnings,
remain distinct from the error that prevented construction.

Both documents are planning artifacts only. They set phased API, ABI,
compatibility, lifecycle, testing, and documentation gates; they do not change
compiler behaviour or expose a new FFI API yet.
