## Integrate complete diagnostics in faustwasm

Commit date: 2026-07-30

Source commit: `ec6033e4` (`faust-rs`) and `f2abc95` (`faustwasm`)

P4 adds public TypeScript definitions for the complete diagnostics-v2 schema
and a `FaustCompilerError` whose parameter-free `getErrorDiagnostics()` owns
the report for one rejected compilation. `FaustCompiler` exposes the same
method as a last-error convenience plus a separate `getDiagnostics()` for
warnings/remarks from the most recent successful compilation.

`RustLibFaust` feature-detects the optional raw exports, copies and parses the
diagnostic text result before freeing the compile result, and always frees the
text handle. Parsing validates the schema discriminator and required envelope
arrays, preserves unknown properties, and degrades to `null` without hiding
the original compatibility message. Old Rust modules and the historical C++
module therefore remain text-compatible. A host-side
`WebAssembly.compile(...)` rejection is rethrown unchanged when no Faust
compiler error exists.

Validation in `faustwasm`: `npm run build-types`; `npm run build`. Prettier
passes on the five touched TypeScript implementation/type files. The repository
wide lint remains red on pre-existing `no-explicit-any`/unused-value findings
and unrelated formatting drift; no unrelated lint cleanup was included.

## Export complete structured diagnostics from wasm-ffi

Commit date: 2026-07-30

Source commit: `0b2efa78`

P3 adds the frozen
`faust_wasm_result_get_error_diagnostics(result_handle)` ABI. It returns an
independently owned text-result handle containing the complete diagnostics-v2
report for a compiler failure. It returns an error text result for successful
compiles, transport-only failures, and unknown/freed handles; the existing
error pointer/length compatibility channel is unchanged.

The additive `faust_wasm_result_get_diagnostics(result_handle)` query exposes
warnings/remarks retained by successful compilations and returns a valid
`status: "success"` report even when the diagnostic list is empty. Neither
query accepts a verbosity parameter, and both omit source text while retaining
source metadata.

Rustdoc documents query semantics and ownership. Unit tests cover valid JSON,
stable repeated queries, transport/success/unknown-handle rejection,
compile-result/text-result free ordering, and opted-in success warnings. The
xtask ABI verifier and raw-ABI README include both exports, and the release
`wasm32-unknown-unknown` module was built and verified.

Validation: `cargo fmt --all`; `cargo test -p wasm-ffi`;
`cargo test -p xtask verify_wasm_ffi_exports`;
`cargo clippy -p wasm-ffi -p xtask --all-targets -- -D warnings`;
`cargo run -p xtask -- build-faustwasm-compiler-module`.

## Preserve typed failures through the WASM compile path

Commit date: 2026-07-30

Source commit: `28b2a432`

P2 replaces the text-only internal WASM failure with an owned
`FfiDiagnosticRecord`. Compiler failures copy their `DiagnosticBundle` and
request metadata before the ABI boundary can stringify them; malformed FFI
arguments retain only their compatibility message and cannot fabricate an
`FRS-*` diagnostic. Rustdoc records the ownership and provenance invariants in
the new non-exported module.

The artifact success shape now retains a warning bundle. `--warn` was added to
the shared FFI argument subset and configures
`Compiler::with_semantic_warnings`, so a successful WASM compile can preserve
non-blocking diagnostics without changing acceptance. Request metadata records
the WASM backend, compile mode, precision, memory model, and effective search
paths without embedding virtual-source contents.

Structural tests cover typed parser-failure retention, source snapshots,
transport-error separation, request metadata, and an opted-in `sqrt` domain
warning that remains a successful compile.

Validation: `cargo fmt --all`;
`cargo clippy -p ffi-common -p compiler -p wasm-ffi --all-targets -- -D warnings`;
`cargo test -p ffi-common`;
`cargo test -p compiler compiler_compile_wasm_artifact --lib`;
`cargo test -p wasm-ffi`.

## Extract diagnostics-v2 rendering into the compiler library

Commit date: 2026-07-30

Source commit: `22434645`

P1 moves the machine renderer out of the binary-only CLI module into the
public `compiler::diagnostics_json` library module. The new Rustdoc-documented
API carries explicit compiler metadata, request metadata, source-text policy,
and field selection. Its dedicated
`render_complete_diagnostics_v2_json` entry point always includes every
retained typed field, including debug evidence, so the later WASM FFI query
does not need a presentation parameter.

The CLI now delegates to the shared renderer. Its existing standard/debug JSON
contract is preserved, while FFI callers get a separate complete-report
entry point. Source text can be omitted, restricted to the primary memory
source, or included for all memory/virtual sources without changing source
ids, hashes, or diagnostic ranges.

Added direct library tests for complete debug retention, request metadata,
source-text independence, and the legacy standard view.

Validation: `cargo fmt --all`;
`cargo test -p compiler diagnostics_json --lib`;
`cargo test -p compiler --bin faust-rs cli::tests::diagnostics_json`;
`cargo clippy -p compiler --all-targets -- -D warnings`;
`cargo run -p xtask -- diagnostics-quality-check`.

## Freeze the WASM structured-diagnostics integration contract

Commit date: 2026-07-30

Source commit: `3355962f`

P0 is frozen for the WASM-only implementation. The result-owned record design
is approved, the raw symbol is fixed as
`faust_wasm_result_get_error_diagnostics(result_handle)`, and every FFI query
returns the complete diagnostics-v2 report without a diagnostic-level
parameter. The returned JSON uses an independently owned text-result handle;
the existing compatibility message and compile-result lifetime remain
unchanged.

The TypeScript contract is likewise fixed:
`FaustCompilerError.getErrorDiagnostics()` owns the authoritative report for
one failed request, while `FaustCompiler.getErrorDiagnostics()` is only a
last-error convenience. FFI reports omit source text by default but retain
source identities, hashes, and ranges. The `faustasm` name from the original
request is resolved to the `faustwasm` repository on branch `rust`.

Validation: inspected the current `wasm-ffi` result/text handle tests and the
`faustwasm` Rust adapter at baseline `74a5132`; no ABI or code change in this
phase.

## Document structured diagnostics integration plans for WASM and native FFI

Commit date: 2026-07-30

Source commit: `b5478ed4`

Added two proposed implementation plans based on the current structured
diagnostics baseline. The WASM-specific plan records where `wasm-ffi` reduces
`CompilerError` to text, and defines an additive result-handle query plus the
`faustwasm` `getErrorDiagnostics()` surface needed to preserve complete
machine-readable diagnostics without breaking existing error-message callers.

The companion FFI plan generalizes the contract across WASM, Interpreter, and
Cranelift backends. It requires a complete, parameter-free diagnostic report
before an FFI boundary stringifies an error, and proposes explicit build-result
handles because a failed native
factory construction otherwise returns no object on which an error query can
be made. Diagnostics retained by a successful factory, such as warnings,
remain distinct from the error that prevented construction.

Both documents are planning artifacts only. They set phased API, ABI,
compatibility, lifecycle, testing, and documentation gates; they do not change
compiler behaviour or expose a new FFI API yet.

Validation: Markdown structure and whitespace checks; staged-diff check.

## Compile-time regression audit of the diagnostics arc, and a gate that can see it

Commit date: 2026-07-30

Measured the compilation cost of the whole compiler-diagnostics-v2 arc
(`8a909843..41e4373d`) by building the pre-arc reference `98496b4a` and running
`--check` over 352 corpus DSPs. The arc costs **4.5x over the corpus** and up to
**17x on individual programs**; `dx7_alg5`, reported in `faust-rs#15`, is the
most visible case, not the only one. Eleven other DSPs regressed between 2x and
17x, and the overhead grows with program size rather than being a fixed cost.

`faust-rs#15` recovers roughly half: with its caps applied the corpus is still
1.74x slower, and every large program stays above 2x. Two further causes remain,
neither touched by that PR. The dominant one is `record_derived_forest`, called
at the end of every box propagation in `crates/propagate/src/engine.rs`: 68 % of
samples in a capped profile, allocating a fresh SipHash `HashSet` per call, and
largely wasted work — `propagate_typed` discards the table it builds, and `eval`
calls it for every constant fold. Disabling that one call takes the corpus from
1.74x to 1.19x. The remaining ~18 % in `evaluation` is diffuse; the reading
points at the unbounded, undeduplicated `BoxProvenance::by_node`, at
`import_box_provenance` deep-cloning a `Box<str>` location per origin per
import, and at the linear full-text scan in `SourceMapBuilder::add`. That third
group is identified but not yet isolated by measurement.

Full analysis, per-file numbers, profiles, and a four-step correction plan:
`porting/compile-time-provenance-regression-analysis-and-plan-2026-07-30-en.md`.

The gate that should have caught this existed and was blind. `reverb_designer`
went from 7.1 s to 18.3 s against a `scalar_max_ms` of 45 000 and never turned
CI red, because absolute wall-clock ceilings have to be loose enough for the
slowest runner. Rather than adding a parallel tool, `vector-compile-budget-check`
gains a second dimension (baseline schema 2): a front-end basket over
`tests/impulse-tests/dsp` entries that measures the `--check` path only and
expresses each cost as a ratio against a calibration DSP measured in the same
process. Machine speed cancels, so the tolerance is 25 % instead of an order of
magnitude. `karplus` is the calibration — it moved 0.997x across the arc, so it
divides without absorbing the effect being measured.

One design flaw surfaced during bring-up and was fixed: measuring the
calibration after the codegen basket in enforcing mode but before it in
`--update` mode moved it by 44 % and shifted every recorded ratio. The front-end
basket now runs first and identically in both modes, and the calibration takes
the minimum of eight runs rather than two. Observed run-to-run spread on the
recorded basket is then ±8 % worst case.

The recorded baseline is the *current, regressed* state — the honest starting
point, with each entry carrying its debt against the pre-arc reference in a
`note`. It ratchets downward as the plan's steps land. `dx7_alg5` is present but
disabled: it exceeds the 120 s compilation timeout on `main-dev`, and step 1
re-enables it.

Documented as a mandatory pre-commit gate for pipeline changes in `AGENTS.md`
§9bis, including the rule that matters most: a failure is a finding, and
`--update` without a justification in the commit message is a regression
ratified rather than fixed.

Validation: `cargo fmt --all`; `cargo clippy --workspace --all-targets -D
warnings`; `cargo test -p xtask`; `vector-compile-budget-check` run three times
for reproducibility.

## Execute the compile-time correction plan

Commit date: 2026-07-30

Three commits (`431b1b87`, `a0d4a658`, `d74010d4`) take the corpus from 4.53x
the pre-arc reference to **1.10x**, and — the part that matters — flatten the
overhead across program sizes: 1.06x to 1.17x in every bucket, against up to
9.55x before. The complexity defect is gone; what remains is a uniform
constant. `dx7_alg5` compiles in 1.67 s against 1.97 s before the arc, having
been over the 120 s timeout at the start.

Step 1 disables provenance recording on `propagate_typed`, which returns only
signals and so cannot expose the table it was building; `eval` reaches it for
every constant fold. Cause 1 replicates the `faust-rs#15` caps, which target
`main` and were absent here. Step 2 prunes the per-box provenance walk at
already-attributed nodes, sound because a call leaves its whole reachable
subgraph attributed and Signal nodes are immutable — a test compares against
the previous unpruned walk and asserts the tables are identical.

Two corrections to the plan, both driven by measurement rather than reasoning.

The step order was wrong. Step 2 was implemented first and produced no
improvement whatsoever; the profile then showed 4 056 samples of self time in
`SignalOrigins::record`, so the bottleneck was cause 1's unbounded lists, not
the traversal. Step 2 was stashed, the caps landed, and only then did the
pruning show −15 % to −53 %. A step that measures as worthless may be blocked
by another, not useless.

Step 3 was not implemented, and should not be. Its premise — that parser and
eval provenance recording carries the residual — was recorded in the plan as
"identified by reading, not yet isolated by measurement", and that caution paid
off: `BoxProvenance`, `import_box_provenance` and `SourceMap` appear nowhere in
the final profile, and a direct probe gives 80 origins over 41 nodes with a
maximum of 3 per node on `dx7_alg5`. The proposed cap of 8 would never fire.
Adding it would have changed which occurrence a diagnostic selects, for
nothing. The residual 1.10x is left explicitly unattributed: the profile shows
diffuse allocator traffic plus `ui::split_label_metadata` and
`boxes::match_box`, neither introduced by this arc, and inventing a cause is
exactly how cause 3 entered the document.

Step 4 (lazy diagnostic-time derivation) stays open as a design decision, now
less urgent since the eager tables cost a flat ~10 % rather than a
size-dependent multiple.

Validation per commit: `cargo test --workspace --all-targets` (87 suites,
including `cli_diagnostics_channel`, `diagnostic_errors`,
`machine_applicable_fixes`); `golden-check` 197 cases; clippy `-D warnings`;
fmt. The front-end budget baseline was ratcheted down after each step and
`dx7_alg5` re-enabled in the basket.
