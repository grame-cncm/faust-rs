# 2026-07-17

## Rust backend: impulse-test gate (`make rust`, 92/92 green)

Added the `tests/impulse-tests/` gate for the Rust backend, following the
WASM/AssemblyScript scalar-prefix pattern:

- `archs/impulserust.rs` — a Rust impulse architecture appended after the
  generated `-lang rust -double -cn mydsp` output (top-level items are
  order-independent, so the Make rule is a plain `cat`). It mirrors
  `tools/impulsewasm.js`, which itself mirrors the C++ 4-pass harness's first
  pass: 44.1 kHz, blocks of 64, a 1.0 impulse on the first frame of every
  input channel, buttons (only buttons, like `FUI::setButtons`) held at 1.0
  during the first block, the shared sinusoidal soundfile fixture
  (2 channels, 4096-frame parts, `sin(part + 2*pi*i/4096)`, installed after
  `init`), and `%6d :  %.6f` output lines with |v| < 1e-6 normalized to 0.
  Buttons are driven by re-visiting `build_user_interface` with a
  `SetButtons` UI (no zone-pointer captures, no `unsafe`); soundfiles are
  installed the same way with an `InstallSoundfiles` UI whose fixture shares
  the two channel buffers through `Rc` across the 64-entry channel table.
  The driver runs on a 512 MiB-stack thread because generated DSP structs
  hold delay lines by value.
- `Make.rust` — generate (`-double`), concatenate, `rustc --edition 2021 -O`,
  run `-n $(SCALARFRAMES)`, compare with `filesCompare -part` at the shared
  per-DSP tolerances.
- `Makefile` (`make rust`, added to `all`), `known.mk`
  (`KNOWN_FAIL_rust :=` — empty), `README.md`, `KNOWN_FAILURES.md`.

Result: **92/92 pass** at the default `2e-06` tolerance (plus the
pre-existing per-DSP bounded-rounding overrides), including `sound` (soundfile
fixture), `UITester`, `grain3`, `logical`, and `math`. The only exclusion is
the shared `subcontainer1` compile gap (`KNOWN_FAIL_all`). `KNOWN_FAIL_rust`
is empty, matching the parity bar of the other six backend gates.

This also resolves the open question from the emitter-slice sweep below: the
16 small Rust-vs-C divergences observed in single precision do not exist in
`-double`, confirming they came from the C backend promoting `float` operands
to double-precision libm calls rather than from the Rust emitter.

## Rust backend: first module-first emitter slice (`-lang rust`)

Implemented the `rust` backend scaffolded in
`crates/codegen/src/backends/rust/mod.rs`, following the C/Julia module-first
emitter conventions (`generate_rust_module(&FirStore, FirId, &RustOptions) ->
Result<String, CodegenError>`, stable `FRS-CGEN-RUST-000x` error codes, shared
`faust_api` canonical-signature validation). Generated shape: `FaustFloat`
alias + `remainder_*` helpers, `static` tables, `pub struct <name>` DSP state
with an explicit `new()`, snake_case Faust lifecycle methods
(`init`/`class_init`/`instance_init`/`instance_constants`/
`instance_reset_user_interface`/`instance_clear`), `build_user_interface`
against host `Meta`/`UI<FaustFloat>` traits, and `compute(&mut self, count,
&[&[FaustFloat]], &mut [&mut [FaustFloat]])`.

Rust-specific parity decisions (documented in the module header):

- Integer `+ - * / %` lower to `wrapping_*` so C two's-complement behavior
  (noise LCGs) survives; logical right shift round-trips through the unsigned
  type of the same width.
- Rust has no implicit numeric conversions, so store sites, binary operands,
  call arguments, and `Select2` branches are coerced to the FIR
  result/destination type when the operand's own FIR type differs (module
  state/table types are collected up front for store-site coercion).
- FIR comparisons carry their C result type (`Int32` from the fast lane);
  they render as native Rust booleans in condition position and as
  `((a op b) as i32)` in value position.
- FIR output-channel aliases (`output0 = outputs[0]`) become disjoint mutable
  borrows taken in channel order from `outputs.iter_mut()` — the
  borrow-checker-friendly equivalent of the C pointer aliases. Input aliases
  copy the shared `&[FaustFloat]` slice.
- C float math families (`sinf`, `acoshf`, `fmodf`, ...) are normalized by
  suffix + FIR result type onto `f32::`/`f64::`/`FaustFloat::` associated
  functions; `rint` maps to `round_ties_even`, `remainder` to emitted helpers,
  integer `abs` to `wrapping_abs`, `isnan`/`isinf` to `is_nan()`/
  `is_infinite()` casts.

CLI: `CliLang::Rust` (`-lang rust`, alias `rs`) wired in both the
`--fir-fixture` path and the DSP-file path (compile-to-FIR + generate, like
the asc backend); `--double` selects `FaustFloat = f64`; `--architecture` is
rejected like the other non-C/C++/Julia backends.

Lifecycle contract: per `porting/backend-lifecycle-contract-en.md`, the
backend includes a source-inspection conformance test proving `init` calls
`class_init` before `instance_init`, `instance_init` replays
`instance_constants -> instance_reset_user_interface -> instance_clear`, and
`instance_init` contains no `class_init` call. The `instanceConstants`
fallback/injection writes `self.fSampleRate = sample_rate;` exactly like the
C/C++/Julia emitters.

Validation beyond unit tests (7 backend tests + CLI parse/help tests): an
ad-hoc differential sweep over the 93 `tests/impulse-tests/dsp/` programs
compiled each DSP with `-lang rust` and `-lang c`, built both under minimal
host harnesses (`rustc` + `cc`), and compared 2048 impulse-response samples
per channel. Result: **70/93 bit-exact** against the C backend. Remainder:
16 DSPs differ by 5e-6..8e-4 on a subset of samples (root cause: this repo's
C backend calls double-precision libm (`sin`, `pow`) on `float` operands via C
implicit promotion, while the Rust output uses true `f32` operations — to be
adjudicated against the C++ reference oracle when the impulse gate lands);
6 DSPs produce NaN/Inf-bearing outputs in the C harness that need the real
4-pass impulse architecture to compare meaningfully; `subcontainer1` fails
upstream of codegen (foreign functions, `FRS-SFIR-0004`); `math.dsp`/
`sound.dsp` fail only in the ad-hoc C harness (C `isnanf` on macOS,
soundfile stub), not in the Rust output.

Known gaps / follow-ups:

- `tests/impulse-tests/` gate (`Make.rust` + `Makefile` target + `known.mk`)
  is the next step; the sweep above is scaffolding for it, not a substitute.
- Soundfile field accesses are emitted textually (`self.sf.fLength[...]`)
  against a host `Soundfile` struct; untested end-to-end.
- Helper functions with `AccessType::Struct` references and
  `IteratorForLoop`/`ShiftArrayVar` nodes fail fast with
  `FRS-CGEN-RUST-0003` (same boundary as the C emitter today).
- Large DSP structs are returned by value from `new()`; hosts with big delay
  lines need a large stack or heap placement (same contract as C++ Faust
  stack-allocated DSPs; the C API `calloc` path has no direct equivalent yet).
