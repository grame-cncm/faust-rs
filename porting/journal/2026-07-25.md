# 2026-07-25

## CI fix: `phaser_flanger.dsp` legacy library names don't resolve against the pinned faustlibraries checkout

`main-dev` CI run
(https://github.com/grame-cncm/faust-rs/actions/runs/30137107145) failed
`Lint and test` on all three OSes: `fused_serial_groups_survive_dead_pure_root_removal`
(added yesterday in `f04276d9`) errored with "library could not resolve
source file `oscillator.lib`" while compiling
`tests/impulse-tests/dsp/phaser_flanger.dsp`.

Cause. The fixture imports the legacy singular library names
`oscillator.lib`, `filter.lib`, `effect.lib` via `ol/fl/el =
library(...)`. Those names only exist under `old/` in the pinned
`faustlibraries` checkout (`ecf2fdc238148c44c18352102333a1229ca7a8d3`,
used by the `Lint and test` job's `FAUST_LIB_PATH`); the canonical
top-level names since faustlibraries' 2017 legacy-compatibility
reorganization are the plural `oscillators.lib`/`filters.lib`, and none
of `sawtooth_demo`/`flanger_demo`/`phaser2_demo`/`spectral_level_demo`
even live there anymore — they moved into `demos.lib` (prefix `dm`).
`candidate_loaded_source_paths` (`crates/eval/src/lib.rs`) does a direct
`search_path.join(target)` with no subdirectory search, so `old/` is
never consulted.

This passed on the author's machine only because a Homebrew-installed
`faust` (`/usr/local/share/faust`) happens to carry a flatter, legacy-
compatible library layout that resolves the old singular names directly
— a fallback search path entry that masked the gap locally. CI's
`Lint and test` job has no system `faust` install (only the separate
`vector_retention` job does, via `apt-get install faust`), so it hit the
real gap.

Fix. Rewrote `phaser_flanger.dsp` to `dl = library("demos.lib")` and
`dl.sawtooth_demo` / `dl.flanger_demo` / `dl.phaser2_demo` /
`dl.spectral_level_demo`, matching the pinned checkout's current layout.
Verified with `FAUST_LIB_PATH` pointed at a fresh clone of the pinned
faustlibraries commit (no system faust on `PATH`/fallback masking to
worry about, since `FAUST_LIB_PATH` is checked before the
`/usr/local/share/faust` fallback in `default_import_search_paths`):
`cargo test -p compiler --test vector_mode` — 37/37 passed.

Not fixed here (flagged, out of scope): several other impulse-tests
fixtures (`cubic_distortion.dsp`, `gate_compressor.dsp`,
`parametric_eq.dsp`, `spectral_tilt.dsp`, `vcf_wah_pedals.dsp`,
`virtual_analog_oscillators.dsp`, `carre_volterra.dsp`,
`reverb_tester.dsp`, `reverb_designer.dsp`, `thru_zero_flanger.dsp`,
`zita_rev1.dsp`) use the same legacy singular library names. They
currently only surface in jobs/tools that either don't compile them
through this eval path yet or run where a real `faust` install papers
over the gap (`vector_retention`); any future test that compiles them
through the plain git checkout will hit the identical failure.

Public API mapping: test-fixture-only change; no CLI, C, C++, ABI, or
generated-code contract change.
