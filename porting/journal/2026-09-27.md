## Plan for the first embedder feedback on the `faust` crate

Commit date: 2026-09-27

Source commit: this commit

`py-faust-rs` has been ported onto the `faust` crate by its author
(shakfu/faust-rs@py-facade, `99e9419a` on top of `0f240664`) and the report
is on issue #17: state persistence, lifetime, the `sha_key` fix and imports
from a source string work on both backends; 150 Python tests pass, 3 are
strict xfails. Five requests: `f64` I/O for `-double` interpreter programs
(the one regression: the facade and the C entry point both narrow to
`f32`), `Dsp: Sync` for PyO3 0.29, a `label` on `Control`, controls in
declaration order, and a program Cranelift refuses, for a test.

`porting/rust-facade-embedder-feedback-plan-2026-09-27-en.md` checks each
against the code, adds two defects found on the way (control ranges rounded
to `f32` in `-double`, since `UIGlue` passes `f32` scalars; an allocation
per block in the interpreter's `-double` C compute), and plans six steps,
P1 to P6, one commit each, fixed forward on `rust-facade`. The C ABI does
not change: the interpreter's `f64` path is a Rust-only `interp-ffi` entry
used by the facade. Plan only; nothing implemented.
