# 2026-10-10

## `--version` and the diagnostics JSON name the build's commit

Commit date: 2026-10-10

Source commit: this commit

[grame-cncm/faust-rs#20](https://github.com/grame-cncm/faust-rs/issues/20):
the workspace version only changes at a release, so the `0.8.0` tag and the
282 later commits of `main` all reported `faust-rs 0.8.0`, and a downstream
project could not check which commit a binary came from.

`crates/compiler/build.rs` records the full hash of `HEAD` and its committer
date (`FAUST_RS_COMMIT`, `FAUST_RS_COMMIT_DATE`), exposed as
`Compiler::commit()` and `Compiler::commit_date()`. It reports nothing outside a
Git checkout of this repository (a source archive, no `git`). It reruns when
`HEAD`, `packed-refs` or `refs/heads` change, and watches only existing paths,
since a missing one would rerun it on every build: an empty rebuild compiles
nothing. A commit or checkout recompiles `compiler` and its dependents.

- `--version` prints `faust-rs 0.8.0 (2199d069 2026-10-06)`, as `rustc` and
  `cargo` do. Without a commit, `faust-rs 0.8.0` as before.
- The diagnostics-v2 `compiler` block gains optional `commit` (full hash) and
  `commit_date`, present together; the schema declares them, with
  `dependentRequired`, and `assert_diagnostics_v2_shape` checks them.
- Generated code still names the package version only, so the output of a
  program does not change from one commit to the next.
- C++ Faust prints the commit on a second line, `Source commit: <hash>`, with
  `-modified` and `unknown`; the user chose the `rustc` form. Uncommitted
  changes are not reflected. Registry: `DIFF-CLI-013`.

The CLI transcript harness normalizes the commit on the `--version` line, and
`faustprobe`'s snapshot masks `commit`/`commit_date` like `target`. Only
`version.txt` and `compile_error_json.txt` were re-recorded. The 56 other
transcripts that differed already at `2199d069` (include-path order, generated
code) were left as they were.
