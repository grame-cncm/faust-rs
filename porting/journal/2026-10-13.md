# 2026-10-13

## faustprobe output snapshots no longer read the installed Faust libraries

Commit date: 2026-10-13

Source commit: this commit (parent `ede4217`).

`cargo test -p cranelift-ffi --test output_snapshots` failed with 53
findings on `main-dev`, at `ede4217` and at its parent `78bd77e` alike
(checked in a worktree): last-digit and sometimes third-digit differences,
e.g. `sweep_at_other` 0.2854786602654218 -> 0.283676624753246. The
hand-written cases ran programs of `tests/output/dsp/` that
`import("stdfaust.lib")` without `-I`, so the libraries came from the
machine's installation (`/usr/local/share/faust`), updated with Faust 2.90.8;
the corpus cases (`--protocol impulse-test -I tests/impulse-tests/dsp`) did
the same for 80 of the 133 corpus programs (`stdfaust.lib`, and the legacy
`music.lib`, `math.lib`, `maxmsp.lib`, `effect.lib`, `filter.lib`,
`oscillator.lib`, ...). AGENTS.md §3 forbids a test that depends on a locally
installed Faust.

- `tests/output/dsp/mini.lib`: test-local stand-ins for the library
  functions the programs used (`osc`, `sawtooth`, `smoo`, `resonlp` as an RBJ
  biquad, bilinear one-pole `lowpass1`/`highpass1`, a decaying `peak` for
  `ba.slidingMax`, an `asr` envelope whose linear release reaches 0 so that a
  released poly voice is freed). `filt`, `osc`, `smoo`, `ring` and
  `synth_in.dsp` import it. `synth.dsp` writes the definitions it needs in
  the file: faustprobe compiles its inline `effect` from a string
  (`environment{...}`, as `poly-dsp.h` `getEffectCode` does), where a file
  beside the program cannot be found, so importing `mini.lib` there lost the
  effect (`--set wet` became "no control matching `wet`"). That behaviour is
  the C++ one and is left as is.
- `corpus()` keeps the corpus programs that are self-contained: every file
  named by `import`, `library` or `component` exists in the program's
  directory, recursively (`self_contained`, `imported_names`). The 80 others
  are recorded only under `FAUSTPROBE_LIBS=installed` (the user's choice over
  dropping them or comparing them loosely), against
  `tests/output/expected/installed-libs/`, blessed against the libraries
  installed on 2026-10-13; the impulse-test harness keeps comparing them with
  the C++ compiler.
- New test `case_programs_need_no_installed_library`: every `.dsp`/`.lib` of
  `tests/output/dsp/` is self-contained, the corpus filter keeps some and
  drops some. A mutant program importing `stdfaust.lib` in that directory
  fails it.
- Recordings blessed with `FAUSTPROBE_BLESS=1 FAUSTPROBE_CORPUS=all`: 54
  changed, all cases running one of the six rewritten programs; their exit
  status, messages, `active_voices`, `--freqresp` verdicts (linear and
  time-invariant, ringing) and `--fail-above` outcomes are unchanged, only
  the numbers move. The 80 library-dependent corpus recordings moved to
  `installed-libs/`, 24 of them re-blessed against the current libraries.
- Validation: the snapshot test passes in both modes; fmt, clippy
  `-D warnings` on the crate, the crate's tests and the five structure gates
  pass.
