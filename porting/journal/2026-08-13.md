## M6: emit versioned `mem0` JSON and `compute_cost`

Commit date: 2026-08-13
Source commit: this implementation commit

- Extended the shared strict JSON model with an optional version-2 memory
  description derived from the retained `Mem0Analysis`. It identifies the
  effective C, C++, or Cranelift backend, distinguishes the legacy C++ manager
  ABI from the shared aligned C ABI, records target pointer facts and access
  metric, and serializes every canonical zone with legacy fields plus explicit
  scope, role, alignment, allocation phase/order, exactness, and provenance.
- Emitted the corrected version-2 `compute_cost` alongside every `mem0` layout,
  retaining the legacy one-element arrays and scalar key order. Binary and math
  operation maps come directly from deterministic `BTreeMap` analysis and
  carry checked totals. C, C++, and Cranelift use the same cost snapshot for
  the same effective FIR.
- Kept ordinary strict and Wasm JSON byte-stable by making all additions
  optional. Added explicit source/file compiler entry points for selecting the
  native memory-layout flavor and re-exported that typed flavor as documented
  facade API.
- Replaced the Cranelift factory's minimal hand-built status JSON with the
  shared strict FIR serializer. Factory JSON now carries normal DSP metadata,
  UI and arity fields while retaining `backend`, `jit_compiled`, and
  `compute_body_lowered`; a `mem0` factory additionally exposes its immutable
  native allocation/cost plan before a manager is bound.
- Added semantic `serde_json` tests for schema versions, backend ABI selection,
  deterministic rendering, zone metadata, one-element cost blocks, total/map
  agreement, cross-backend cost equality, and strict absence of all memory
  fields without `mem0`.
- Validation: `cargo fmt --all`; Rustdoc for `codegen`, `compiler`, and
  `cranelift-ffi`; warnings-denied workspace Clippy; and the full workspace
  all-target suite, including the hermetic loopback test with local-bind
  permission. The mandatory release cost gate was run twice without changing
  its baseline; only the known sub-millisecond-calibration noise triggered,
  first for `APF` vector (2.250 units vs 2.165) and then scalar (1.250 vs
  1.082), while all larger cases and front-end baskets remained within their
  ceilings.

## M5: implement Cranelift `mem0` JIT and factory ownership

Commit date: 2026-08-13
Source commit: this implementation commit

- Retained the canonical `Mem0Analysis` in every `-mem0` JIT result and added
  the typed `FRS-CGEN-CLIF-0005` layout diagnostic. Instance arrays now occupy
  pointer-sized `ExternalTable` slots linked to stable `MemoryZoneId` values;
  ordinary layouts retain inline payload sizes and behavior.
- Changed struct table load/store/shift lowering to resolve inline payloads or
  dereference managed pointer slots without changing finalized function ABIs.
  Writable generated static tables now use finalized JIT pointer slots backed
  by factory-owned class allocations; literal read-only data remains embedded.
- Added copied, version-checked manager bindings and transactional aligned
  allocation for the logical JIT object, every instance buffer, and generated
  class table. Partial failure unwinds safely, clone recreates and copies every
  instance allocation, and final cache release drops instances, class storage,
  then JIT code. No host callback executes while the global cache lock is held.
- Added `setCCraneliftMemoryManager` to the C API and mirrored the canonical
  header. Compilation/cache/serialization may remain unbound, while instance
  creation under `-mem0` fails until binding. Rebinding is idempotent for the
  same copied callbacks and rejected after allocation for a conflicting one.
- Replaced the C++ wrapper's no-op manager methods with factory-lived adapter
  glue and a real getter. The adapter documents the narrower legacy type and
  alignment surfaces; Rust validates every returned address before publishing
  it to JIT code.
- Extended `compute_cost` for no-op FIR labels and scalar delay-shift nodes,
  fixing a real fast-lane delay rejection found by the Cranelift runtime test.
  Added structural pointer-slot identity coverage and a managed runtime test
  with a generated class table, delay buffer, unbound creation failure,
  multiple allocations, deep clone, and complete destruction.
- Updated the authoritative plan, compatibility registry, and Cranelift FFI
  parity matrix. M6 remains responsible for strict shared JSON emission and M7
  for `tests/impulse-tests` integration.
- Validation: `cargo fmt --all`; Rustdoc for `codegen`, `cranelift-ffi`, and
  `ffi-common`; full workspace Clippy with warnings denied; and the full
  workspace all-target suite. Its loopback test passed with the required local
  bind permission; one parser temp-directory test affected by an accidentally
  overlapping diagnostic rerun passed immediately in isolation. The mandatory
  release cost gate again reports only the pre-existing noisy
  `reverb_designer` vector measurement (996.000 units against 953.982); all
  other baskets pass and no baseline changed.

## M4: implement generated C `mem0` and the shared C ABI

Commit date: 2026-08-13
Source commit: this implementation commit

- Published ABI v1 as the authoritative `#[repr(C)]` callback table in
  `ffi-common::abi` and as the guarded
  `crates/ffi-common/include/faust-memory-manager.h`. The table carries a
  version, byte size, opaque context, explicit alignment, and the complete
  append-only memory-type vocabulary shared with Cranelift.
- Embedded that exact header in self-contained generated C and reject missing,
  truncated, or version-mismatched callback tables before calling the host.
  Rust layout/compatibility tests and strict C11/C++17 header-smoke tests guard
  field order and enum discriminants.
- Retained one canonical `Mem0Analysis` in C emission. Eligible instance arrays
  and writable tables become pointers; literal static tables remain compiled
  constants. Effective single/double precision is reflected in manager
  allocation sizes while preserving the established host-supplied
  `FAUSTFLOAT` interface contract.
- Added class-namespaced `memoryInfo*`, `classInit*`, `classDestroy*`,
  `create*`, and `destroy*` functions, plus checked companions for operations
  with legacy void surfaces. Instance creation checks alignment, unwinds
  partial allocations in reverse, captures its manager/context, and returns
  `NULL` on failure. Destruction never consults a rebinding global manager.
- Preserved `init = classInit -> instanceInit`, idempotent same-manager/sample
  class initialization, live-instance protection, pointer clearing, and
  manager allocation for generated-table subcontainers. Ordinary C output
  retains its original `new*`/`delete*` ABI and inline fields.
- Added generated-C structural and runtime tests. Strict C11 compilation uses
  warnings as errors; failure is injected at each object/buffer allocation;
  two live DSPs prove independent contexts; the delay DSP runs identically in
  both contexts; early class destruction is rejected; and all allocations are
  released. Added single/double source-shape tests and the corresponding C++
  precision guard.
- Validation: `cargo fmt --all`; Rustdoc for `codegen` and `ffi-common`;
  warnings-denied Clippy for all touched crates; and the full workspace
  all-target suite (the loopback HTTP test was rerun with its required local
  bind permission). The mandatory release cost gate was run twice; its only
  failure is the already-recorded noisy `reverb_designer` vector case at
  964.000/966.250 units against 953.982, reproduced before M4 at M0–M2. M4's
  ordinary pipeline adds only a false `memory_manager_mode` branch at emission
  and all other baskets pass. No budget baseline changed.

## M3: implement generated C++ `mem0`

Commit date: 2026-08-13
Source commit: this implementation commit

- Made `CppOptions` carry the effective sample precision into canonical target
  analysis and added the typed `FRS-CGEN-CPP-0004` layout failure. Ordinary
  code generation remains free of manager fields/methods and retains inline
  arrays.
- Under `mem0`, every eligible DSP array is emitted as a pointer. Writable
  generated static tables become manager-owned class pointers; literal static
  tables stay compiled constants. Generated subcontainers use manager
  placement construction/destruction, including nested generators.
- Preserved the public `fManager`, `memoryInfo`, `classInit`/`classDestroy`,
  `create`/`destroy`, and `memoryCreate`/`memoryDestroy` names. Added checked
  companions for recoverable description, class initialization/destruction,
  and creation. Legacy void lifecycle entry points terminate deterministically
  on a violated contract rather than dereference null or publish partial state.
- Allocation is transactional, verifies returned alignment, unwinds in reverse
  order, nulls released pointers, and captures the manager that owns each DSP
  and class allocation set. Object destruction no longer consults a possibly
  rebound global manager, and class destruction rejects live instances.
- Kept `init = classInit -> instanceInit` and the established internal
  `instanceConstants -> instanceResetUserInterface -> instanceClear` order.
  Repeated class initialization is idempotent only for the same manager/sample
  rate. Semantic static-table filling is exception-contained with allocation
  rollback.
- Replaced the reference's shallow clone with independent manager allocation,
  named scalar copies, and per-buffer payload copies; approved class tables
  remain shared. Zero-length arrays remain null and produce no allocation.
- Added Rustdoc/provenance comments and structural tests for ordinary/mem0
  separation, pointer emission, descriptions, lifecycle, generated tables, and
  subcontainers. A self-contained C++17 test compiles with
  `-Wall -Wextra -Werror`, injects failure at each allocation, checks leak-free
  unwind, runs the delay DSP, proves clone buffer independence, and verifies
  final class cleanup.
- Validation: `cargo fmt --all`; `cargo doc -p codegen --no-deps`; focused
  workspace Clippy with warnings denied; all codegen targets/tests; and all
  compiler targets/tests except the sandbox-denied loopback bind pass. The sole
  hermetic HTTP test passes when rerun with loopback permission.
- The mandatory release `compile-budget-check` passes all five scalar/vector
  codegen cases and all eight normalized front-end cases. No baseline changed.

## M2: add canonical memory-layout and compute-cost analyses

Commit date: 2026-08-13
Source commit: this implementation commit

- Added the immutable `Mem0Analysis` snapshot shared by C, C++, Cranelift, and
  JSON. Its version-2 `MemoryLayout` co-locates stable zone identity, type,
  scope, role, allocation phase/order, exact checked sizes, alignment,
  exactness provenance, and scalar-frame read/write counts.
- Added an explicit `TargetAbi` instead of the pinned C++ compiler's virtual
  pointer and padding heuristic. C, C++, and Cranelift object models are
  distinguished; C++ numeric object layout is marked as a compiler-expression
  estimate, while generated `sizeof`/`alignof` remains authoritative in M3.

  described but non-allocated zones, one-byte pointer-aligned empty Cranelift
  state, exact static-table counts, and explicit class/instance/subcontainer

  checked and unknown/unsupported constructs fail closed.
- Added `analyze_effective_mem0`: C/C++ analyze nested-container FIR directly;
  Cranelift uses its canonical `MergedStructFields` flattening first, ensuring

- Added the exhaustive version-2 scalar-FIR `ComputeCost` visitor with lexical
  `BTreeMap` breakdowns, exact function-call keys, bitcast counting, all scalar

## Plan the `-mem0` custom memory-manager port

Commit date: 2026-08-13
Source commit: this planning commit

- Analyzed the pinned Faust C++ `-mem`/`-mem0` contract, its generated C++
  lifecycle, memory-layout JSON, and `compute_cost` visitor. Recorded the
  reference weaknesses that the Rust port must not reproduce: heuristic object
  size, zero-sized static-table sentinels, empty `init`, shallow `clone`, global
  manager rebinding, unchecked allocation failure/alignment, incomplete type
  vocabulary, and defective conditional cost accounting.
- Defined one typed `Mem0Analysis` as the source of truth for generated C,
  generated C++, Cranelift JIT storage, manager descriptions, JSON
  `memory_layout`, and versioned `compute_cost`. Scope is deliberately limited
  to the four `mem0` aliases; `mem1`–`mem3` stay rejected.
- Specified an adapted, versioned plain-C manager ABI with alignment and opaque
  context, while preserving the legacy-compatible C++ manager surface. The
  plan includes transactional allocation, captured-manager destruction,
  poison/failure testing, exact target-ABI metadata, and deep clone behavior.
- Extended the design to Cranelift: external-buffer pointer slots in
  `StructLayoutPlan`, pointer-aware lowering, factory-owned writable static
  tables, managed class/instance allocation sets, functional C/C++ factory
  manager binding, cache and serialization rules, explicit wrapper-versus-JIT
  state ownership, and strict rejection of compute stubs in parity tests.
- Added a dedicated `tests/impulse-tests` strategy with `cpp-mem0`, `c-mem0`,
  `cranelift-mem0`, and `all-mem0` targets, self-contained DSP fixtures, a
  portable allocation trace, semantic JSON checks, and ordinary-versus-mem0
  plus optimized-versus-unoptimized runtime parity.
- This commit is planning/documentation only. No compiler behavior or public
  API is enabled yet; the document's whitespace check is clean.
