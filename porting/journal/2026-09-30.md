## `faust`: use compiler arguments as the only precision input

Commit date: 2026-09-30

Source commit: this commit

Issue [#19](https://github.com/grame-cncm/faust-rs/issues/19) exposed a
memory-safety defect: `CompileOptions::precision` could disagree with
`args`, so Cranelift received host buffers and parameter zones at the wrong
width. Removed the public input field. The compiler's `-double`/`-single`
arguments now choose the width; the safe facade reads it from the compiled
interpreter factory variant or Cranelift JIT module before publishing a
`Factory`. `Factory::precision` and `Dsp::precision` remain queries.

Migrated the crate's tests and English/French embedding examples. The
regression test covers both backends, both host buffer widths, parameter
zones, all four precision spellings and last-option precedence. The change
breaks Rust struct literals that set `precision`; C and C++ ABIs are unchanged.

Validation: `cargo fmt --all`, workspace Clippy and tests, all five
structure checks, `golden-check`, and `cargo test -p faust --test api`
passed. The canonical release `compile-budget-check` was attempted twice
but stopped before measuring cases because this machine calibrated
`karplus.dsp` at 3 ms, below its 4 ms floor. A diagnostic run against a
temporary copy of the baseline with only the floor set to 3 ms passed all
front-end and codegen cases; the checked-in baseline was not changed.
