## `-svg` folds shared sub-diagrams (port of C++ #1290)

Commit date: 2026-10-22

Source commit: this commit

C++ `master-dev` #1290 (`6789c5da8`) made three changes. Its `applyList`
memo was already ported (`porting/MEMOIZATION.md` §2.4e). The other two,
for `-svg`, were missing, and faust-rs drew a recursion with shared
subproblems as its expanded tree: `cheb(23)` wrote 373 MB, `phaser_flanger`
368 MB. Plan:
`porting/svg-shared-node-folding-port-plan-2026-10-22-en.md`.

- `boxes`: `BoxComplexity`, `box_complexity` memoized and saturating at
  10^9 (C++ `addBoxComplexity`); `box_pp_bounded`, `box_pp` within a node
  budget (C++ `mBox`/`PrintBudget`).
- `draw`: `DrawMemo` counts the parents of every node at the start of a
  drawing (C++ `Occur`). A node with more than one parent is folded like a
  named one, labelled by its own expression and filed as `diagram-<hex>.svg`
  (`diagram.svg`, `diagram-2.svg`, ... under `FileNaming::DefinitionName`).
  Every use of a folded diagram is a link: Rust used to expand a second use of
  a named one, which C++ never did. A folded diagram's inside schema is built
  once, when it is scheduled, to read its arity, and drawn as its file; the
  link no longer builds the unfolded inside. `legal_file_name` gives a stem
  that does not start with a letter the stem `diagram`, as C++ since
  `068fb9a80`.

Measured: `cheb(23)` 373 MB / 1.3 s → 192 KB, `cheb(100)` 808 KB in 0.01 s;
`phaser_flanger` 1.81 s / 595 MB resident / 368 MB → 0.57 s / 91 MB / 19 MB;
the 133 impulse-test programs, 1.28 GB in 14 058 files → 191 MB in 17 536
files, all drawn. `faustprobe --svg` on `fdn.dsp` folds 54 shared nodes,
as C++ 2.90 does, and two runs are byte-identical. DIFF-BEH-025 and
MEMOIZATION §2.26 record the change.

Tests: `crates/boxes/tests/shared_dags.rs` (3), three `draw` tests, one
`svg_probe.rs` test; two existing tests updated for the new folds.

## faustprobe draws block diagrams: `--svg DIR`

Commit date: 2026-10-22

Source commit: this commit

Producing the figures of a document on spatial-audio combinators needed the
C++ `faust -svg`, which writes `<name>-svg/` next to the source, cannot draw a
sub-expression without a throw-away `.dsp`, suffixes every file with an
address (`layer-98768.svg`), and runs another front end than the one the
probe measures with. `faustprobe --svg DIR` draws the program the probe would
render (`-I`, `-pn`, `--eval` included) with faust-rs's `draw`, into `DIR`
alone, and prints an index (`file,name` CSV, or a JSON document under
`--format json`). Draw-only: the render flags are refused by Clap
(`conflicts_with_all`), the drawing options without `--svg` too (`requires`).

- `draw`: `DrawConfig::file_naming` (`FileNaming::BoxIdentity`, the C++
  scheme and still the default of `faust-rs -svg` and of the aux-files API;
  `FileNaming::DefinitionName`, `name.svg` then `name-2.svg` in drawing order,
  compared without case). A `FileNames` table in the fold state assigns a
  file when a diagram is scheduled, so a link and its file agree.
  `draw_diagrams` returns `Diagram { name, file, svg }` with a root title
  separate from the root file name; `draw_schema` and
  `draw_schema_to_memory` are now thin wrappers over it (same output).
- `eval`: `simplify_diagram`, C++ `boxSimplification` for `-sd`, with its
  transfer of the definition name to the rewritten tree. faustprobe applies
  it to the drawing only, not to the compiled program (C++ `-sd` simplifies
  the process in `evalprocess`).
- `cranelift-ffi`: `factory::compile_signals_with_argv` (the constructors'
  front end, errors published as theirs) and `probe::diagram::draw_program`;
  under `--eval` the root is `process.svg` titled with the expressions, and
  the wrapper's `__faustprobe_evalK` members are labelled with their text.
- Labels of factories: faust-rs already names the result of an application
  after the applied function (`feedbackNetwork`, `matrix`), where C++ 2.90
  prints the closure (`feedbackNetwo...ER5[nil]]]}`) or `diagram_13`; nothing
  was needed. faust-rs keeps the innermost name where C++ keeps the
  outermost (`encoder` for C++'s `encodeAt`), left as it is.

Tests: `crates/draw` (3 unit tests: disambiguation order and case, names
independent of box indices, C++ scheme kept), `crates/cranelift-ffi/tests/
svg_probe.rs` (9: stable names and bytes across runs, writes only in `DIR`,
`--eval` on a `.lib`, several expressions, a bad expression writes nothing,
`-pn`, `-sd`, JSON index, refusals). `--help` snapshots re-blessed (additions
only). Checked on `faust_composition/examples/fdn.dsp` (100 files),
`texture.dsp` (349) and `--eval 'sc.parallel(7, 4, mk)'`, twice each,
identical.
