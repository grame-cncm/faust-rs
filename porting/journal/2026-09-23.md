## Analysis revised: `cinputs` and `coutputs` return the widgets, not their count

Commit date: 2026-09-23

Source commit: this commit

`porting/control-inputs-and-wildcard-modulation-analysis-2026-09-22-en.md`,
section 3: `cinputs(e)` is now the list of the N widget boxes of `e`, in UI
order, the same nodes as in `e`, and `coutputs(e)` the list of its
bargraphs; the count is `outputs(cinputs(e))`, and the counting primitive
disappears. `cinput(i, e)` and `coutput(i, e)` keep their tuples
`(widget, init, min, max, step)` and `(bargraph, min, max)`. The seeds of a
descent become one identifier, `fad(op.mse(e, target), cinputs(e))`, and the
tuple's width stays inside `cinput`, the only place a sixth entry would
change. A list of tuples was considered and rejected (no list of lists in
Faust: ten boxes in parallel, a count divided by five). A program without
controls gives the empty box `0 : !`, which `adaptive_fad` must report
rather than fail on a `par` of zero. The implementation plan and the tests follow
the change. Section 3.4 now carries the envisaged code of `adaptive_fad` and
`adaptive_rad`, one helper `_adaptive(descend, e, loss, upd, clock, reset, X, t)`
called on `descend_N_fad_clocked` or `descend_N_rad_clocked`: the parameters
enter the wildcard-modulated `e` as its first N inputs, the loss is applied
after the model through a one-parameter lambda per output, and the audio
inputs and the target are arguments, closed over as signals, since Faust has
no lambda over a bus of N and `mse` mentions its argument twice. The first
sketch's `\(P).(loss(model(P), target))` was a box of one input whatever N.
