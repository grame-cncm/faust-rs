## Cranelift: a basic block longer than 1 MB failed the emission

Commit date: 2026-09-08

Source commit: this commit

Found by an additive oscillator-sync program whose control-rate section
holds three 64 x 32 sinc matrices, about 44 000 slow statements: the JIT
panicked in `MachBuffer::handle_fixup` ("assertion failed: (label_offset -
offset) <= kind.max_pos_range()") and faustprobe fell back to the no-op
stub. Instrumenting cranelift-codegen 0.117.2 showed the fixup: an `Ldr19`,
the PC-relative load of a constant-pool entry emitted at offset 52 of the
function, whose constant was bound at offset 1 169 568, in the island that
followed the first basic block; the block was 1.17 MB long, the load reaches
1 MB, and no veneer exists for a literal load. Cranelift 0.117 considers
islands only between basic blocks (`VCode::emit`, `island_needed` before
each block), so a single straight-line block longer than the range cannot
be emitted. Upstream, the same case is wasmtime issue #12968 (a single
basic block with enough constant loads on aarch64, the 19-bit `ldr` field,
"we cannot insert an island in the middle of a basic block"), fixed by PR
#13392, "MachBuffer: resolve deadline issues with very large islands",
merged 2026-05-16: `VCode::emit` now checks the deadline after every
instruction and emits a jump-around island inside the block. First release
with it: wasmtime 46.0.0 of 2026-06-22, cranelift-codegen 0.133.0 (current:
0.135, 0.136 in release candidate); faust-rs is on 0.117, wasmtime 30, and
the upgrade spans sixteen minor versions of the five cranelift crates, a
separate job.

A lowering-side workaround was written and validated first: a fresh block,
jumped to from the current one, once a straight-line block held more than
2048 CLIF instructions, between the statements of a `Block` and before every
expression node (a single `sum` over a large `par` is one statement of tens
of thousands of nodes), with a test counting the blocks of a
ten-thousand-local compute body. It made the 22 500-term reduction
(`sum(i, 150, sum(j, 150, ...))` of slider-dependent terms) and the original
program run under the JIT, the latter identical to its per-mode variants
that never exceeded the range. It was then dropped rather than kept: the
next entry removes the cause by upgrading Cranelift, and a workaround for a
bug fixed upstream would only have added a code path.

## faustprobe -v: the version with the copyright notice

Commit date: 2026-09-07

Source commit: this commit

`faustprobe -v` and `faustprobe --version` print the version followed by
the GRAME copyright line, as `faust-rs -v` does (`render_version_text` in
the compiler CLI). clap's automatic flag was `-V` only and printed the bare
version; it is disabled and replaced by an explicit `--version` argument
with `-v` as its short form and `ArgAction::Version`, the text being
`CARGO_PKG_VERSION` and the notice concatenated at compile time. `-V` is no
longer accepted.

## optimizers.lib 0.8.0: gating and stopping

Commit date: 2026-09-07

Source commit: this commit

A new section of the library, "Gating and Stopping", generalises the gated
self-calibrating reverberator: `gated(C)` runs an arbitrary block whose
last output is a flag in an `ondemand` domain clocked by `1 - flag'`, so
that once the flag is raised nothing of the block is computed and its
outputs hold; `gated_when(on, C)` adds an enable signal (the parameter is
not called `enable`, a Faust primitive, which no pattern can match);
`stop_after`, `stop_below` and `stop_relative` build the flag from a period
clock and a per-sample loss, kept raised by `ba.peakhold(1)` (a first
`op.latch` duplicated it under the name of `ba.latch`, which is a
sample-and-hold), the last one comparing the period
loss with the loss at the previous checkpoint `window` periods earlier
rather than with the previous period, which the plateau of an overshoot
fools; `on_change(C)` runs a block only when one of its inputs changes, the
control-rate computation of coefficients that depend on learned parameters.
Two fixtures and two runtime tests (`opt_gated_stop_after`: the gated gain
is bit-identical to the plain one until the fifth firing and constant after
it, `on_change` is exp of it; `opt_gated_stop_relative`: the flag rises on
a period boundary at the twelfth period of a noisy target), six entries in
`opt_all_functions.dsp` (80 entries, 139 outputs). The overview gains
section 4.9 and its section 7 uses the functions instead of inline code;
the organisation table has thirteen rows.

## Interpreter: a loop with a zero bound ran its body once

Commit date: 2026-09-07

Source commit: this commit

Found by `gated`: in the interpreter, a block gated by its own held flag
never stopped, while the C++ and Cranelift backends held. The bytecode
compiler lowers `ForLoop` and `SimpleForLoop` as `init; do { body; step }
while (cond)`, which runs the body once whatever the bound; the loop of an
`ondemand` block runs `clock` times, and a silent clock still executed the
body. Both lowerings are now guarded by a `kIf` on `init < end` (`init >
end` reversed) or `upper > 0`, so a zero bound runs the body zero times, as
the C++ `for` does; the bytecode-to-C++ converter and the optimizer see an
ordinary `If` around the loop. The structure tests of the compiler follow
(the `then` block of the guard holds `kLoop`), and one of them passed a
comparison as the loop's `end` where the lowerings pass the exclusive
bound, so the guard, which evaluates the bound before the variable exists,
showed the mistake. `compute(0)` also ran the sample loop once before.

## optimizers.lib overview: two phases, learning then use

Commit date: 2026-09-07

Source commit: this commit

Section 7 of the overview (EN and FR), from the gated form of a
self-calibrating reverberator: a program that learns in the audio process keeps paying for its
learning once the parameters have settled, `gate_g` and `select2` do not
help since both still compute, and `ondemand` does, a block whose clock is
silent computing nothing. The pattern: the whole loop in an outer
`ondemand` clocked by `1 - done'`, the flag raised by a checkpointed
convergence criterion at a period boundary; a second `ondemand` computing
the filter coefficients when a parameter changes; the measurements (28x
real time learning, 23x gated, 196x stopped, 572x with hoisted
coefficients, 625x for the network with sliders, 631x after a
recompilation with constants) and why the gate is available: the
derivative is a signal of the same program. Scope becomes section 8,
references 9; the tutorial's hygiene section points to it. Documentation
only.

## optimizers.lib overview: a Scope section

Commit date: 2026-09-07

Source commit: this commit

The overview of `optimizers.lib` (EN and FR) gains a section 7, "Scope:
what this reaches, and what it does not", written from the calibration of a
reverberator to measured rooms: what compiler-level differentiation reaches
(calibration and adaptation of parametric models, tens to a few hundred
parameters, inside the audio process or in a host loop, small networks in
Faust, design by objective, a Faust program as a differentiable layer of a
tensor framework as the bridge to build), what it does not reach today and
could (batches and accelerators, graphs beyond tens of thousands of nodes,
a spectral loss without an FFT, the bounds of `rad`: tapes and horizon
equal to the block, no variable delay, no writable table, no clock-domain
crossing, subgradients, no second derivative; the tooling: no execution
graph, no schedules, checkpoints or hyperparameter search, double
precision), and what it will not reach by construction (large-scale deep
learning, dynamic graphs, learning representations from a corpus,
differentiating what is not a signal). References become section 8.
Documentation only.
