Commit date: 2026-10-11

Source commit: this commit

## W1: the functions of `maths.lib` the backends lacked come from the C math library

Commit date: 2026-10-11

Source commit: this commit

`maths.lib` declares, as `ffunction`s of `<math.h>`, functions neither
Cranelift (`HOST_MATH`) nor the interpreter (its opcodes) implement: `cbrt`,
`hypot`, `erf`, `erfc`, `tgamma` (`ma.gamma`), `lgamma`, `logb`, `ilogb`,
`ldexp`, `scalbn` (`ma.scalb`), `nextafter` and the Bessel functions `j0`,
`j1`, `jn`, `y0`, `y1`, `yn`. Both failed on them ("no Cranelift
implementation", `UnknownMathFunction`) unless a host registered each. The C++
LLVM JIT finds them among the process's symbols, in the C math library.
Rust's standard library has `cbrt` and `hypot` only, stable; the user chose
the system's library over the `libm` crate, for the results the C and C++
code generated on the same machine computes.

- `foreign-call`: the 28 C symbols, `float` and `double` variants, declared
  `safe` in an `unsafe extern "C"` block (`-lm` outside Apple), with a typed
  table, `libm_functions()`. `ldexpf` and `scalbnf`, inline in MSVC's
  header, go through `ldexp` and `scalbn`, which is exact. The Bessel
  functions are `double` only, `_j0`... under MSVC. Nothing on wasm32.
- `TypedFunction` (moved from the Cranelift backend, where it was
  `HostMathFn`, with three new shapes: `float(float, int)`,
  `double(double, int)`, `double(int, double)`) and `NamedFunction` now live
  in `foreign-call`, so `HOST_MATH` and the C math library table are typed
  the same way.
- Order, both backends: the backend's own math functions, then host
  registrations, then the C math library, which a host may so replace. A
  call follows the rule of the typed registrations: arguments and result
  convert (`float j0(float)` calls `j0` on a `double`), another shape is
  refused naming "the C math library function `double j0(double)`".
- Cranelift registers the table as JIT symbols; the interpreter compiles the
  call as a typed one and the executor finds the address in the table when
  no host registered the name.

Checked: `ma.cbrt`, `ma.hypot`, `ma.ldexp`, `ma.scalb`, `ma.logb`,
`ma.ilogb`, `ma.erf`, `ma.erfc`, `ma.gamma`, `ma.lgamma`, `ma.J0` to
`ma.Yn` and `ma.nextafter` from this repository's `maths.lib`, rendered by
`faustprobe` in both precisions, give the values a C program calling the
same functions prints.

Tests: `foreign-call` calls each kind of function through `invoke`
(`ldexpf` at the edges of `float` included) and checks the symbols are
unique; `a_c_math_library_function_is_called_from_its_maths_lib_declaration`
and `a_host_registration_replaces_a_c_math_library_function`
(`math_signature_probe.rs`, Cranelift, both precisions, opt levels 0 and 3);
`a_c_math_library_function_is_called_by_the_interpreter` (interp-ffi, a
refused shape and a host replacement included);
`a_c_math_library_function_resolves_after_the_registrations` (codegen).

Also fixed: the journal index counts. Updating them by the text
"(N entries)" changed the first line with that count, so the four previous
commits left 2026-02-23 at 27 instead of 26, 2026-02-24 at 26 instead of 23,
and 2026-10-10 at 23 instead of 27. The two February lines are back to their
values on `origin`, 2026-10-10 holds its 27 entries, and each line is now set
by its date.
